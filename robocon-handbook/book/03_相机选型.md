# 第 3 章 相机选型：从 USB 相机到工业相机

> 训练赛那天场馆顶灯全开，自动白平衡把篮球看成了一团白。从那天起，我到每一个新场地的第一件事固定成五样：打光，锁曝光，锁白平衡，重标定，试射验收。

## 相机家族

车上的相机主要有三路。

**USB 相机。** 便宜，接口通用，插上就能用，生态省心，做原型练手都靠它。缺点也同样明确：帧率一高就掉，曝光可控的型号不多，长时间运行容易掉线。预算有限的时候从它起步。

**工业相机。** 全局快门，曝光时间可控，帧率稳，耐用，赛场需要的可靠性它都有。代价是价格，外加一套 SDK 的学习成本，接进 ROS 还要自己写适配。这部分成本换来的是参数可控。

USB 相机还有一个差别在驱动。通用驱动认的设备多，但能改的参数项浅，曝光和增益常常只有几档。厂商驱动参数全，换一台机器要重装一遍环境。选型时把相机型号和驱动方案绑在一起定，免得采购回来才发现参数调不到需要的档位。

**深度相机。** 主动打光测距离，近场好用，输出 RGB-D。远场和强光下质量掉得明显，这一条后面单独说。

## 接口与带宽：连线的账

相机的选型不只挑传感器，还要挑接口。

USB 相机省事，插上就用，但带宽和线长有代价。高分辨率和高帧率同时要的时候，USB 2 的带宽顶不住，画面要么掉帧要么自动降分辨率。USB 3 口能松一口气，代价是线缆变粗，接头锁不住，车一颠就松。压缩格式能省带宽，代价是每帧多一道解压，占 CPU 预算。

网口相机是第三条路。带宽稳定，线可以拉长，一根线到上位机，代价是价格上去，驱动和 SDK 要多花时间接。工业相机接进 ROS 一般要用厂商 SDK 写一层适配，把图像按 ROS 的话题格式发出来，帧号与时间戳要自己补齐，这层写一次就能复用。

不管哪种接口，有两件事要提前定。一是掉线怎么办，驱动带自动重连，重连之后参数能重新下发。二是触发方式，软触发简单，帧率受上位机负载影响，硬触发稳定，多一根线。这两件事定得晚，联调都要返工。

## 帧率与快门：120Hz 的意义

帧率决定一秒内能看到多少个运动时刻。球在飞，车在动，30Hz 是每 33 毫秒一帧，120Hz 是每 8.3 毫秒一帧，抓时机的能力差四倍。评估时见过车端跑 120Hz 的配置，回头看这个方向是对的：运动场景里帧率带来的收益比堆分辨率更直接。帧率和曝光是连着的，每一帧先曝光再有读出，两段时间加起来才是帧周期，所以缩短曝光也是给帧率腾位置。

快门分两种。卷帘快门逐行曝光，运动一快，画面里的直线开始弯，称为果冻畸变。全局快门所有像素同一时刻曝光，画面不会出现这种弯折。高速场景里，全局快门的成本在像素旁边多出的那组存储，这部分投入是必要的。

## 曝光三角

曝光时间，增益，光圈，三者互换亮度，这是摄影的常识，搬到车上要重排权重。

我的排序：曝光时间第一，它决定拖影，宁可欠曝也别拖影。光圈第二，它动景深，也动进光量。增益最后，高增益用噪声换亮度，检测框的置信度随之波动。锁定曝光时间之后，白平衡也要手动锁。场馆灯光的色温和亮度一变，自动白平衡会把球和地板的颜色调偏。

每到一个新场地，我们的流程固定：看直方图打光，锁曝光，锁白平衡，再跑一遍标定。训练赛那次失误之后，这套流程写进了预检清单。

## 找目标的两条路线

选完相机，接着定用什么方法从画面里找目标。

传统视觉路线是颜色分割加轮廓处理，最后把目标像素坐标交给 PnP 解出位姿。分割放在 HSV 空间做，光照变化集中反映在 V 维上，色相 H 相对稳定，白光源和金属高光大多落在低饱和度区域，先筛掉一批。候选目标再过一道圆形度检查，顶灯高光和圆形标志牌是主要的干扰项。这条路线占用低，参数改哪里看得见。

学习路线评估过两条。FoundationPose 面向通用物体的位姿估计，评估时把推理时间与车载算力对了一遍账，帧率跟不上任务节奏。FFB6D 这类基于深度图的位姿网络，推理的算力同样超出车载预算。两条线的评估都停在半路，结论是那年的硬件上，位姿估计的重活先交给几何方法。

学习模型留在检测环节。YOLO 找框，这部分推理轻，帧率够，误检靠多帧连续稳定来压。检测负责找到目标，距离与位姿交给几何方法和雷达，这个分工后来没有变。

## 白平衡锁定与阈值重标

场馆灯下，人眼觉得颜色正常，相机看到的色温差别很大。自动白平衡随灯变化调整颜色增益，增益一动，上一场的阈值表全部作废。选型阶段就把这一条写进清单：相机要支持手动白平衡与手动曝光，白平衡锁住之后才谈阈值标定。

锁定之后的流程三步：用场馆实拍帧重标阈值，跑回归样本核对误检，确认通过再进比赛配置。三步的顺序不要颠倒，颠倒一次，这一轮标定要重来。补光是另一条路，主动补光把目标照亮，颜色分布就稳定。场馆灯的显色性也要考虑，显色差的灯会让颜色分布互相靠拢，分割余量变小，打光这件事因此不只是为了亮度。

## ToF 与双目

深度方案在车上主要两种。

**ToF** 直接测光的飞行时间，近场稳定，结构简单。强光下信噪比下降，反射面上的读数会漂移。

**双目** 靠视差，深度等于焦距乘基线除视差。视差越小，距离越远，误差随距离平方放大，没有纹理的表面直接失效。

篮板是平面，篮筐是细结构，这两个目标对深度测量都不利。我们的结论是：深度只做近场辅助，主线距离交给雷达几何。深度读数要通过四项检查才进入决策：置信度，距离范围，连续帧稳定，观测时效。

双目的标定账另算。两个镜头先把内外参标齐，行对齐没做好，深度图整片失真。评估深度方案时，这几项成本都记在同一张纸上，最后的结论和前面一致：近场辅助可以做，主距离源不行。

## 镜头与视场角

视场角等于两倍反正切，反正切里是传感器尺寸除以两倍焦距。选镜头先算一笔账：目标在几米外，要在画面上占多少像素，检测网络才能稳定输出。篮筐内径 0.45 米上下，十米外拍下来占不了几个像素。长焦镜头进光少，视场窄，车身一晃目标就出画。广角和长焦之间，我们取了偏中间的焦距，兼顾远距成像和视场余量。

分辨率不用追高，像素一多，读出慢，传输重，处理也重。够用的标准就一条：目标在画面里占的像素数，够检测网络稳定输出。

## 深度漂移那次

有一次调试，现场人流密集，检测框开始抖，随后深度读数整体偏移，篮筐的距离对不上。那天我们切到备用方案，用点云找篮板，按篮板和篮筐的装配关系反推位置，另以四周挡板做参照，把雷达和篮筐的高度关系写死。多路校验加试射验收之后，那场练习赛才通过。

这次之后，深度在我们系统里的定位固定了：近场确认和距离档参考，不承担主距离源。它的读数不参与弹道解算，只参与安全判断和候选选择，这条分界后来写进了接口文档。

相机参数的携带方式也在选型清单里。参数要能导出成配置文件，按场地存几套，进场选一套再微调。有的相机不支持配置导出，换机器全部重调，这类型号在评估阶段就被标记出来。线缆和接头的型号随接口一起定，采购时写进清单，坏了按型号换，不临时找替代品。

## 小结

每到一个新场地，打光，锁曝光，锁白平衡，重标定，试射验证距离档，五条合起来是一张固定清单。相机可以慢慢升级，这张清单每场都要走一遍。
