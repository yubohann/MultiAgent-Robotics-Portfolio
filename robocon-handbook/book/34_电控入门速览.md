# 第 34 章 电控入门速览

> 第一次看别人上电，我站在两米外。板子冒烟的那一刻，全场安静了一秒。后来复盘，起因是急停按钮的弹跳加上一笔算错的电源回路。那晚之后，队里上了两路供电。

这章写给上位机方向的人。你的代码最后都要落到这些电机和板子上，不懂它们的特性，联调时你只能反复说“我这边没问题”。

## 先补一点电路

电路，写代码的人要碰，原因在最小的地方就能看到。单片机的引脚在高低电平之间切换，传感器把物理量变成电压，代码读到的每个数，背后都是电。排故的时候，软件没问题这句话能不能站住，取决于你看不看得懂电压与波形。

三个基础量，电压，电流，电阻，关系是欧姆定律，电压等于电流乘电阻。万用表对应三个用法：电压档并到两点上测，电流档串进回路里测，电阻档断电测。上车排故之前，这三个动作要练熟。

三个概念在代码里出现得最多。分压：两个电阻串起来，中间点的电压等于输入电压乘下电阻除以两电阻之和，电池电压就是这样缩小到单片机能测的范围。上拉：引脚悬空时电平不定，读数乱跳，接一个电阻拉到电源，默认就是高电平，按键检测靠它，常见阻值十千欧。滤波：电源引脚旁放 0.1 微法电容就近吸收波动，电源入口再放大容量电容储能，电机启动抽电流的时候，大容量电容先补上电流的缺口。传感器读数抖动，硬件上先看这两级电容，再看软件滤波。

## 电机家族

赛队里最常见的三类任务，对应三类执行器。

底盘用大疆 M3508。这款电机生态成熟，资料多，接入 CAN 总线就能控制，扭矩和转速都够用，损坏后更换方便。这类小体积大扭矩的无刷电机，驱动器里运行的是 FOC，即磁场定向控制。

底盘这批任务有共同点：负载一直在，车重，摩擦，坡度，加减速，全部压在同一批电机上。选型主要看持续扭矩和散热，峰值扭矩只在短时动作里用得上。堵转是这类电机的大敌，堵转电流是额定电流的数倍，热量攒起来直接到烧毁。软件上的对策两条，电流限幅，加速斜坡加长，输出贴着电机的持续能力走。

机构用达妙电机，DM 系列，比如 DM4310。体积小，扭矩高，MIT 模式好用，一个 CAN 帧里同时给位置，速度，扭矩三个指令，写起来简洁。

机构类任务的特点相反，动作短促，频率高，一个赛季往复几十万次。选型看的是峰值扭矩和反馈精度。往复动作接近限位时提前减速，硬撞限位省下的时间拿机构寿命来换，撞过几次，间隙变大，位置标定全部重做。

舵机负责摆角度的动作。总线舵机带角度反馈，几个舵机一串线就能带，不用一个个调脉宽。

舵机有三件配套的事要交代。供电，舵机堵转电流大，和主控共用细线时，电压被拉低，板子跟着复位，所以舵机的供电单独走一路。行程，机械上先限定摆角，程序里再设软限位，两级一起管。反馈，总线舵机回读角度，程序把回读当执行结果核对，命令与回读长期对不上，就停下来查。

没选的路也说一句。CubeMars 的电机进伺服模式之后回不去 MIT 模式，要专用调试器，生态问题多，我们试过之后就避开了。

## 从 Arduino 到 STM32

上位机方向的人迟早要碰底层，一条常见的入门路径是从 Arduino 起步。Arduino 把底层都包好，几行代码就能点灯，转舵机，读传感器，先把代码到动作的最短链路跑通。接着做一个小项目，循迹小车是常见的选择，读传感器，做判断，调 PWM，这个循环就是 PID 的雏形。

小项目跑通之后，往 STM32 走，工具链是 CubeMX 加 HAL 库。先在图形界面把引脚，时钟，串口配出来，再写业务逻辑。有三道关要过。中断，外部事件靠它响应，编码器读数和限位触发都走这里。定时器，控制周期的精度由它保证，PID 的采样间隔写进定时器配置。总线先学 UART，串口打印是排故的眼睛，再学 CAN，车上的电机都挂在这条线上。

两个阶段的差别值得说透。Arduino 把时钟，寄存器，中断都藏在库后面，开发快，出问题只能在代码层猜。STM32 把这些摆在外面，上手慢，每一层都能查。小项目用 Arduino 交付没有问题，车上的节点按 STM32 的规范写。过渡期最容易犯的错是拿 Arduino 的写法写 STM32，delay 阻塞主循环，一次串口打印就把控制周期打乱。

## 驱动器与控制模式

电机本身不包含控制逻辑，控制功能由驱动器完成。驱动器一般提供几种控制模式：电流模式管力矩，速度模式管转多快，位置模式管转到哪。往上叠，对应电流环，速度环，位置环三层结构。

三种模式的用法分开记。电流模式给力控和柔顺动作，机构贴着外力走的时候用它。速度模式给连续转动，底盘轮组和发射摩擦轮都在这一档。位置模式给到位的动作，摆臂转多少度由它管。模式切换放在低速或者静止的窗口里做，切换瞬间限幅，避免阶跃冲击。

调试顺序固定自内向外：先确认电流环，再调速度环，最后碰位置环。内环没稳，外环怎么调都没有意义。达妙的 MIT 模式把位置，速度，扭矩统一下发，简单，但也意味着保护逻辑全部由用户代码承担，限幅不做，电机可能以全扭矩撞上机构。

## CAN 总线实操

CAN 用两根线连接一串节点，电机全在线上应答。实操要记住几条。

每个节点的 ID 不能重，重了就互相冲突。总线两头要终端电阻，少一个，通信时好时坏，这种故障最棘手。电机的状态帧周期性刷新，控制帧的发送节奏要与它匹配，发太快总线承受不住，发太慢机构动作失稳。

排查 CAN 问题，线缆和供电先查，代码放到最后怀疑。

终端电阻的检查是第一招。值是一百二十欧，两端各一个，断电状态下量总线两头，读到六十欧左右说明两个都在，读到一百二十欧说明缺一个。总线负载率估一下占用，留出余量，控制帧发得快是常态，发到总线满起来，丢帧先出现。

排查写成五步更清楚：终端电阻，波特率一致性，节点 ID 冲突，线序与共地，最后看负载率和错误计数。CANH 与 CANL 接反是新手常见的手误，接反不通，换回来就行，不会烧器件。

## 编码器与传感器

电机转了多少，舵机摆在哪，限位碰没碰到，这些信息分两类来源，电机内置的编码器和外挂的传感器。

编码器分增量式和绝对式。增量式输出 A，B，Z 三路信号，A 与 B 相差九十度，靠相位先后判方向，Z 相每转一圈给一个零点。A 和 B 的四个跳变沿都能计数，四倍频后分辨率是线数的四倍。它的短板在上电时刻，不知道自己在哪，要回零。绝对式上电就报角度，单圈记一圈内的位置，多圈再加圈数，关节类反馈多用它。

编码器有两个指标要分开。分辨率是能分清的最小角度，精度是读数离真值多远。高分辨率不等于高精度，安装偏心，磁体偏心，温漂都会让读数整体偏移，所以装完要标定，把已知角度和读数对一遍。

车上外挂的传感器主要三类。限位开关做到位和超程保护，接线简单，安装位置要在机械设计阶段留好。IMU 给三轴加速度与角速度，姿态解算和轮式里程计融合都靠它。距离与目标类传感器在视觉和雷达的章节里讲。

编码器出问题按一个顺序查：先信号，后安装，再标定。信号层拿示波器看 A，B 的波形与相位，安装层查偏心，松动，线缆应力，标定层复查方向与零点。全部丢失和偶发丢失的路径不同，偶发丢先怀疑干扰与接触不良。

## PID 逐环调试法

PID 在电控里用得最多，调法有纪律。

一次只动一个参数，改完立刻测试并记录结果。

先 P，后 I，再 D。P 给到系统开始小振荡，退一点。I 消稳态误差，给大了会产生明显过冲。D 压振荡，噪声大的系统慎用。

按环来。速度环调好再进位置环，位置环的噪声往往是从速度环漏上来的。

所有参数都有适用工况。换个负载，换块电池，参数就可能不适用，所以参数表要跟着每台车维护。

再补两条纪律。采样周期固定，控制周期写死，PID 的输出才有可比性，周期一变，同一组参数的表现跟着变。积分限幅，误差长期消不掉的时候积分项越积越大，放开的时候产生大超调，给积分项设上限，位置环上尤其要设。每次改动留一行记录：哪台车，哪个环，改了什么，改完的表现。

## 电源系统

电控一半的异常出在电源上。

我们最严重的一次事故是急停弹跳烧板，复盘之后上了两路供电：动力一路给电机，逻辑一路给板和上位机，中间用 DC-DC 隔开。电机的启动电流很大，电池电压一被拉下去，逻辑那一路跟着抖，轻则复位，重则烧器件。

选 DC-DC 要核算两个指标：峰值电流余量和压降。偶发复位的案子我们查过一次，最后确认是电源在特定工况下掉出了允许范围。

电池的账先立三个词。电压，按电芯串联数算，常见档位 7.4 伏和 11.1 伏。容量，按安时算，决定能撑多久。放电倍率，决定瞬时能放出多少电流，倍率乘容量，就是这块电池的电流上限。三个数不够用的时候，母线电压被拉下去，现象是板子复位，电机出力下降。

布线与接插件按电流选。电流大一级，线径粗一档，接插件用航插或者带锁扣的。车一震，松动的接插件比焊点先失效。上电顺序写进流程卡：先逻辑后动力，下电反序，每次执行，不凭记忆。

## 焊接与接线

电控的动手活主要是焊接和接线。这两件事练起来花不了多少时间，跳过不练的代价，会在每一次排故时出现。

焊接几条规矩。烙铁温度 320 到 380 度，偏低挂不上锡，偏高伤焊盘和元件。烙铁头闲置时挂一层锡保护，氧化发黑的头导热迅速变差。头不能锉不能磨，磨掉镀层就报废。一个焊点两三秒完成，锡化开就撤，停久了热量顺着引脚进元件。焊线先给线头预挂锡，再给焊盘预挂锡，两个预挂锡面一碰就合。

焊完的检查也要成习惯。放大镜看焊点，圆润发亮是正常的，发灰起渣是温度不对，拉尖是撤得快了。万用表通断档扫相邻引脚，连锡是最常见的返工原因。走线先规划再动手，贴着车架，每段留固定点，活动线束留弯折余量，线被扯断的情况会少很多。

## 急停与安全回路

急停是车上最后一级保护。比赛里它必须做到一件事：拍下去，车停住并进入安全状态。

做法上我们坚持三点。锁存，拍下之后保持断电状态，人工复位才能恢复，防住弹跳式断电。直断动力，急停切电机的动力回路，软件里的急停命令只是辅助，不能替代硬件断电。限位和过流保护留在控制器端，机构撞限位或者电流超限，驱动器自动收力。

作为软件方向的人，我对急停的体会是：不要假设程序始终正常运行，这条回路要在程序失效的情况下仍然工作。
