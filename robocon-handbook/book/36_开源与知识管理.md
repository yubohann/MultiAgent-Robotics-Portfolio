# 第 36 章 开源与知识管理

> 老队长毕业那个暑假，后勤先断了联。供应商联系人只存在他那台蓝屏的旧电脑里，全队找不出一份备份。那年买一个零件，后勤靠着翻聊天记录找线索，找了三天。

知识管理这个词听起来很大，落到实处就是一件事：人走了，资料和记录还留在队里。这章讲我们的教训和后来立的规矩。

## 仓库运营

代码进仓库，这是底线。仓库的规矩有几条。

main 分支上的代码必须是在车上跑过的，其余代码待在自己的分支。每次比赛之前打一个 tag，那台车的代码就冻结在这儿。大文件走 Git LFS 或者单独归档，录包尤其要绕开仓库本体。

还有一个教训：参数也是代码。参数被覆盖那次事件之后，我们定了规矩，一车一套参，参数文件进仓库，开机自检的时候打印版本号。车上的参数和仓库对表，版本一致才允许比赛。

版本留存的做法：每次修改标上日期和改动点，一行就够，比如“日期，底盘图纸，调整孔距”。图纸，代码，参数使用同一套格式，翻历史的时候按行找。出过一类教训：机械改了零件没有通知，电控按旧尺寸写的东西白写两天。交叉的改动，改了的一方说一声，受影响的一方确认了才动手，这条后来进了版本留存的规定。

仓库的目录结构也提前定死，代码，脚本，文档，参数各占一层，新人进来照着目录找东西，不靠问人。定得晚的代价是搬家，一次迁移比一次约定贵得多。

## 文档规范

文档是写给三个月后的自己看的。三个月后，今天解决的问题基本都会忘掉。

我们认的文档结构很朴素：现象，排查路径，根因，解决，预防。这五段写下来，一篇故障记录就成型了。写的时候手要快，趁还记着，先把事实钉牢，润色放在后面。

接口文档单独一档。字段，单位，频率，超时，四条对齐，签完字才算数。跨组联调出问题，先翻接口文档，八成能找到分歧点。

文档的命名用同一套格式，日期加主题加状态，找的时候按时间翻，翻到哪份看哪份。改版之后旧版不要删，标上状态：现行，废止，或者合并去了哪一份。队里最费时间的一份文档，是“以为它是最新的”那一份，版本乱比没有文档还难查。

重要的文档要有第二个人看过。一个人的笔误，两个人能挡掉一部分。看过的人在文末留一行名字和日期，这行字约定的是责任。

## 资料归档

资料分四类归档：规则书历年版本一档，图纸和模型一档，录包和标定数据一档，行政信息一档。

行政信息包括采购渠道，供应商联系人，报销流程，器材清单。这些东西平时不起眼。从那台蓝屏电脑之后，我们的规矩是：任何只存在于某个人电脑里的资料，都要立刻归档一份。

四类资料各有各的落法。规则书按赛季编年份，问答和补充说明跟着当年版本走。图纸和模型留最终出货版加关键中间版，删之前想清楚。录包按日期和场景命名，标上是哪台车，哪个场地，室内馆和室外场的数据不要混在一个文件夹。行政信息随时更新，采购渠道变了，联系人换了，当下就改，拖一周就忘。

纸质的东西拍照进库：加工单，验收单，会议记录。实物归档两样，样件和备份件，标上名字和日期，柜子上的标签和文档里的清单对得上。找得到和存得住一样重要。

备份做三层：仓库一份，移动硬盘一份，云端或者队里服务器一份。赛前把所有资料同步一遍，比赛期间每天晚上同步增量。

## 开源礼仪

我们的技术栈很大一部分建立在别人的成果上。FAST-LIO2 和它用的增量 k-d 树是港大张富组的成果，这一点要写清楚。固定地图那块，我们用的就是 ICP 这套东西。哪些是自己的，哪些是别人的，队里要有一份清单。

用开源有三条规矩：用之前读 license，用之后写出处，改进别人的方案要注明基于谁的。把自己的东西开源出去的时候，README 写清楚依赖什么，跑在什么环境，哪些参数必须改。

细一点的规矩也有几条。用开源库之前先看 license 的类型，MIT 和 Apache 这类限制少，注明出处即可，GPL 类的要求衍生作品继续开源，用法上有疑问先问清楚再动手。改别人的方案，改动点标在自己的文档里，上游更新了要对一遍，避免两边的版本各走一路。别人用了你们的东西并且改了，条件允许的话请他把改进提回来。

把拿来的东西讲成自研，破坏的是学术诚信，也损害队里的口碑。这个圈子很小，彼此都认识。

## 数据交接

每年毕业季，队里最重的活是交接。

交接分两种。人的交接：谁毕业后，他的任务谁接，一对一带着走一遍，至少留一个月的重叠期。物的交接：账号，密码，服务器权限，仓库权限，联系人，全部更新到公共文档，换人之后老密码立刻停用。

赛季末还有一次大交接：复盘文档，参数表，故障矩阵，下一个赛季的接口文档草案，全部归位。这些资料齐了，新赛季的第一次周训才能直接从“去年讲到哪了”续上。

交接要落成清单：账号一类，密码一类，服务器与仓库权限一类，联系人一类，每项写明现在谁持有，转给谁，什么时候转。接手的人对照清单逐个确认，口头交接不算完成，能自己操作一遍才算。

权限比密码更容易被忘记。谁有仓库的合并权限，谁有服务器的登录权限，谁在组委会的对接群里，这些逐项过一遍，把名单和总目录一起放进公共文档，不在任何一个人的聊天记录里。

也有一套验收标准：接手的人不问任何人，完成一次开机自检，改一次参数，提交一次代码，查一次录包。四件都做通，交接才算完成。

知识管理没有终点。把资料交接做成固定流程，队伍换人时才接得上。
