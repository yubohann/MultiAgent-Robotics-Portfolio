# 第 11 章 雷达与定位案例

> 实验室里连跑三天都稳，进场馆就开始随机跳变。定位平时不显眼，一出问题全队停摆。这一章五张卡，来自五次正面遭遇的实战复盘。

## 案例 1：定位疑难，环境差异型故障

**现象**：定位系统在实验室连续几天保持稳定，到了赛场频繁跳变，漂移随机出现，有时又完全正常。场上的位姿变化没有规律。同一天里，上一场表现正常，下一场全面失准，我们连复现都做不到。

**排查路径**：

1. 怀疑数据延迟，降频率，抽样回放，排除。判定依据是跳变的幅度远超延迟能解释的量级，延迟只造成整体滞后，不会让位姿来回跳
2. 怀疑雷达硬件个体问题，换上备用雷达，排除。同一套硬件在实验室连跑几天都稳，换到赛场故障照旧，故障跟场地走，不跟设备走
3. 怀疑传输链路，小主机到主控的链路板逐一更换，排除。更换期间统计了链路层错包计数与断连次数，数字都正常
4. 问题时好时坏，找不到能把问题稳定复现的修改点。赛程不允许继续等，先带着问题上场。事后整理记录，跳变的出现位置有聚集倾向，个别区域出现次数偏多，这些区域在实验室里没有对应物

**根因**：未最终定位。嫌疑集中在与实验室差异过大的环境变量上，场馆地面的反光与纹理，周围设备的电磁环境，机械振动耦合到雷达支架，几项叠加。每一项单独看都正常，叠加后故障出现。环境差异大致分两类。几何一类，场馆地面平整反光，能提供约束的墙面离得远，扫描匹配在弱约束下容易接受错误结果，反光还会制造出距离虚高的假点。非几何一类，密集人流与设备带来电磁噪声与动态遮挡，振动沿支架耦合进雷达安装面。实验室里每项都在容忍范围内，赛场里几项同时踩过算法的余量。

**解决**：赛中没有解决。整场比赛只有最后一场正常发挥，勉强打完收官战。回队之后，环境差异排查立成专项，重点放在备馆阶段的暴露测试。专项的第一个动作是把整条定位链放进场地连跑，记录跳变次数与触发区域，把实验室里逼不出来的问题尽量在备馆里反复出现。降级口径提前定死，纯里程计加固定点位校准怎么走，在哪里停一下重校，超时怎么处理，都写下来。

**预防**：

- 备馆调试时间优先安排，多一天备馆就多一次暴露环境差异的机会。赛程排布上把备馆的每一天都按正式比赛演练，作息，节奏，流程全对齐，问题出现得越早，留的修复时间越充裕
- 关键模块必须有降级方案，里程计推算加固定点位校准的兜底提前备好。降级后的路线与重校点位提前写死，触发条件交给状态机自动判断
- 换件式排查要留记录，每次换件前后跑了什么，结果如何，都写进排查记录。记录还有个用法，故障跟着件走是硬件问题，跟着位置走是环境问题，两类问题的后续动作不同
- 位姿质量三项跟着位姿一起播发，跟踪状态，地图锁定，位姿年龄，出现异常先看这三项

延伸：环境差异可以列一张对照表，逐项比实验室与场馆。地面材质与反光，周围金属结构与动线，人群密度与活动模式，无线电占用，振动源。每项标上在场观察到什么，哪个区域最明显。表格本身不解决问题，但能把它拆成可以逐项对付的子问题，排查有了具体的落点。

## 案例 2：3i-2D 解析链排错，从乱码到点云

**现象**：2D 雷达经网口接入开发板。链路通，组帧验证全对，单 Block 192 点，8 个 Block 拼出 270 度，总点数 1536。无遮挡区域本该干净，点云里杂点却铺满画面，1 米外的桌腿与墙面混成一片，量程过滤与降采样看起来没有生效。

**排查路径**：

1. 先查基础层，处理日志乱码，JSON 帧分割不完整与 Base64 解码问题，用点数与角度逐级验证组帧。验证方式是做点数账，单 Block 192 点，8 个 Block 共 1536 点，角度覆盖 270 度，三个数对得上，组帧算通过
2. 打印原始距离值，核对毫米与米的单位假设。打印发现多数值量级正常，少数值集中在 0 与满量程两端，这两端就是无效回波的编码，量级核对顺带给无效值定了位
3. 反查过滤代码有没有真的执行，用打点与断点确认。过滤入口与出口各打一行累计点数，数字不动，说明代码没执行或条件全不满足，两种都要继续查
4. 翻雷达手册，核对角分辨率，约 0.175 度每个点。远距光斑随距离张开，相邻采样在边缘糊在一起，这是器件的物理账，软件解决不了

**根因**：未完全定论，方向锁定两个。其一，数据有效性没验证就写了处理逻辑，坏点全被当成有效点使用。其二，远距边缘的模糊贴着角分辨率的物理极限，属于器件层面的物理限制。两条同时存在，排查中互相掩盖。解码链的顺序是物理连接，分帧，解码，单位换算，有效性检查，过滤，任何一步颠倒，后面全错，终端里的乱码只是最表层的一步。无效回波在数据里通常有约定的编码，不先剔掉，它们会以原点附近的碎点或者拉满量程的远点混进画面，看起来像过滤没有生效。边缘模糊是另一类，光束随距离张开，角分辨率决定两个相邻点能不能分开，这是器件参数，改软件改不动。

**解决**：逐条排除。先验证单位与有效性，再确认过滤代码执行路径，最后照手册把方法问题与物理极限分开。复测时点数按预期减少，残留的模糊点也确认了来源。修完给处理管线每一层都留了可观测输出，分帧成功率，数值量级分布，过滤前后点数，三层数字都进日志。

**预防**：

- 怀疑代码没生效时，第一步先确认它到底有没有执行
- 排错顺序固定，物理连接，数据有效性，处理逻辑，对照手册
- 方法与物理限制分开排查，混在一起无法定论
- 无效回波的处理写死在有效性层，约定为 0 或满量程一类的编码一律先剔除，不允许流进点云
- 每层数字进日志，分帧成功率，量级分布，过滤前后点数，出问题先看数，对不上再查代码

## 案例 3：单点激光测距做基准校准

**现象**：场地固定站位上，我们需要一个绝对位置基准。方案很直接，用单点激光测距传感器量车到挡板的距离，反推车在场地里的位置，给定位链校零点。实测读数来回跳，同一站位同一姿势，两次量出来对不上，校准结果跟着漂。

**排查路径**：

1. 先核对标定，近点远点分别查一遍，两端都不差，问题出在标定之外。标定曲线这一段可信，读数跳动另有来源
2. 把传感器装在低位试一次，车体轻微起伏，读数立刻跟着跳，装机高度有嫌疑。起伏量与跳变量对得上，高度的问题先记下
3. 检查目标面，打到斜面上读数偏，打到深色面上更偏，入射角与材质也有影响。光斑变形与回光变弱都在读数上留下痕迹
4. 多点同时取数，发现单点的偶然抖动可以用中值压下去。每个站位布多个测点，读数取中值，换算结果每轮接近

**根因**：单点激光的读数对安装高度，入射角度和目标面材质都敏感。安装位置低时，车体起伏被一起量进读数，单点一次测量没有复核机会，抖动直接进入坐标换算。多数单点激光按光斑位置反推距离，读数对入射角与目标面材质都敏感，角度一大光斑变形，深色面回光弱，噪声跟着上来。安装位置的账另算，装在低位时车体的俯仰与滚转被一起量进去，地板振动也能进读数。

**解决**：传感器抬到受车身晃动小的位置，安装面找正。每个校准站位布多个测点，读数取中值再换算。换算只在车停稳时执行，取数窗口内连采多次，车动起来不回读。每个站位测完与上次记录对一遍，差值超出经验范围就重测。换算结果只用来给定位链对零点，连续位置估计照常交给雷达。

**预防**：

- 单点激光只负责基准校准，连续定位交回给雷达，分工写进接口文档
- 场地适应期复标一次基准，高度与角度记进装配记录，下次复标先照上次的位置摆
- 校准数据留档，下次同一个站位可以前后对照
- 取数前过一道合理性检查，超出站位间预期差值的数据当场丢弃重测

## 案例 4：重定位初值偏差引发的紧急急停

**现象**：重定位第一版上线试跑，流程走通，车从待机区起步，直直地朝挡板方向冲，定位给出的自身位姿落在场地另一头。急停链路在零点一秒内切断动力，车在离挡板半个车身的地方停住。

**排查路径**：

1. 回放录包，把前后位姿序列拉出来对，初值给了半米左右的偏差。日志里能看到漂移的起点，对准时间轴，跳变发生在扫描匹配第一次收修正的那一刻
2. 查初值来源，上一环节的猜测位姿直接喂给了扫描匹配，中间没有检查。初值链条上没有任何检查点
3. 人为把初值偏开复现，匹配分数在偏值时依然收敛，错误初值会被当作正常结果接受。这一步说明匹配分数只反映点云贴合程度，判不出位姿对错
4. 复查急停，锁存与复位功能正常，问题集中在重定位准入条件上。急停在零点一秒内切断动力，这一环没有问题

**根因**：扫描匹配适合小范围精修，初值偏一点能拉回来，偏半米也能收敛出看起来正常的匹配分数。缺失的环节是初值进算法前的那道质量检查。扫描匹配是局部优化，在初值附近找最贴合的解，初值错了，解就收敛到错误的一侧，过程平静，没有报错。可以补的检查有两层，一层是初值来源的可信度，起点区域与上一刻位姿都能做交叉确认，另一层是修正幅度，相对当前位姿的幅度限制能拦住大偏差。

**解决**：重定位初值专项做了一周。多假设初值并行试，两个以上假设收敛到一致解才放行，不一致就保持上一位姿重新试。修正量设限，单次平移超过 0.80 米或偏航超过 25 度一律拒收，位姿年龄超过 0.30 秒不收。修正后先小范围试走，确认无误再进任务流程。

**预防**：

- 急停链路保持最高优先级，锁存加人工复位，这一条固定不变
- 重定位的准入条件写进启动自检与赛前预检
- 改初值估计逻辑，同场景录包回归，偏值场景存成测试用例，后续每版软件都要过一遍这批用例
- 初值链条每一环留检查点，起点区域确认，与上一刻位姿的连续性确认，多假设一致性确认，三项都过才进匹配

## 案例 5：空旷场地的纯里程计漂移

**现象**：空旷区域缺少参照物，墙面离得远。纯里程计在短距离内误差不明显，跑一段回来对表，位置差出几厘米，朝向慢慢偏。远距离投射的时候，yaw 的误差被距离放大，瞄的位置和实际位置差出一个球的距离。

**排查路径**：

1. 录包回放，同一段路跑两遍，漂移方向一致，属于系统性问题。两遍的量级也接近，可以按固定观测点做重复对照
2. 对比两种区域，开阔处的有效匹配点明显变少。与实验室走廊的点数一比，几何约束不足的判断有了观察支撑
3. 复现急转弯，角速度拉高之后，点云分层，旋转错位肉眼可见。错位量与角速度大致成比例
4. 对时间戳，急转工况下时间偏差与旋转错位的对应关系对上了。角速度 180 度每秒时，10 毫秒偏差约等于 1.8 度旋转错位，点云分层由此而来

**根因**：空旷场地里雷达能用的几何约束少，弱约束下匹配容易接受错误结果，误差随距离与时间积累。高速旋转时，时间戳上的偏差会被角速度放大，角速度 180 度每秒的工况下，10 毫秒的偏差约等于 1.8 度的旋转错位，点云叠成分层。墙面离得远时入射角小，返回点稀疏，匹配沿墙面方向的约束弱，航向角最难被约束，误差沿航向积累。逐点扫描的雷达每个点采集时刻不同，去畸变依赖时间同步精度，同步差一点，高速旋转下错层就出现。yaw 误差在投射场景里按距离放大，同样的角度偏差，目标越远横向偏得越多。

**解决**：关键站位与动作靠固定地图匹配校正，纯里程计只在特征足够的位置启用。急转工况下把角速度上限调低，时间同步重新标了一轮，标完用急转场景复测，点云不再分层才算修完。

**预防**：

- 场地巡检时记录特征分布，供任务编排参考，特征不足的区域与站位标出来
- 纯里程计的误差按 2 到 4 厘米的量级估算，这是短距离口径，远距离任务按时校正
- 涉及旋转的标定与同步，验收一律加急转弯工况
- 每次更新定位软件，先过一遍急转回归，点云质量与位姿连续性都看
