### 27. 2026-08-06 文献总结与候选池修复

结合本地失败证据和公开论文/仓库，短路线、折返、频繁停机重规划和同走廊冲突的成熟解决方案不是再调控制器，而是先修候选池层次与任务连续性。

- RACER（T-RO 2023）：空间分解 + 全局 MTSP/ACVRP 覆盖路线 + 局部观察位点，路径截断和死端处理，避免频繁全量重规划。
- FUEL（RA-L 2021）：前沿聚类、全局访问路线、局部观察位点、B 样条轨迹；低重规划频率被认为是探索慢的重要原因。
- C2-Explorer（IROS 2026）：把区域任务与连通约束结合，任务分配更连续；公开高层代码仍是单层 grid，不能直接声称支持 HM3D 多层。
- FC-Planner（ICRA 2024）：骨架全局覆盖路线 + 局部位点，强调 global/local hierarchy。
- Fast Multi-Robot Exploration（RA-L 2023）：EXPLORER/GARBAGE_COLLECTOR 角色切换，避免无任务时短视抖动。
- GVP-MREP（IROS 2024）：MR-DTG、局部/全局 GVP、图 Voronoi 分配和 job state，证明多机分配需要 owner、距离、增益、剩余时间和失效候选删除。
- VORL-EXPLORE（IROS 2026）：把 execution fidelity 耦合进任务分配，直接针对分配器不了解执行难度导致的振荡重规划。

## 0. 结论

当前不能继续把所有未完成模块都设为大实验前置条件。进入大规模真实执行结果采集只保留五个硬门槛：

> 指标可信、执行不空闲等待、路线能跨区域、四机确实参与分工、运行不崩溃。

执行顺序冻结为：

```text
修复 P0 硬错误
-> 两张差异场景的 40 秒完整性复测
-> 若且仅若两图均满足 M1-M5，冻结当前 v6/v1 执行合同
-> 启动 300 个真实决策执行结果
-> 1000 / 3000 / 5000 冻结检查点
-> 并行补齐 GVP-MREP 与 MARL-IPP 资格
-> 主方法通过 random 和强规划基线后再跑完整主表与消融
```

### 0.1.1 当前 `00626` 安全包络死锁与恢复协议

`00626` 的下一处直接阻塞不是放宽物理安全阈值，也不是更换控制器。该回合的
两机间距处在物理硬下限 `0.50 m` 与正常规划包络 `0.90 m` 之间，普通联合候选
因此全部被 `synchronized_fleet_separation` 拒绝。旧实现只有在已有足够长的
outcome-backed 执行结果历史时才会生成反向路线，冷启动或短执行结果状态没有可执行的
发散动作。

当前代码增加了第二种、仍然严格受限的恢复来源：从当前公共几何中重新守卫一条
路线，并且只在下列条件全部满足时把它标成
`viewpoint_kind=collision_avoidance_recovery`、`task_kind=backtrack`：

- 当前物理间距已经满足 `>=0.50 m`，且恢复时只有一架机移动；
- 其他无人机保持静止，或路线的每个线段都被点积条件证明不会减小与其间距；
- 运行时联合守卫仍逐段检查物理间距、终点规划余量和路径净空；
- 终点重新达到正常规划余量（当前合同为 `0.90 m`，并保留 `0.95 m` 终点余量）；
- 恢复路线不贡献信息增益，不更新公共探索 belief，不写入 QD/OGFR/replay。

恢复候选使用稳定 frontier ID 在 `PublicSearchState` 排序后重新解析索引，不能按
追加顺序假定 synthetic frontier 的位置。普通探索候选一旦有足够可行行，恢复候选
不会进入候选池；因此该协议只解决安全包络死锁，不会把正常四机分工改成单机退让。
现有单元测试覆盖安全发散、相向拒绝、排序索引、显式 recovery 元数据和零收益
合同。该修复尚未关闭 M5，仍需在固定 `00626` 与 `00803` 上完成 fresh-process
40 秒配对 smoke，并修复 `uav3:completed_transit_without_observation_timing`。

需要特别区分旧的 envelope-recovery 资格产物：
`E:\\asset\\hm3d_p0_envelope_recovery_20260805\\00626_frontier3d_v6_envelope_recovery_p0eligible_r1_seed20260805.json`、
对应的 `00803` 文件和 `p0_envelope_recovery_evidence_eligibility_audit_20260805.json`
只允许作为工程动力学、覆盖诊断和配对诊断证据。两份 episode 的每个 decision
中 `collision_avoidance_recovery` 实际均为 `null`，即没有真正执行恢复动作；不能
把配置名称解释成恢复已飞行。审计已经将 formal performance、RL transition 和
QD history 排除，且这些回合不是冻结的 240 秒正式结果。后续必须用固定死锁构造
产生一条非空、被联合守卫接纳的恢复执行结果，才能声称恢复动作实际执行；该执行结果仍不
计探索收益或 replay。

### 0.2 修订后的唯一关键路径

GVP 值得认真完成，但不再作为启动 RL 和真实执行结果采集的前置门槛。主线与外部基线支线按以下顺序推进：

```text
透明规划链跑通
-> 冻结公共候选、执行结果和执行语义
-> random + 透明规划器采集共享预热
-> 启动普通 SAC 与 QD 资格审查
-> 长时间训练期间补 GVP 和 MARL-IPP 论文级资格
-> 正式 holdout 前裁决哪些外部基线有资格进主表
```

这里的“透明规划链”不是当前短步前沿评分器换一个名字，而是最低完整规划能力：

```text
三维前沿聚类
-> 已知自由空间中的观察位点
-> 公共自由空间全局路径
-> 四机全局 agent-viewpoint 分配
-> CF2X 局部可执行轨迹
-> 完成即重规划
```

它同时承担三个职责：P0 验证工具、无学习强透明基线、RL 候选生成基础。若它仍只能生成短路线和大量 hold，任何 SAC、QD 或外部学习基线都没有可信的动作空间。

GVP 与 MARL-IPP 在长训练期间并行建设，但正式主表前必须裁决：合格则进入主表；只恢复部分机制则进入附录或机制表；实现失败则不作为被本文“击败”的对手。

### 0.3 强基线不是占位符

本文对失败实现采用以下规则：

- 作者源码、作者检查点或决策核心没有被忠实保留的版本，只能标记 `prototype`；
- 黄金测试、原任务趋势或 HM3D 合法性失败的版本，不得进入正式主表；
- 正确实现并充分训练后仍然表现差，这是可报告的真实负结果；
- 因输入语义错误、动作语义错误、少训、调参不足或端口退化造成的差结果，不得用来支持本文优越性；
- 失败实验仍保留在工程审计和失败分母中，但论文表格必须明确其证据等级，不能删掉失败后只展示好看的运行。

这既避免拿虚基线规避比较，也避免因为一个局部错误否定此前所有控制和运行证据。

## 3. P0 解决方案

### 3.1 覆盖分母与可追溯 schema

#### 问题

当前起点策略来自最大连通分量，但 P07 分母包含全部保留自由体素。场景 `00626-XiJhRLvpKpX` 中：

```text
最大起点分量 = 20,811 voxels = 325.171875 m^3
全部 8 个分量 = 596.375000 m^3
不可从当前起点到达的额外体积 = 271.203125 m^3
分母膨胀倍数 = 1.834
```

同一条 `5.8046875 m^3` 观测，旧分母为 `0.9733%`，起点分量分母约为 `1.7851%`。修复后仍然很低，因此分母修复不能代替规划与调度修复。

#### 解决方案

在经过无人机净空膨胀后的冻结可飞体素上，复用 P03 的精确连通性定义计算标签：

```text
start_component_ids = unique(component_label(start_uav_i))
reachable_mask = union(component == id for id in start_component_ids)
confirmed_reachable_free = evaluator_confirmed_free intersect reachable_mask
coverage_fraction = volume(confirmed_reachable_free) / volume(reachable_mask)
```

当前四个起点按合同属于最大分量时，`start_component_ids` 应只有一个。只有起点合同明确允许分散到多个互不连通分量时，分母才使用这些起点分量的并集。

分母身份至少包含：

```text
scene_id
start_reset_manifest_sha256
start_component_ids
component_ids
component_voxel_counts
reachable_voxel_count
reachable_volume_m3
origin_center_m
resolution_m
connectivity
flight_space_manifest_hash
collision_geometry_sha256
mask_sha256
metadata_sha256
geometry_evaluation_denominator_sha256
source_geometry_sha256
vehicle_clearance_m
start_reset_manifest_sha256
denominator_sha256
```

生产执行结果使用 `mask_sha256` 与 `metadata_sha256` 表示组件掩码及其解释元数据，
并在 worker 层用 `geometry_evaluation_denominator_sha256` 绑定完整评测分母。
`source_geometry_sha256`、`vehicle_clearance_m` 和 `start_reset_manifest_sha256` 也必须逐回合写入；
不能把旧的 `reachable_mask_sha256` 或单一 `start_component_id` 别名当成当前字段。

需要同步升级的所有权边界：

- P03 飞行空间资产；
- P04 评测/接收位置资产；
- P07 起点和在线执行结果；
- 指标注册表；
- 预检；
- 训练数据 provenance；
- 正式结果文件。

算法不能读取 `reachable_mask` 或连通分量真值。该信息只属于冻结评测器。

#### 旧结果处理

| 旧证据 | 可恢复指标 | 仍然有效的非覆盖证据 |
|---|---|---|
| 有逐决策射线或新增观测体素 | 覆盖曲线、AUC、最终覆盖 | 全部保留 |
| 只有最终公共地图 | 只能重算最终覆盖 | 全部保留 |
| 只有旧百分比 | 覆盖不可重算 | 轨迹、速度、碰撞、守卫、吞吐、通信仍可用 |
| 几何/净空/控制合同已改变 | 不进入正式性能表 | 只作工程诊断 |

重评分必须生成新结果和新哈希，不覆盖原始运行文件。

#### 验收

- 同一场景、同一起点、同一评测配置下，random、frontier、auction、RL 的分母对象逐字段和哈希一致；
- 改变起点分量、净空、分辨率或几何版本时，哈希必然变化；
- 运行中的探索结果不会改变分母；
- 新旧分母重评分结果能追溯到同一原始执行结果哈希。

### 3.2 事件驱动 SMDP 调度

#### 问题

当前固定决策窗口把“动作允许使用的硬上限”和“动作实际持续时间”混为一体。短路线完成后，团队仍占用窗口尾部，物理预算被等待消耗。

#### 最小可落地实现

保留团队同步决策，不立即引入完全异步四机调度：

```text
为本轮设置规划硬超时 action_timeout_s
-> 执行所有已授权轨迹和观察 dwell
-> 全部必需片段完成，或出现失效/硬超时
-> 立即封账并生成下一次决策
```

动作实际持续时间：

```text
delta_t = max(actual_end_s of required team fragments)
```

物理预算是唯一正常终止条件：

```text
while elapsed_physics_s < episode_budget_s:
    plan_and_execute_one_team_action()
```

最大决策数只作为零长度动作死循环保护。它应由冻结的最小合法动作时间和预算推导，而不是预先决定正常回合长度：

```text
max_decisions >= ceil(episode_budget_s / minimum_legal_action_duration_s) + safety_margin
```

最后一个动作若被物理预算截断，必须记录 `truncated_by_budget`，不能伪装成正常完成。

#### SMDP 折扣

不再直接使用：

```text
gamma_transition = 0.99 ** delta_t_seconds
```

改为显式时间尺度：

```text
gamma_transition = gamma_reference ** (delta_t / reference_duration_s)
```

`reference_duration_s` 的候选值只能用训练/开发动作时长分布和期望规划时间尺度冻结。论文必须同时报告 `gamma_reference`、`reference_duration_s` 和由此得到的有效半衰期，不能只写一个无单位的 `gamma=0.99`。

#### 验收

- 执行结果中的 `delta_t` 等于真实完成/超时事件，不等于预留窗口；
- 决策间没有未解释的固定等待；
- 相同物理预算下，决策数允许随方法和动作时长变化；
- 零长度动作不会形成高频死循环；
- 最后动作的完成、任务终止和预算截断语义可区分。

### 3.3 长程前沿观察路线

#### 问题

当前候选主要是从当前位置向附近前沿边界移动一个短终点。增大最大步长不能自动得到穿过房间、走廊和垂直通道的探索路线。

#### 最小合格结构

```text
公共未知/自由边界
-> 三维前沿体素聚类
-> 每个前沿簇生成多个已知自由空间观察位点
-> 估计各位点可见未知体积
-> 在公共已知自由空间中规划全局路径
-> 生成满足 CF2X/守卫合同的局部可执行轨迹
```

核心约束：

- 路径和观察位点必须位于已知合法自由空间；
- 未知空间只能作为传感器观察目标，不能作为无保护捷径；
- “长程”表示路线可以离开当前局部邻域并沿拓扑结构推进，不设置未经验证的固定最小米数；
- 前沿簇应有稳定身份，避免相邻体素每轮重编号导致任务抖动；
- 全局路径代价应使用图/栅格测地距离，不只用欧氏距离；
- 局部轨迹失败时要保留失效原因，并删除或降权失效观察位点。

该分层结构与 FUEL 的增量前沿结构和分层规划原则一致，但本项目不应在 P0 阶段宣称完整复现 FUEL。

#### 验收

- 单层复杂 smoke 图中至少出现一条离开起点房间/局部邻域的合法路线；
- 多层 smoke 图中至少生成并真实执行一条通向垂直连接区域的路线；
- 所有路径点均通过公共自由空间、净空、动力学和守卫检查；
- 路线失败不会静默退化成无理由 hold；
- 候选池同时保留局部高收益和全局推进候选，而不是全部变成长路线。

### 3.3.1 公共任务的跨决策生命周期

#### 已确认的根因

旧候选层在每个决策重新从稀疏公共前沿生成联合分配。一次短航段完成后只保留末端朝向，未保留“这架无人机仍在执行哪个公开任务”的身份，因此下一轮会把刚完成的任务当作不存在，重新偏向最近的小前沿。这会产生短航段、90--180 度换向和无必要的折返。它是候选任务生命周期缺失，不是 CF2X 飞控必然失败，也不能靠设定固定最小路线长度解决。

#### 当前修复合同

活跃实现使用 `PublicTaskReservation`（`hm3d-public-task-reservation-v1`）作为公共、执行结果支持的任务关联证据：

1. 只有完成安全的公共 `observation` 或 `route_progress` transit 后，才可为对应无人机建立 reservation；hold、relay、backtrack 和失败航段不能建立探索 reservation。
2. reservation 只保存任务锚点、任务法向、终端航向、来源决策/manifest/路径/执行结果哈希和簇来源审计信息，不保存可直接重放的旧轨迹或 evaluator 真值。
3. 每个决策从当前公共观测重新提取 frontiers，并用锚点半径、法向一致性和当前 agent pose 重新生成/守卫访问路径。匹配失败就释放 reservation；旧 manifest 不得绕过当前净空、通信、时序或联合安全检查。
4. 匹配且方向前向兼容的任务在相同公开收益下优先保留；当前 `frontier_3d` 选择器使用冻结的 `PUBLIC_TASK_RESERVATION_SWITCH_MARGIN_GAIN` 作为有限滞回：只在最高公共收益的该容差内偏向前向 reservation，超过容差的新公开任务仍然可以切换。该项只是选择排序证据，不能覆盖 guard 或强迫无人机运动。
5. reservation 复用、释放、切换和原因写入逐决策执行结果；其 transit 失败或安全恢复执行结果不得计为探索收益，也不得进入 QD/OGFR 可复用样本。

这不是固定路线长度目标，也不保证每轮都产生长航段。路线仍由当前公共已知自由空间、观察位点和物理预算决定；该层只避免在任务仍然可公开确认时无理由洗牌。若合法边普遍只有亚米级，必须审查稀疏射线支持和观察位点生成，而不能用选择器硬造长度。

#### v6 执行结果兼容性与拒绝规则

`hm3d-public-candidate-pool-v5` 不具备跨决策公开任务生命周期；不能通过给旧 JSON 补写字段来升级为 v7。进入 P07 正式比较、P08/QD、outcome dataset、SAC 或 MARL-IPP 训练的记录必须 fail-closed：缺字段、版本不完全相等、或 transition 与所属 decision 绑定不一致时一律拒绝，而不是降级混入。

顶层 P07 outcome 必须同时绑定：

```text
candidate_pool_schema_version = hm3d-public-candidate-pool-v7
task_reservation_schema_version = hm3d-public-task-reservation-v1
public_candidate_pool_hash
public_candidate_pool_sequence_hash
runtime_record_sha256
```

每个 executed decision 及其训练 transition 必须再次绑定前两个 schema version，并具备：

```text
decision_id
public_context_hash
public_candidate_pool_hash
selected_manifest_hash
next_public_context_hash
next_public_candidate_pool_hash
outcome_hash
transition_sha256
```

其中版本字段必须等于所属顶层 outcome，当前 pool/context/hash 必须等于对应 executed decision；非终止 transition 的 `next_*` 必须等于下一条真实 transition 的当前状态。只有此完整链路才可说明候选、任务 reservation、行为执行结果和学习样本属于同一语义域。

旧 v5 运行不因此被删除或否定：其控制完成率、真实轨迹、速度、跟踪、碰撞、吞吐和视频诊断仍可保留。它们不得进入 RL/QD/OGFR replay、训练数据集、planned/realised-QD 比较、P07 正式性能均值或跨方法配对统计；若需这些用途，必须以 v6/v1 合同重新执行。

#### 验收指标

- 逐决策报告 reservation 建立、匹配、释放、切换数量及释放原因；
- 报告每机任务切换率、连续任务 transit 数、反向率、重复前缀率和实际/计划路程比；
- 固定 `00626` 用于安全包络/受限任务诊断，不作为四机分工证据；
- 在预注册且四机各有合法互不冲突观察边的 reset 上验证 M4，而不是强迫 `00626` 每轮四机活动；
- 对比修复前后的任务切换和路径连续性时，控制器、起点、随机种子、物理预算和公共观测合同必须冻结。

### 3.4 四机全局分配与候选多样性

#### 问题

当前有效执行结果中没有任何候选让四机同时探索，但最新 v4 两图诊断修正了旧的归因：`_feasibility_first_assignments()` 已先枚举每架机的公共可达边并保留最少 hold 的组合；`00626` 的 `uav3`、`00803` 的 `uav2` 在多数轮次的合法边计数仍为零。因此不能把本问题简单写成“按无人机编号贪心分配”。仍需保证全局匹配不依赖编号顺序，但当前首要缺口是起点附近的可安全观察位点/首轮候选资格。

#### 解决方案

四架无人机规模很小，可以优先使用可审计的精确或近精确分配：

1. 为每架无人机保留前 `K` 个合法观察位点；
2. 构建 agent-viewpoint 二部代价；
3. 用 Hungarian、min-cost flow 或分支限界求联合分配；
4. 对联合路径做时空冲突和通信检查；
5. 用 no-good cut/模式约束保留若干个协作方式不同的高分联合候选。

首轮资格不能只检查“起点互相通信”。在冻结起点前，还要用同一 bootstrap 收据、公共自由空间搜索、静态守卫和 v4 时间合同建立 agent-viewpoint 边表：每架机至少一条合法前沿观察边；若存在四条互不冲突边，候选池必须保留一个全活动匹配。该检查只使用执行安全所需的守卫结果，不向选择器暴露评测分母、房间或楼层真值。若某架机边数为零，必须先更换预注册起点或增加公共稀疏观察位点，不能降低净空阈值，也不能把 hold 改写成 relay。

单机到观察位点的基础效用：

```text
预计新增可见未知体积
- 到达时间
- 与队友的预计观测重叠
- 路径冲突风险
- 断联风险
- 当前工作量失衡
```

团队级还要计算：

- 活动无人机数；
- 目标前沿簇数量；
- 最小机间距；
- 预计公共观测互补性；
- 通信图连通占空；
- 是否存在真实中继角色。

候选生成器负责产生多种合法分工，random、规划器和 RL 负责从同一候选池选择。若候选池只有一种分工，后端选择器没有可学习空间。

#### hold 合同

每个 hold 必须有且只有一个主要原因：

```text
relay_required
collision_avoidance
no_reachable_viewpoint
waiting_for_team_completion
controller_failure
```

可增加二级诊断，但不能用 `relay_required` 掩盖匹配失败。只有移除该无人机会使冻结通信约束失效，才能认定真实中继。

#### 验收

- 存在 4 个互不冲突合法任务时，候选池至少有一个四机活动方案；
- 不强迫狭窄区域每轮四机都移动；
- 每次 hold 均能从候选、路径、通信和守卫记录重建原因；
- 候选池至少包含若干目标簇分配或活动机数组合不同的联合方案；
- agent id 置换测试不会系统性改变谁长期获得任务。

### 3.5 解释 `37.3%` 公共自由空间未被评测几何确认

不能只要求一个总百分比下降。必须对每个不一致体素或体积片段做互斥归因：

```text
grid_origin_or_resolution_mismatch
ray_marching_discretization
wall_penetration
clearance_definition_difference
duplicate_observation_accounting
outside_start_component
line_of_sight_occlusion
legitimate_sensor_uncertainty
```

归因总和必须在数值容差内守恒到总差异体积。

阻塞采集的类别：

- 墙体穿透；
- 坐标系、栅格原点或分辨率错配；
- 射线端点/步进导致系统性漏计；
- 算法使用了评测器不可见的几何真值。

可记录后继续采集的类别：

- 合法遮挡；
- 传感器有限视场和量程；
- 公共地图与评测净空定义的预注册差异；
- 当前起点不可达分量。

### 3.7 CF2X 控制器与论文创新边界

#### 直接结论

正式 CF2X/PhysX 动力学实验不能完全取消控制器。规划器输出位置、速度或轨迹目标，而 IsaacLab 最终接收四个旋翼的推力目标；两者之间必然需要控制律。调用仿真器的位置/速度接口也只是把控制器隐藏在接口内部，不等于没有控制器。

可以不使用控制器的唯一方式是直接写入机体位姿的运动学执行。这种模式只允许用于前沿、分配、QD、RL 接口和吞吐调试，必须显式标记 `kinematic_debug_only`，不得进入正式主表，也不得支持以下声称或指标：

- CF2X 动力学可执行性；
- 真实跟踪误差、航段失败和转弯代价；
- 动力学碰撞与实际机间距离；
- 电机/推力能耗；
- PhysX 连续飞行鲁棒性。

否则审稿人可以合理质疑：既然无人机只是被直接移动，使用 Isaac 和 CF2X 只是包装，本文并没有验证真实四旋翼执行。

#### 为什么当前存在自定义控制器

当前 [`hm3d_cf2x_execution.py`](../src/aerocity_method/runtime/hm3d_cf2x_execution.py#L167) 的 `time-parameterized-trapezoid-so3-guarded-v8` 与 `isaac-so3-feedback-v6` 补齐了以下缺失桥接：

```text
局部路径
-> 梯形/三角形时序参考
-> 位置/速度反馈
-> SO(3) 姿态跟踪
-> wrench/旋翼推力分配
-> Isaac set_thrust_target()
```

这一设计属于标准几何轨迹跟踪基础设施，不是本文创新。此前有效证据为 40 秒四机运行中 20/20 航段完成、总路程约 `16.052 m`、峰值约 `1.171 m/s`、零碰撞；新增 v4 P0 证据为 `00626` 的 `32/32` 和 `00803` 的 `28/28` 航段完成，且均无碰撞、越界或失败片段。因此低覆盖的当前主因不是已证实的控制器速度故障，也不能因为后续改用官方控制器就把这些控制和吞吐证据全部作废。

v6 仍需持续记录、但不再作为继续调参的开放门槛的问题如下：

- v4 已覆盖中间 waypoint settle，`00626/00803` 证明事件驱动的转弯执行可以完成；长走廊和复杂垂直转弯只在后续场景分层中作为回归覆盖，不再以“缺少转弯证据”否定现有 P0；
- 每个正式执行结果仍需记录实际 PhysX 轨迹最小机间距离、跟踪误差和加速度/倾角饱和；
- 注释中的增益说明、`controller_profile_hash`、时序模型 hash 和实际参数必须一致，任何改变均创建新的执行数据域。

#### Lee、Mellinger 与 v6 的客观边界

Lee 的优势是作者来源明确、几何控制结构成熟、固件代码可追溯，正确部署后更容易回答“为什么使用这一控制器”和“能否衔接真实 Crazyflie”。它的风险是对状态坐标、角速度表达、质量/惯量、推力单位、旋翼混控和饱和行为非常敏感；只迁移 `controller_lee.c` 的决策核心而复用 Isaac 旋翼分配，不能自动获得原固件完整控制栈的等价性。

v6 的优势是已经按当前 CF2X USD、Isaac 状态接口、逐旋翼推力边界和安全守卫完成真实回归；当前证据中它比旧的无约束 Lee 端口更适合立即执行 P0。它的风险是外部来源说服力较弱，审稿人会追问自行实现、参数选择和是否针对本文方法调优。因此只能把 v6 写成所有方法共享的标准执行基础设施，不能写成控制创新，也不能通过探索方法的胜负选择控制器。

Mellinger 的优势是其决策核心、控制频率和 legacy mixer 均可追溯至 Bitcraze `controller_mellinger.c`；项目已冻结该 C 源码输出金样，再把 PWM/RPM 接口按 Isaac CF2X 悬停推力平衡映射到现有旋翼边界。它不是“未改动官方整套飞控”：坐标、PhysX 步长、质量和逐旋翼执行边界仍是受控适配层，论文中只能称为 `Bitcraze Mellinger decision-core Isaac adaptation`。在 `00626`、相同起点、`frontier_3d`、8 个候选和 40 秒物理预算下，Mellinger 完成 `40/40` 航段、零碰撞/越界/静态净空违规，最小实际净空 `0.461 m`；当前 v6 运行完成 `28/28` 航段、同样零安全失败，最小净空 `0.395 m`。两次 bootstrap 后的首轮候选池已不同，且 Mellinger 的墙钟为 `281.86 s`、v6 为 `167.33 s`，因此这不是可用于宣布 Mellinger 覆盖更高的高层方法比较，也不能按覆盖率选择控制器。它只证明两者在该开发运行中均具执行资格，而 Mellinger 当前约多 `68%` 墙钟成本。证据位于 `E:/asset/hm3d_cf2x_controller_qualification_20260805/`。

当前 A/B 支持以下结论：v6 在相同合法起点下零接触并完成收据；旧 Lee 端口的垂直 A/B 达到 `13.9867 N` 最大接触，混合收据 A/B 出现碰撞、三机 transit timeout、净空违规和约 `108.8 m/s²` 峰值加速度。guarded-v4 已修正共享反馈加速度与倾角合同，在 `00626` 的短垂直路线通过，但在与 v6 相同的合法混合路线中 `uav0/uav2` 均 `transit_timeout`，最高加速度 `5.543 m/s²`、最高速度 `1.495 m/s`；v6 在该路线四机完成、零碰撞、零净空违规，最高加速度 `1.553 m/s²`、最小净空 `0.389 m`。证据路径为 `E:/asset/hm3d_cf2x_controller_qualification_20260805/`。它证明**当前 guarded Lee 桥接不合格**，不证明 Lee 控制律本身不如 v6 或不适合原 Crazyflie 固件栈。

#### 有边界的 Lee 等价适配

控制器工作不再无限临时修补，已给官方来源控制器与 v6 相同的一轮接口等价核验和一轮纠正复测：

1. 冻结 Bitcraze `controller_lee.c` 来源为 `crazyflie-firmware` 提交 `5d287434b21b9b4fd3577c51e4d90bb4c54a5145`，保存原 C 决策输出黄金样例；
2. 逐项核对 Isaac 与固件的世界/机体系、四元数顺序、角速度坐标、重力方向、质量、惯量、控制周期和位置/速度/加速度/yaw 参考语义；
3. 核对 Lee wrench 到 CF2X 四旋翼推力的轴顺序、符号、单位、混控矩阵、推力上下限和饱和反馈；任何偏离官方逻辑的稳定化改动必须产生新的适配器身份，不能仍称未修改官方控制器；
4. 核对积分状态的 episode/reset 边界和饱和期间行为，禁止跨回合残留；
5. 依次运行悬停、正负三轴短位移、纯垂直、偏航、混合四机路线、非共线 waypoint 和长走廊路线；不得使用探索覆盖率或本文方法排名调参；
6. 使用同一 CF2X USD、起点、路线、物理步长、到达判据、净空、旋翼限制和随机种子与 v6 配对。

若第一轮发现明确的接口或单位错误，只允许一次纠正后复测。guarded-v4 已用完此机会且仍未通过混合路线，因此不再凭探索结果搜索 Lee 增益。这样既避免因一次端口错误否定官方方法，也避免控制器继续成为无限期门槛。

#### 资格与冻结方案

两种控制器使用同一套预注册硬标准：

```text
零碰撞和零静态净空违规
所有测试航段完成且无未解释 timeout
实际机间距满足冻结下限
跟踪误差不突破规划使用的 tracking envelope
推力、倾角、速度和加速度无异常尖峰
重复路线结果稳定
事件驱动执行和墙钟吞吐可接受
```

在满足全部安全硬标准后，再用完成时间、RMS/P95 跟踪误差、能耗和吞吐做非劣比较。控制器选择不得依据哪个让 QD/RL 获得更高覆盖率。

执行规则为：

1. P0、300 决策工程先导、后续 replay 和正式评测统一使用已验证 v6；每条执行结果写入控制器 ID、代码哈希、参数哈希和执行 profile 哈希。
2. Mellinger 仅作为冻结策略后的独立控制器鲁棒性复测。它的校准、执行结果和 QD 描述符属于独立兼容域，不能与 v6 replay、QD 档案或 OGFR 片段混合，也不能根据某个高层方法的覆盖结果挑选有利控制器。
3. guarded-v4 不得进入 replay、QD 档案、OGFR 片段库、训练、开发集或正式主表；其执行结果只保留为控制器适配审计证据。
4. 所有 random、规划、RL、QD、OGFR 和外部基线共享 v6、相同旋翼限制、相同轨迹守卫和同一 controller-profile hash。
5. 结论写成“官方 Lee 决策核心的当前 Isaac 受控迁移未通过共同执行合同”；Mellinger 则写成“已通过当前受控适配资格，尚未替代生产执行器”，不能把任一表述扩大为原控制律优劣。
6. 控制器冻结后不得在 train/dev/holdout 之间改变。任何后续控制器变更均使用新身份、新 timing profile 和新训练数据兼容域，不能回填旧结果。

A/B 至少报告：

```text
segment completion rate
RMS / P95 / maximum tracking error
actual speed and acceleration
collision and guard outcomes
actual minimum inter-UAV separation
energy / rotor-thrust integral
simulation wall-clock throughput
planner/baseline ranking stability
```

若最终需要报告控制器敏感性，只能使用冻结后的配对配置。若不同合格控制器改变方法排名，必须报告敏感性并缩小高层结论；不能只展示有利版本。

#### 论文声称

论文创新继续限定为 realised-QD、执行结果感知候选选择、OGFR 和四机无目标探索证据。控制器只作为冻结共享基础设施，方法章节只需说明来源、接口和验证，不做控制器消融，不声称新飞控贡献。这样不会稀释创新点，也能消除“主方法因为使用了特殊控制器而获利”的混淆。

## 4. 分阶段执行结果采集与停止规则

### 4.1 不一次盲跑 5000 决策

使用冻结里程碑：

| 累计真实决策 | 目的 | 必查内容 | 允许动作 |
|---:|---|---|---|
| 300 | 数据与行为 smoke | schema、hash、候选多样性、四机利用率、策略差异、崩溃率 | 修采集器和明显合同错误 |
| 1000 | 初始学习信号 | 固定开发集曲线、Q 值、熵、QD 占格、planned-realised gap | 淘汰明显无信号配置，冻结下一阶段候选 |
| 3000 | 投资判断 | 配对 AUC、random/规划基线差值、成本约束、跨场景稳定性 | 决定是否扩到 5000 或增加预算 |
| 5000 | 候选正式预算 | 收敛趋势、训练种子方差、样本效率 | 只有曲线平台或预算结论明确后进入主表训练 |

`5000` 不是文献保证的充分样本数。若 5000 时开发曲线仍明显上升，只能得出“共同 5000 决策预算下的样本效率”，不能声称外部基线已经充分训练。

### 4.2 不因早期输给 random 立即宣判失败

暂停或淘汰需要同时满足：

- 固定开发集上的配对差值在连续检查点下降或稳定为负；
- 置信区间上界仍低于由重复执行噪声确定的最小实际差异；
- 不是由训练未启动、归一化错误、动作未采样或候选无差异造成；
- 至少覆盖预注册的训练种子。

测试集不能参与检查点选择、早停、阈值和超参数决策。

### 4.3 数据兼容性

分母、特征 schema、奖励定义、控制合同或候选语义变化时，旧执行结果不能无条件混入新 replay。每条 transition 至少绑定：

```text
feature_schema_sha256
reward_schema_sha256
denominator_sha256
candidate_generator_sha256
execution_profile_sha256
candidate_pool_schema_version
task_reservation_schema_version
public_context_hash
public_candidate_pool_hash
selected_manifest_hash
next_public_context_hash
next_public_candidate_pool_hash
outcome_hash
policy_version
source_outcome_sha256
transition_sha256
```

`candidate_pool_schema_version` 必须为 `hm3d-public-candidate-pool-v7`，`task_reservation_schema_version` 必须为 `hm3d-public-task-reservation-v1`，且与顶层 P07 outcome 完全一致。可离线重评分的旧数据只能生成新的覆盖诊断；候选语义为 v5 的记录不能生成 v7 训练 transition，也不能因重算覆盖而恢复正式 P07/QD 资格。不可重评分的数据只保留为诊断。

## 5. 正式 QD+RL 训练闭环

### 5.1 总体结构

```text
共享探索预热
-> 在线/离线混合的 off-policy SAC
-> QD 档案达到可靠度后启用 realised-QD 选择
-> SAC+QD 稳定后启用 OGFR
```

循环 RL 和复杂离线 RL 不是第一阶段前置条件。优先修复当前最影响可信度的六项：

1. 共享而充分的状态/候选编码；
2. bounded replay 和随机 minibatch；
3. 在线交替采集与更新；
4. 训练时策略采样、评测时 argmax；
5. 正确的时间折扣与终止语义；
6. 公平的数据、调参和预训练账本。

#### 文献训练量级只作参照

已核对的相关工作明显不是用几十条转移完成正式训练：

- MARL-IPP 论文配置报告约 12 万次环境交互、36 个并行环境、单回合最多 256 步、batch 1024 和 8 个 PPO epoch；公开提交当前默认却是 batch 64、4 个并行 meta-agent，因此论文配置和仓库默认必须分开复现；
- IR2 使用 SAC、32 个并行环境和两阶段课程，两个阶段约为 6000 与 7500 个 episode；
- MARVEL 报告 5663 张生成地图、容量 10000 的 replay 和 batch 256。

这些环境比 HM3D + Isaac + CF2X 高保真链便宜，动作粒度也不同，不能把其 episode 数直接移植为本项目预算。它们能支持的唯一结论是：当前 `40` 条转移、`2` 张场景和全批 `64` 次重复更新只够验证接口，`5000` 是否足够必须由本项目学习曲线回答。

### 5.2 共享探索预热

建议先用训练 split 上的行为混合产生 `500-1000` 个真实决策作为候选预热量：

```text
random legal candidate
+ frontier_3d
+ gain-cost assignment
```

该数值只是进入 300/1000 检查点的候选范围，最终由开发集的数据覆盖率冻结，不是论文常数。

预热必须覆盖：

- 单层/多层；
- 小/中/大；
- 不同活动无人机数；
- 垂直低/高；
- 低/高观测重叠；
- 低/高通信风险；
- 常见合法候选位置，而不是只覆盖贪心最优动作。

内部 SAC/QD/OGFR 消融使用同一份初始预热数据。外部 on-policy PPO 不能把这份任意旧日志当作 PPO rollout。

### 5.3 在线交替采集与 replay

当前训练器把全静态数据集重复训练 64 次，正式闭环改为：

```text
collect N real decisions
-> append to bounded replay
-> sample minibatches
-> perform UTD updates
-> repeat
```

初始候选参数：

- minibatch：`128` 或 `256`；
- update-to-data ratio：`1 / 2 / 4`；
- replay capacity：当前 5000 决策阶段至少能容纳全部正式有效转移；更长训练时再冻结 FIFO 容量；
- warm-up：达到至少若干完整 minibatch，并覆盖全部训练场景层后开始更新。

这些是开发集搜索空间，不是预先认定的最优值。

抽样采用两级策略：

```text
uniform sample scene/stratum
-> sample episode
-> sample transition
```

这样避免短动作多、候选多的小场景垄断 batch。若训练目标是场景均值，该抽样与正式统计单位一致；必须记录抽样权重，必要时在损失中校正。

当前通用 `ReplayBuffer` 可以复用，但要补：

- 场景/episode 索引；
- 持久化 items、cursor 和 RNG；
- schema 兼容检查；
- 原子 checkpoint；
- 数据来源和策略版本。

优先经验回放可以后置，不能先于均匀场景抽样和基本在线闭环。

### 5.4 训练采样与评测选择

训练采集：

```text
action ~ categorical(masked_policy_probabilities)
```

正式评测：

```text
action = argmax(masked_policy_probabilities)
```

每条转移记录：

```text
behavior_policy_version
selected_action_probability
policy_entropy
legal_action_count
```

SAC 是 off-policy，不要求 PPO 式 ratio；这些字段用于检查分布漂移和错误的确定性采集。

### 5.5 状态与候选编码

当前 `4 + 5` 维输入只能作为弱基线接口。正式普通 SAC 与完整方法共享一个基础编码器，避免完整方法仅因输入更多获胜。

公共状态建议由小型 DeepSets 或 attention 集合编码器组成：

```text
全局：
剩余物理预算
当前公共覆盖进度和近期增长率
前沿数量、大小和相对高度分布
公共通信图摘要

逐机集合：
位置/相对高度
剩余能量
通信度和最近投递状态
当前任务/hold 原因
最近执行持续时间和完成状态

历史：
最近 2-4 次真实执行结果的覆盖增量、重复观测、能耗、断联、守卫和控制截断
```

团队候选编码：

```text
每机路径时间/长度/垂直位移
目标前沿簇与预计可见未知体积
每机合法性和角色
团队预计观测重叠
最小机间距和路径冲突
通信风险
活动无人机数
计划持续时间
```

要求：

- 不读取楼层真值、房间号、目标坐标或完整评测几何；
- 连续量只用训练 split 统计归一化，开发/测试冻结；
- 普通 SAC、no-QD、planned-QD、realised-QD 和 OGFR 共享基础编码器与参数规模；
- 外部 MARL-IPP 保留作者网络，不强迫与本方法同结构。

### 5.6 奖励、成本与真实时间

保留决策级真实执行结果，不退回整回合最终奖励反向分摊。

主奖励可以继续使用每段对冻结覆盖 AUC 的可加贡献，但需要明确：

- 分母必须是新 reachable denominator；
- 若奖励使用训练场景的评测几何，它是 train-only simulator reward，不是策略输入；
- 所有学习方法获得相同奖励定义；
- 测试场景奖励不用于训练、调参或档案预热。

成本至少分开记录：

- 能耗；
- 碰撞/近碰；
- 守卫拒绝；
- 通信失败/过期；
- 重复观测。

能量等量纲不能直接与 `[0,1]` 奖励混用，使用训练 split 冻结尺度或明确物理约束阈值。

对正安全成本，策略和目标中的保守估计应使用：

```text
max(cost_q1, cost_q2)
```

或经过开发集校准的上置信界，而不是当前的 `min`。修改后必须单独验证不会因过度保守导致全部 hold。

### 5.7 `terminated` 与 `truncated`

transition schema 拆分为：

```text
terminated
truncated
bootstrap_allowed
termination_reason
```

语义：

- `terminated=true`：任务/环境真正终止；
- `truncated=true`：采集器、smoke 时间、基础设施或更短日志窗口截断；
- 40 秒日志若服务于 240 秒策略训练，必须是 truncated，并在有合法 next state 时 bootstrap；
- 正式有限时域本身可以是 MDP 终点，但剩余时间必须进入状态；
- 基础设施崩溃不能伪装成正常任务终止。

这与时间限制强化学习中区分环境终止和外部时间截断的处理一致。

### 5.8 固定离线 SAC 的风险

若继续在固定日志上用普通 SAC，critic 会给数据中很少执行过的候选估计 Q 值，容易出现离线分布外高估。优先方案是恢复在线交替采集。

只有在高保真交互无法继续增加、必须长期固定数据集时，才考虑 CQL 等保守离线 RL，并为普通 SAC 与 CQL 单独做开发比较。CQL 不是当前 P0 的必需模块。

### 5.9 历史执行结果：快速路线与完整循环路线

时间优先时先实现固定窗口：

```text
last 2-4 outcome features -> feed-forward encoder
```

此时论文只能声称“使用有限历史执行结果”，不能声称 recurrent policy。

只有开发消融证明更长历史有独立价值时，再实现：

- GRU/LSTM；
- sequence replay；
- burn-in；
- truncated BPTT；
- episode/agent reset mask；
- 隐状态 checkpoint；
- 隐状态恢复黄金测试。

不能为了一个尚未证明必要的循环模块继续推迟大实验。

### 5.10 realised-QD 与策略的马尔可夫性

QD 档案不应把已经离开当前候选池的旧 manifest 当作可直接重放动作。档案保存：

```text
behavior cell statistics
behavior prototype
realised return distribution
planned-to-realised mapping error
candidate-conditioned quality estimate
source provenance
```

每轮把当前合法候选映射到预计 realised 行为格，再由档案修正当前候选评分。最终执行的永远是本轮合法候选。

如果 QD 档案在训练中持续变化，则整体策略状态也在变化。必须选择一种可重现方案：

1. 把档案摘要、版本和 hash 纳入状态/transition，并能重建；或
2. 分阶段冻结档案，再训练固定档案下的策略。

不能让 replay 中相同表面状态在不同隐藏档案下对应不同策略，却不给模型和训练器任何档案身份。

测试时：

- 可以加载训练 split 冻结档案；
- 若方法合同允许，可在单个测试 episode 内更新；
- 不允许把前一张测试图的执行结果带入后一张测试图；
- 所有档案更新规则在看 holdout 前冻结。

QD 改选阈值不手填。用训练/开发集相同或近似动作的重复执行估计执行结果噪声，只有预期改善超过噪声区间和切换代价时才改选。

#### QD 丰富性不是留到最后再处理

当前实现已经不是早期“固定三个数、看档案是否非空”的版本。活跃代码 [`hm3d_realised_qd.py`](../src/aerocity_method/runtime/hm3d_realised_qd.py) 当前包含：

- `hm3d-outcome-grounded-qd-v5` 执行结果 schema；
- 五个仅由执行后公共证据计算的诊断特征：垂直运动、公共垂直观察跨度、团队空间分散、各机独有贡献均衡、公共观察互补性；
- 四组预注册三轴描述符族，训练阶段可以证伪当前默认族，而不是事后挑最好看的轴；
- 当前部署族 `v4_motion_dispersion_complementarity`；
- 最少 `12` 条执行结果、`6` 个联合格、Shannon 有效格不少于 `4`、轴绝对相关不高于 `0.90`、相关矩阵行列式不少于 `0.10` 的丰富性底线；
- 候选意图丰富性、planned-realised 对齐、公共探索需求和选择器 abstain 审计。

因此待解决的不是“有没有写丰富性代码”，而是以下两层证据尚未闭合：

1. 候选生成层必须主动提供不同协作模式：水平/垂直、紧凑/分散、重叠/互补、1-4 架活动机、探索/真实中继。若候选池不提供这些模式，档案不可能凭空创造多样性；
2. `MINIMUM_QD_NEED_ALIGNMENT_IMPROVEMENT` 和 `MINIMUM_QD_NEED_REALISATION_FIDELITY_RATE` 当前仍为 `0.0`，只能证明代码路径被触发，不能证明干预具有实质意义。它们必须由 train/dev 重复执行结果的噪声分布冻结。

QD 资格审查在至少两个差异训练场景、足够真实执行结果后执行，且只检查三件决定性事实：

| 问题 | 最低证据 | 裁决 |
|---|---|---|
| 计划与实际是否有稳定实质差异 | planned-realised 距离超过重复执行噪声，并在多个场景/模式出现 | 否则 realised-QD 没有必要性 |
| 行为轴是否非退化、非共线 | 通过联合占格、有效格、方差、相关和行列式审计 | 否则更换预注册族或降为诊断 |
| 档案是否改变选择且不明显牺牲质量 | 有非零且可重复的改选率，改选后的 realised quality/AUC 不低于价值保护阈值 | 否则 QD 不进入主方法 |

不能“确保 QD 一定有效”。可以确保的是：候选池提供可辨别模式、档案真实进入决策、统计检验有足够机会发现作用、无效时不让它拖住论文。只有上述三项成立，才运行 `planned_qd` 对 `realised_qd` 的正式配对；不成立则把 QD 降为行为诊断，主方法退回无 QD 的增强 SAC。

### 5.11 OGFR

正式消融：

```text
no reuse
ungated reuse
outcome-gated reuse
```

所有复用片段必须在目标状态重新规划、重新执行并产生新执行结果，不能复制旧奖励。

公平预算要求：

- 片段的来源交互计入训练数据预算；
- no-OGFR 对照获得相同原始 transition 数据；
- OGFR 只增加结构化检索/建议机制，不免费增加额外环境标签；
- 外部片段库若存在，单列为预训练先验，不能混入 matched-budget 主结论。

## 6. 学习型基线的公平训练预算

### 6.1 核心结论

> 学习型基线必须与主方法保持相同的环境交互上限、训练场景分布、基础观测权限、调参机会和训练种子要求；不需要强制使用相同梯度更新数、batch 或算法超参数。

强行让 PPO 与 SAC 使用相同更新次数并不公平，因为二者的数据复用和 on-policy/off-policy 语义不同。公平的主单位是环境机会，而不是优化器调用次数。

### 6.2 四本预算账

每个学习方法单独记录：

1. 环境交互账：场景、起点、episode 物理秒、physics steps、真实决策数；
2. 优化账：梯度更新数、batch、UTD/PPO epoch、GPU 时长；
3. 调参账：超参数组合数、开发评测次数、训练种子；
4. 先验账：作者预训练、外部数据、片段库和源码检查点。

matched-budget 的主键：

```text
(scene_id, start_seed, episode_physics_budget_s, execution_profile_sha256)
```

所有学习方法获得相同数量的训练 episode 和累计物理秒/physics steps。事件驱动方法在相同物理时间内可能产生不同决策数，这是算法行为，必须报告而不是强行抹平。

### 6.3 方法分类

| 方法 | 训练预算合同 | 不能做的事 |
|---|---|---|
| random、frontier、gain-cost、GVP 规划 | 不训练；统一评测场景、起点、种子、物理预算和执行器 | 不把“无训练成本”解释为可以使用额外真值 |
| vanilla SAC、single_rl、no/planned/realised-QD、OGFR 消融 | 相同训练 split、初始预热数据、累计真实交互、基础编码器、调参次数和训练种子 | 不给完整方法更多状态或更多原始数据 |
| MARL-IPP PPO 迁移 | 相同 HM3D 物理交互上限，但保留 on-policy rollout、PPO epoch、LSTM 和作者算法超参数 | 不把任意旧 replay 混入 PPO 并仍称作者训练 |
| 作者公开预训练检查点 | 单列“预训练迁移” | 不与从零 matched-budget 样本效率混为一行 |
| 未在共同预算内收敛的外部基线 | 增加 author/converged-budget 结果，或降为 prototype | 不声称已经充分训练并被击败 |

基础编码器相同只适用于本文内部 SAC/QD/OGFR 消融。外部基线应保留作者架构，否则公平接口会把算法核心抹掉。

### 6.4 双预算报告

主表建议同时给出：

1. `matched budget`：相同 HM3D 训练交互与调参机会，回答样本效率和共同预算下性能；
2. `author/converged budget`：作者设置或开发集平台期，回答外部基线是否因共同预算过小被压制。

如果 MARL-IPP 在 5000 决策时仍持续上升，合法结论是：

> 在共同的 5000 决策/对应物理交互预算下，本方法样本效率更高。

不能写成：

> 本方法全面优于已经充分训练的 MARL-IPP。

### 6.5 调参公平

每种学习方法应获得相同的：

- 超参数 trial 数；
- 开发场景；
- 训练种子数；
- 早停检查次数；
- 人工干预规则。

算法内部超参数空间可以不同，但 trial 总量和开发信息量应匹配。不能给主方法试 20 组，只给基线一个未经 HM3D 适配的默认值。

至少训练 3 个独立模型种子。只固定一个模型、改变 3 个评测种子不能反映 RL 训练方差。

### 6.6 MARL-IPP 在 1000 张 HM3D 资产上重训的成本

本机为 RTX 4090 24 GB、i7-12700 12 核/20 线程、31.7 GiB 内存。MARL-IPP 的 60 万参数 AttentionNet 不是主要瓶颈；主要成本是 HM3D 几何、稀疏射线、公共地图、候选图、PhysX 和执行结果生成。

“训练集有 1000 张场景”必须区分资产总体和高保真交互次数。HM3D 约 1000 个资产可以作为筛选总体，但不意味着每个模型种子都必须在每张资产上运行完整 Isaac episode。

按当前有效历史吞吐，40 秒、8 决策 episode 的墙钟均值约为 `162.65 s`：

| 工作量 | 串行旧链估算 | 旧双集群 `1.5-1.95x` 估算 | 含义 |
|---|---:|---:|---|
| 1000 张场景各跑 1 个 40 秒 episode | `45.2 h` | `23.2-30.1 h` | 只有一遍资产覆盖，不等于收敛 |
| 上述资产遍历做 3 个训练种子 | `135.5 h` | `69.5-90.4 h` | 仍未计 PPO 重采样、评测和失败重跑 |
| 1000 张场景各跑 1 个 240 秒 episode | `150-267 h` | 尚无可信实测 | 依据旧 `9-16 min/episode` 外推，不可作为承诺 |

MARL-IPP 论文约 12 万环境交互不能直接换算到本项目，因为论文中的 interaction 可能按单机器人动作、并行环境步或团队时刻计数，而本文一条团队决策同时包含四机动作。若粗略按当前 `8` 个团队决策/40 秒 episode 换算：

- 12 万个团队决策约需 `15,000` 个 episode，旧链串行约 `28.2 天`；
- 若 12 万指单机动作，乐观按四机折成 3 万个团队决策，串行仍约 `7.1 天`；
- 双集群只能按 P0 后实测吞吐缩短，不能把理想并行度当结果。

因此不采用“1000 张 HM3D 全量高保真、从零复现论文交互量”的方案。可行路线是：

1. 在作者廉价环境恢复原论文趋势和 PPO/LSTM 黄金行为；
2. 1000 个 HM3D 资产只作确定性筛选总体；
3. 约 60 张合格 train 场景承担高保真受控迁移，12-18 张 dev、24-36 张 holdout；
4. 以 matched-budget 的 1000/3000/5000 团队决策检查点训练；
5. 若 5000 时 MARL-IPP 仍上升，另给 author/converged-budget 曲线，不把少训结果包装成最终能力。

P0 后必须用至少 20 个完整代表 episode 重测 P50/P90、失败率、显存/内存峰值和双集群加速比，再替换本节旧链估算。

### 6.7 消融训练总量与本机工期

消融不能做完整笛卡尔积。最低独立训练族按共享锚点合并为：

```text
vanilla SAC
duration/cost SAC
enhanced SAC without QD
planned-QD
realised-QD without OGFR
realised-QD + ungated OGFR
realised-QD + outcome-gated OGFR
```

外部 MARL-IPP PPO 是第八个独立训练族。OGFR 若只在冻结策略评测时开关且不改变采集分布，可以复用检查点；只要它改变动作、replay 或信用分配，就必须独立在线分支。

内部 off-policy 方法可以共享相同的初始 random/frontier/gain-cost 预热执行结果和归一化统计，但正式在线闭环不能全部复用同一条后续轨迹。QD 或 OGFR 一旦改变选择，策略访问的数据分布也随之改变；公平做法是共享预热、随后给每个分支相同新增交互上限。MARL-IPP 必须独立采集 on-policy rollout。

若每个独立训练运行都使用 5000 个团队决策，当前旧链单运行约 `28.2 h` 串行：

| 矩阵 | 训练运行数 | 串行数据收集 | 旧双集群估算 | 解释 |
|---|---:|---:|---:|---|
| 最小生存矩阵：普通 SAC、增强无 QD、realised-QD、完整 OGFR、MARL-IPP，各 3 种子 | 15 | `423.6 h` | `217-282 h` | 约 `9-12` 天纯采集 |
| 完整相邻消融 7 个内部族 + MARL-IPP，各 3 种子 | 24 | `677.7 h` | `348-452 h` | 约 `14.5-18.8` 天纯采集 |

这些数字尚未加入 240 秒正式评测、GVP 原环境回归、失败重跑和调参，但也没有计入事件驱动调度可能带来的提速。GPU 梯度更新预计不是主成本，仍需实际记录 GPU 小时，不能未经验证忽略。

控制总工期的方法不是少训基线，而是阶段淘汰：

- `300`：只查 schema、候选和实现错误；
- `1000`：淘汰 QD 不丰富、MARL 语义不对齐和明显不学习的配置；
- `3000`：保留能超过 random/透明规划器且曲线健康的分支；
- `5000+`：只给正式候选和仍未平台但有合理上升趋势的外部基线。

按现有证据，P0 后的现实总工期仍应按 `2-3 周`规划，而不是承诺所有模块 8 天内完成；P0 之前继续外推没有意义。

## 7. GVP-MREP 资格路线

### 7.0 立即使用的无学习透明强规划器

正式训练不能等待 GVP 完整迁移，因此先实现并冻结一个可解释的层次化规划器：

```text
public sparse belief
-> 3D frontier clusters
-> multiple collision-free viewpoints per cluster
-> graph/A* path in known free flight space
-> exact four-agent assignment with overlap/conflict/connectivity cost
-> several diverse joint plans
-> CF2X execution and event-driven replanning
```

它不读取评测器真值、楼层号或完整 HM3D 网格，只能使用与本文方法相同的成功投递公共观测。四机规模允许对每机前 `K` 个观察位点做精确小规模组合搜索，或用 Hungarian/min-cost flow 生成初解后做路径冲突修正，不需要用不透明的大型学习模型。

该规划器是论文中的透明强锚点，不冒充 FUEL、RACER 或 GVP。FUEL 提供前沿层次结构和高频重规划的设计依据；RACER/GVP 提供多机协作与拓扑分配的设计依据；实现、名称和结果均属于本文公共接口下的透明规划基线。

最低资格不是“能返回一个 candidate”，而是：

- 在单层复杂图产生跨房间/走廊路径；
- 在合格多层图产生并执行通向垂直通道的路线；
- 有四个互不冲突任务时，至少存在一个四机活动联合方案；
- 与 random、单位时间 frontier 和 gain-cost 在目标、路径或轨迹足迹上稳定不同；
- 决策延迟 P95 小于动作的最小有效持续时间，不因规划计算重新制造空闲等待。

### 7.4 GVP 论文、仓库与原始证据

GVP-MREP 全名为 *Fast and Communication-Efficient Multi-UAV Exploration Via Voronoi Partition on Dynamic Topological Graph*，发表于 IROS 2024，DOI `10.1109/IROS58592.2024.10801613`，官方仓库为 `https://github.com/NKU-MobFly-Robotics/GVP-MREP`，许可证为 MIT。

原方法不是一个孤立评分公式，而是一套分布式三维探索系统：

```text
local volumetric map
-> incremental MR-DTG
-> frontier/history nodes and reachable edges
-> topology-delta communication
-> graph Voronoi ownership
-> local/global job allocation with remaining work time
-> MINCO/GCOPTER trajectory
-> distributed replanning
```

作者在 Small/Large Maze 中与 RACER 比较 3、5、10 架无人机；Large Maze 为约 `40 x 40 x 3 m^3`，最长 300 秒。论文报告 GVP 探索时间相对 RACER 缩短约 `18.3%-38.3%`，通信量减少约 `93.5%-95.6%`。真实实验使用 6 架无人机，在约 `40 x 24 x 3 m^3` 户外灌木场地中约 `67.2 s` 探索大部分空间，总通信量 `14.47 MB`。

这证明它是有真实多机系统证据的无目标三维探索方法，但原场景高度只有约 3 米，不能据此声称它原生解决了 HM3D 多楼层室内跨层探索。

仓库中可直接复用的算法核心包括：MR-DTG 数据结构、frontier/history 状态、Graph Voronoi、job 与剩余时间、局部/全局任务切换、失效 viewpoint 删除及增益公式。不能原样带入公平 HM3D 主表的是 RotorS/Gazebo、作者体积地图、maze/city 场景、MINCO 执行结果和 ROS 网络行为；这些层由共同的 HM3D 观测、CF2X/PhysX 和通信合同替换。

### 7.5 为什么仍选 GVP，而不是其他规划论文

增量检索与本地仓库审计后的排序如下：

| 排名 | 方法 | 适合点 | 不适合点 | 裁决 |
|---:|---|---|---|---|
| 1 | GVP-MREP, IROS 2024 | 多 UAV、未知三维、无目标覆盖、有限通信、实飞、MIT 完整仓库 | ROS 栈重；当前端口只保留部分公式；原场景非多楼层 | 外部规划主候选，训练期间补齐 |
| 2 | RACER, T-RO 2023 | 成熟多 UAV 三维协作、异步通信、实飞 | 更重的旧 ROS/规划栈；本地有 Python 2 遗留；GVP 原论文已直接比较 | GVP 原环境回归参考，不作为当前第一迁移线 |
| 3 | C2-Explorer | 三维低层轨迹、协同分配和连通性 | 作者高层管理器存在单层 grid 与 `dz=0` 路径证据 | 多层 HM3D 主表风险高，作为备选/参考 |
| 4 | Distributed Frontier + NBV, Drones 2024 | 正式期刊、三维 LiDAR、多 UAV、无 RL | 最多三机；未找到可核验完整作者仓库 | 方法参考，不能承担源码强基线 |
| 5 | FUEL, RA-L 2021 | 三维前沿、全局访问和局部轨迹结构成熟、开源 | 主要是单机，缺多机通信与分配 | 用于透明规划器结构，不冒充完整复现 |

当前没有检索到同时满足“原生 HM3D、连续三维无人机、多机、无目标覆盖、非 RL、正式发表、完整开源”的方法。HM3D 同数据集上的 PointNav/ObjectNav 多为地面离散目标导航，任务迁移比 GVP 更严重。同数据集不是最高公平性；共同观测、执行、预算和指标下保留同任务算法核心，才是更有意义的比较。

## 8. MARL-IPP 资格路线

### 8.0 外部 RL 候选的全面筛选结论

候选按“任务匹配、三维表达、多机协作、源码/检查点、迁移改变量、正式发表证据”排序，而不是只看期刊分区。SCI 分区会随年份和学科变化，RA-L、T-RO、T-IV、ICRA、IROS 的同行评审身份可以作为质量筛选，但不能替代代码与任务审计。

- 每架无人机独立候选图和动作；
- 与作者一致的 `x/y/z/朝向 + 本机信息/不确定性 + 邻机信息/不确定性` 语义；
- 每机跨决策维护 `h/c`，只在 episode 结束或机器人失效时清零；
- rollout 保存 old logp、value、next value、reward、done、`h/c` 和 mask；
- PPO ratio、`epsilon=0.2` clipping、8 epoch、batch、梯度裁剪和学习率衰减；
- 同一张量输入下与作者代码核对前向、LSTM、return、ratio、clip 和 loss。

动作和输入语义改变后，作者检查点能严格加载不等于预训练能力被保留。原则上 HM3D 迁移需要重新训练。

未通过黄金测试和开发收敛前，名称只能是：

> MARL-IPP AttentionNet controlled-transfer prototype

### 8.3 MARL-IPP 是否真的做过真实无人机

答案是肯定的，但实机任务规模和本文不同。论文明确报告：

- 真实平台为 4 架 Ryze Tello；
- 场地约 `7.62 x 3.25 x 2.4 m^3`；
- 放置随机障碍和 6 个 ArUco tags；
- 图 1 可见 4 架 Tello 与 3 个标签；
- 在线目标是发现静态目标并规划碰撞规避路径。

论文仿真使用 gym-PyBullet-drones 与 Houses3K，场景边界约 `60 x 60 x 30 m^3`，实验配置包含 3 架 UAV、最大速度 `1 m/s`、完美定位和 ground-truth target discovery，并展示扩展到最多 64 个机器人的策略推理。

这证明 MARL-IPP 不是只在抽象二维栅格上画曲线，也证明作者网络与 UAV 多机任务有关。但它不能直接证明本文迁移成功，因为原目标是“在资源预算内发现静态目标”，而本文目标是“在未知 HM3D 中最大化公共确认可飞自由体积”。此外，作者使用无噪声/真值目标发现，本文不能把目标坐标、房间标签或评测几何作为策略输入。

### 8.4 原方法与开源仓库具体做了什么

MARL-IPP 使用集中训练、分散执行。每架机器人在自身候选动作图上选择下一节点，网络通过三维位置、方向、本机信息收益/不确定性、邻机通信信息/不确定性、图邻接、预算和循环状态形成动作分布。执行后按新发现目标、探索知识和通信知识构造奖励，并用 on-policy PPO 更新共享策略。

其协调图与高斯过程服务于目标发现：本机 GP 估计自己执行动作的目标收益和不确定性，通信 GP 表达从其他机器人获得的信息。这里正是迁移风险最大的部分，不能把本文的团队终点中心、planned descriptor、quality 和 cost 填进同样 8 个槽位后就声称语义对齐。

官方仓库为 `https://github.com/AccGen99/marl_ipp`，MIT 许可证，当前冻结提交 `8d02dab751c647b69a2b4f666aa7bfca5c096dda`。本地审计结果包括：

- 19 个 Python 文件语法通过；
- 作者 `AttentionNet(8, 128)` 和官方 `best_model_checkpoint.pth` 严格加载；
- 参数量 `600,449`；
- batch 4、变节点图、动作 mask、三维 z 扰动、反向传播通过；
- 当前机器 CPU 前向约 `2.45 ms`，说明网络推理不是高保真训练瓶颈。

这些结果只证明作者神经核心可复用，不证明当前 `hm3d_marl_ipp.py` 已经恢复作者策略。当前端口清零 `h/c`、使用单步 actor-critic、选择完整团队候选，仍不具正式基线资格。

### 8.5 MARL-IPP 的论文级准入指标

MARL-IPP 进入主表前必须同时通过以下五类指标：

| 证据层 | 必须通过的指标 | 失败后的处理 |
|---|---|---|
| 来源 | 固定 Git SHA、许可证、作者检查点 hash、依赖 manifest | 来源不清则不发布结果 |
| 作者行为 | 同一张量下前向、LSTM、return、ratio、clip、loss 数值一致；恢复完整方法优于作者消融的方向 | 失败则为实现错误，不进主表 |
| HM3D 合法性 | 无额外真值；逐机图动作；合法动作率、episode 完成率、碰撞/失败率正常 | 失败则修迁移，不把差结果当基线结果 |
| 学习资格 | 至少 3 个训练种子；固定 dev 曲线达到平台或明确给出未收敛状态；matched 与 author/converged 预算齐全 | 少训只能报告样本效率，不能报告最终优越性 |
| 行为与性能 | 与 random/frontier/SAC 有稳定目标和轨迹差异；配对 AUC、final volume、路径、通信和失败分母齐全 | 若实现正确但任务上真实落后，可如实进入结果 |

“失败实验是否放进论文”的裁决取决于失败原因：算法在公平、正确、充分训练后失败，应该报告；端口错误、未收敛或预算不足导致失败，必须先修复或降级为 prototype，不能拿来衬托本文方法。

### 9.1 主表

在资格满足后，主表保留：

```text
random
+ 一个经典几何方法
+ 一个强规划迁移/透明强规划器
+ 普通 SAC
+ 合格外部学习迁移

```

random 必须覆盖全部正式测试场景、起点和种子。它是合法候选池上的随机选择，不是随机乱飞，因此可能很强。

完整方法平均打不过 random 时，核心选择机制失败。不能把 random 移到附录掩盖结果。

### 9.2 机制表

只做相邻比较：

```text
no_qd / planned_qd / realised_qd
vanilla_sac / duration_cost_sac / enhanced_sac
no_reuse / ungated_reuse / outcome_gated_reuse
```

每组只改变一个机制，其余候选、编码器、训练数据和交互预算一致。

### 9.3 系统级与选择器级分开

所有方法共享候选池时，主要证明的是选择机制，不足以声称完整探索系统全面优于原论文。

建议分两类证据：

- 系统级：保留外部规划方法自身决策核心，统一传感、CF2X 执行、物理预算和评测；
- 选择器级：在完全相同候选池上比较 random、gain-cost、SAC、QD+RL。

### 9.4 无人机数量合同

主表继续固定 4 架 CF2X，因为本文任务、当前有效执行证据和 MARL-IPP 真实实验都能支持四机。不能为了让某个基线更方便，把本文跑四机、基线跑三机后放在同一性能表。

外部方法处理规则：

- MARL-IPP 的共享参数网络原本支持可变机器人数量，HM3D matched-budget 仍训练/评测 4 机；
- GVP 原论文覆盖 3/5/10 机和真实 6 机，HM3D 主表适配为 4 机；
- 若方法只能固定数量且无法合理改造，则不具同表资格；
- 3/6/8 机只作为额外规模扩展，使用相同方法集合和独立预算，不替代四机主结果。

## 10. 场景、预算与评测合同

### 10.1 场景分层

先在官方 HM3D split 内做确定性合法性过滤，再按以下维度分层：

- 可达可飞体积/面积；
- 楼层和垂直连接机会；
- 连通分量结构；
- 房间/走廊拓扑复杂度；
- 通信困难度；
- QD 行为机会。

层内用确定性最大差异抽样，不能按“每层挑面积最大”或逐图选择有利场景。

目标规模可先按：

- 高保真训练约 60 张；
- 开发 12-18 张；
- 正式测试 24-36 张。

这是资产过滤前的规划范围，不是已经冻结的场景数。最终数量由可复现过滤结果决定。

QD 高/低机会是预注册的机制子层，不能替代代表性 holdout。

### 10.2 240 秒预算标定

240 秒仍是候选预算。开发集选择单层/多层、小/中/大代表图，单次最多跑到 600 秒，并每 60 秒保存检查点：

```text
coverage curve
first confirmed upper-storey observation
reachable height-band coverage
trajectory and active time
failure/communication state
```

根据开发场景的覆盖曲线拐点、首次上层确认时间分布和墙钟成本冻结正式预算。

不要求 240 秒完整探索场景，但要求在合格多层场景中能产生真实跨层差异。若所有方法 600 秒仍无法发现评测器确认可飞的上层，当前执行链不能支撑多层主张。

### 10.3 楼层评测器

仅评测器可见的楼层清单应由支撑面高度和水平连通性聚类得到，输出：

- `storey_id` 和高度/水平区域；
- transition 区域；
- 每架无人机首次进入时间；
- 停留时间；
- 每层新增可飞体积；
- 首次确认上层公共观测时间。

算法不能读取楼层号。进入上层至少要求：

```text
机体进入上层区域
+ 持续停留
+ 公共测距确认上层新增自由体积
```

只在楼梯井或挑空区升高不能算进入二楼。

### 10.4 指标与统计

同时报告绝对量和比例：

- 新增确认自由体积 `m^3`；
- `m^3/s`；
- 覆盖 AUC；
- 最终覆盖比例；
- 路径长度和活动时间；
- 能耗；
- 通信投递/过期/字节；
- 碰撞、守卫和失败；
- 首次跨层确认时间；
- 决策 P50/P95 延迟。

主统计单位是场景。相同场景、起点、预算和执行种子做配对比较：

- 每场景差值；
- 跨场景均值/中位数；
- 分层或层级 bootstrap 95% CI；
- 胜/负/平场景数；
- 训练种子和评测种子方差；
- 失败率。

不能只报告若干运行均值，也不能把同一场景的大量 episode 当成大量独立场景。

基础设施失败可以按预注册规则重跑；算法碰撞、超时和崩溃必须作为方法失败计入，不能静默删除。

### 10.5 `Explored-Free-Flight-Volume-AUC_time` 的确切含义

当前代码 [`hm3d_exploration_metrics.py`](../src/aerocity_method/evaluation/hm3d_exploration_metrics.py) 对覆盖曲线使用梯形积分，并除以冻结物理预算：

```text
C(t) = evaluator-confirmed explored reachable free-flight volume
       / frozen reachable free-flight volume

AUC_time = (1 / T) * integral_0^T C(t) dt
```

因此它是 `[0,1]` 的时间平均覆盖比例。若显示为 `1.5%`，含义是整个 episode 内的平均已确认覆盖约为可达可飞体积的 `1.5%`，不是“最终只覆盖 1.5%”也不是“每秒覆盖 1.5%”。同样最终覆盖达到 `2%`、但主要在最后才获得时，AUC 会显著低于 `2%`。

这个指标适合比较固定物理时间内的探索速度，但绝不能单独使用。正式结果必须同时给出：

```text
final explored m3
final coverage fraction
new m3/s
path length and active-flight fraction
energy
collisions/failures
communication
first confirmed upper-storey time
```

当前 `1.x%` 量级不能作为“HM3D 本来就难”的正常结果直接写论文。结合四机总路程、短路线、固定空闲等待和长期 hold，它首先说明规划/调度/分配链尚未把物理预算转化为探索推进。分母修复会提高比例，但不会消除绝对覆盖过低的问题。

### 10.6 为什么不能直接引用其他 HM3D 论文的百分比

HM3D 目前没有官方“四机 CF2X、连续 PhysX、稀疏测距、无目标自由飞行体积覆盖”benchmark。相邻论文的指标并不等价：

- PointNav/ObjectNav 报 Success、SPL、DTG，存在目标和地面 navmesh；
- ReCuriosity 在 HM3D 上做单 RGB 纯探索，报 `0.05 m` 阈值的表面重建覆盖完整度，回合 1024 个 Habitat 离散动作；
- MARL-IPP 报发现目标百分比；
- GVP/RACER 报完成探索时间和通信量；
- VisFly 证明 HM3D 可用于连续四旋翼平台，但没有同任务主表数值。

这些论文可以约束任务设计、训练规模和辅助指标，不能把其百分比与本项目 AUC 直接横排。本文必须用公开的场景筛选、几何转换、reachable denominator、起点、观测、执行和评测 artifact 建立自己的可复现 benchmark，并在完全同一 benchmark 内比较所有方法。

## 13. 风险登记与裁决

### 13.1 论文当前最大的生存风险

审稿人最可能据此直接否决，按严重程度排序：

1. **强基线身份不成立**：把清零 LSTM、单步 actor-critic 的端口写成 MARL-IPP，或把 94.1% 与 auction 同选的评分器写成 GVP；
2. **任务没有真正跑通**：所有方法 AUC 只有 `1.x%`、大量物理时间空闲等待、无人机不跨区域，却仍用相对排名声称探索有效；
3. **候选池决定全部上限**：RL/QD 只能在本文偏置的短路线中选择，优势来自候选工程而不是学习；
4. **QD 没有因果作用**：轴退化、planned-realised gap 不显著、档案不改选，或改选只牺牲质量；
5. **RL 没有超过最低下界**：完整方法平均不如 random、透明规划器或普通 SAC；
6. **自定义 benchmark 不可复现**：HM3D 到 Isaac 的几何、reachable denominator、场景筛选、起点、传感与失败分母不公开；
7. **训练公平性不足**：主方法得到更多数据、状态、调参和种子，外部基线少训后被宣布失败；
8. **机制堆叠无法归因**：SAC、SF、cost、history、QD、OGFR 同时变化，消融不能回答贡献来源；
9. **场景泛化不足或挑图**：只用少量 QD 高机会场景，或按方法得分选择 holdout；
10. **控制器混淆高层贡献**：使用自定义控制器却没有官方来源对照、跨方法共享和参数冻结，使性能差异无法归因于规划、QD 或 RL；
11. **工程不可复现**：单张 4090 需要数月高保真交互、断点不完整、运行入口依赖错误 Python 或未冻结脏工作树。

最小生存主张不是“完整系统全面超过所有已有方法”，而是：

> 在公开、冻结的 HM3D/CF2X 四机无目标探索合同下，真实执行结果能揭示计划行为与实际行为的系统差异；在相同候选和交互预算下，执行结果感知的高层选择是否比透明规划、random 和普通 SAC 更有效。

若 QD 三项资格不成立，就删除 QD 因果主张；若 RL 打不过 random/透明规划器，就不能投稿当前核心方法；若外部基线未合格，就只报告透明强规划器和内部公平对照，不能虚构胜利。

### 13.2 为什么相邻工作很多，但这一组合仍可能有贡献

别人没有“做出同一篇论文”不代表本文自然成立。现有工作分别覆盖了部分问题：

- HM3D 提供真实扫描室内资产，但主流 benchmark 是地面目标导航；
- ReCuriosity 做 HM3D 无目标探索，但为单 RGB/单机 Habitat 动作；
- VisFly 提供 HM3D 连续 UAV 平台，但没有同任务四机主结果；
- GVP/RACER 做多 UAV 无目标三维探索，但场景、地图、动力学和评测不是 HM3D 多楼层；
- MARL-IPP 做三维多 UAV 学习与实机目标发现，但奖励是静态目标映射；
- QD 文献证明行为库可维护多样解，但没有自动证明在高保真多机探索中有用。

本文潜在的新意是把以下证据闭环放在同一冻结任务中：

```text
real scanned multi-storey geometry
+ continuous CF2X/PhysX execution
+ sparse partially shared observations
+ target-free reachable free-volume evaluation
+ planned-to-realised behaviour discrepancy
+ outcome-grounded high-level repertoire/selection
```

但“组合没人做过”只是研究机会，不是论文贡献。只有 realised-QD 相对 planned-QD 有稳定收益、普通 SAC/透明规划器/random 被公平超过、跨场景和跨层证据成立，这一组合才有资格成为贡献；否则应收缩为 benchmark/系统审计或负结果论文。

| 风险 | 观测信号 | 裁决 |
|---|---|---|
| 所有方法覆盖都很低 | 绝对 `m^3`、活动时间、路线推进均低 | 先修候选/调度/预算，不能用相对排名掩盖任务没跑通 |
| 完整方法平均输 random | 配对 AUC/最终覆盖为负 | 核心选择机制失败，检查奖励、QD 干预、数据偏移和候选差异 |
| QD 不改变选择 | 改选率、档案读取和行为格影响接近零 | 删除或降级 QD 主张，不用档案占格包装贡献 |
| planned-realised gap 很小 | 计划和真实描述符长期一致 | realised-QD 的必要性不足 |
| QD 档案造成非平稳 | 相同表面状态随隐藏档案产生不同决策 | 把档案纳入状态或阶段冻结 |
| GVP 与 gain-cost 轨迹几乎相同 | 目标、分区、轨迹和足迹高重合 | 端口退化，不能作为强 GVP 基线 |
| MARL-IPP 不收敛 | PPO 曲线持续上升或黄金测试失败 | 增加 author/converged 预算或降为 prototype |
| 固定离线 SAC Q 值异常 | 未执行候选 Q 值远高于数据支持 | 恢复在线采集，必要时使用 CQL |
| recurrent 模块持续拖延 | 固定历史已经足够或无独立收益 | 使用固定历史并缩小论文声称 |
| OGFR 使用额外历史数据 | 主方法先验账高于对照 | 计入预算或单列预训练结果 |
| 控制器选择改变方法排名 | v6 与官方来源适配器下的配对排序不一致 | 报告敏感性并缩小高层结论；禁止只选择有利控制器 |
| 运动学调试结果混入正式表 | 执行结果没有执行模式或旋翼推力证据 | 降级为开发诊断，不能支持 CF2X/PhysX 动力学主张 |

## 14. 冻结执行顺序

### 阶段 A：P0

1. reachable denominator、schema、hash 和旧结果重评分；
2. 事件驱动团队动作和物理预算循环；
3. 前沿簇、观察位点、公共路径和局部轨迹；
4. 四机全局分配和 hold 原因；
5. `37.3%` 差异归因；
6. 两图 40 秒复测。

### 阶段 B：立即采集

1. 只有两张 fresh-process 40 秒回合同时满足 M1-M5 后，才允许用 random、单位时间 frontier、gain-cost 和透明层次规划器在至少两个差异 train 场景采集 300 个真实团队决策；首轮四机活动候选资格只是其中的 M4 诊断，不是单独的启动许可；
2. 审查字段、候选模式、规划/实际差异、三个 QD 轴和档案真实改选；
3. 旧的无约束 Lee 端口第一次真实 A/B 未通过，guarded-v4 的唯一接口等价复测也未通过合法混合路线；300 决策工程先导、后续 replay 与正式评测冻结 v6 为唯一控制器；
4. QD 三项资格成立才保留 planned/realised 分支，否则 QD 降为诊断；
5. 冻结公共候选和执行结果 schema 后，接入 bounded replay、训练采样和新状态编码；
6. 启动普通 SAC，按 1000/3000/5000 决策检查点推进。

### 阶段 C：并行资格建设

1. SAC 长时间采集期间完成 GVP 原环境、快照和差分，不反向改变公共候选 schema；
2. 完成 MARL-IPP 公开提交黄金测试、论文配置回归和 HM3D PPO/LSTM on-policy 迁移；
3. 用 train/dev 重复执行结果冻结 QD 改选与 fidelity 阈值；
4. 只在固定历史有明确不足时实现 recurrent history；
5. 只在 realised-QD 已有价值后投资 OGFR 三档消融。

### 阶段 D：正式实验

只有主方法在固定开发集上：

- 明显优于 random；
- 不弱于透明强规划器/普通 SAC；
- QD 至少有可审计的独立作用；
- 训练和预算账完整；

才启动完整主表和消融矩阵。

## 17. 最终裁决

当前最应该做的不是继续扩大 gate，也不是立即盲跑 5000 条旧语义数据，而是：

1. 用最小 P0 修复让每一物理秒、每一架无人机和每一个覆盖体素都可审计；
2. 先让透明层次规划器证明候选池能跨区域、跨层，并在存在安全任务时让四机真实分工；
3. 两图 v4 smoke 已证明 v6 执行、时序和清理链可用，但第四架机的首轮合法观察边仍缺失；“修复起点/候选资格后开始 300 个 v6 工程先导执行结果”只是当时的历史判断，不能作为当前启动许可。当前 fresh `00803` 又发现 observation-timing 收尾失败，因此实际规则是：只有 M1-M5 在两张 fresh-process 40 秒回合中全部通过后，才能启动 300；这条历史判断不再构成独立准入条件，也不能覆盖 M5 未通过状态。
4. 明确正式 CF2X/PhysX 不能无控制器运行；控制器只作共享基础设施，不作为论文创新；
5. 在任何先导执行结果被接纳为正式 replay 前冻结唯一动力学执行器，禁止训练和 holdout 使用不同控制器语义；
6. 用真实执行结果当场裁决 QD 三项资格，不再靠“以后会丰富”或“设计上一定有效”；
7. 冻结候选和执行结果 schema 后，把静态全批训练器改成真实的在线/离线混合 SAC；
8. 给内部消融相同预热、编码器和新增交互机会，给外部基线相同环境机会并保留各自算法；
9. 用 matched-budget 与 author/converged-budget 同时堵住“基线少训”的质疑；
10. 让 GVP、MARL-IPP、循环 RL 和 OGFR 在长训练期间并行成熟，而不是继续串行阻塞主任务；
11. 正式 holdout 前严格裁决：prototype 不进主表，正确实现的真实负结果不隐藏。

这样既保留过去一个月已经获得的控制、执行和工程证据，也能尽快把项目推进到真正决定论文成败的数据阶段。GVP 要认真做，但顺序是“规划能力先跑通、RL 立即开始、长训练期间补 GVP”，而不是继续让 GVP 阻塞第一批可信数据。

### 28. 2026-08-07 短路程不是单一策略问题：路线级方法修正

先回答“是不是只有一种方法差”：不是。E:/asset/hm3d_p0_train_outcome_300_20260806 中仅统计 P07_EXECUTION_SMOKE_COMPLETE 的完整回合，random、frontier_3d、auction 都落在相近区间：

frontier_3d 14 回合：AUC 0.0325 [0.0318, 0.0343]，最终覆盖 0.0535 [0.0488, 0.0591]，realized fleet path 19.62 m [18.48, 20.41 m]，决策 3.07
auction 1 回合：AUC 0.0324，最终覆盖 0.0532，realized fleet path 19.31 m，决策 4

因此根因在共享候选池和执行合同，不在 selector。逐决策审计显示同步等待占决策时间的 33% 到 45%，但等待本身不是第一步：一次 frontier_3d 决策中，一架机完成约 18.7 秒的 7.25 m 路线，另三架约 3.2 秒完成后等待约 16.5 秒；候选池里的计划路线只有 0.2 到 5.45 m。也就是说，即使把同步改成完全异步，当前候选池也没有给出足够长的任务。

规划间隔也不是主因。当前决策时长已经按剩余物理预算分配，一次决策不是固定短窗口；问题是候选目标来自前沿 1.0 到 2.5 m 观测 standoff，公共自由图即使存在长走廊，也容易退化成 0.5 到 1.5 m 的 micro-route。FUEL/RACER、Fast Multi-Robot Exploration 和 C2-Explorer 的共同做法是：先形成区域/前沿结构，再提交到观察位点的全局访问路线，执行期间只在完成、显著新证据或安全事件时重规划，而不是每次决策都围绕短观测点重来。

本轮代码已把方法改为“路线级承诺 + 长路线候选 + 连续区域访问”，不替换原架构：前沿簇 -> 观测位点（1.0-2.5 m，保留局部传感） -> 当前连通 free component 内朝簇中心前进的 region_access 路线 -> route_progress 保留 45%/70%/85%/95% 前缀 -> 共同静态守卫和四机联合守卫仍为唯一安全权威 -> 同一候选池交给 random/frontier_3d/auction/QD/SAC。

region_access 只从公共 sparse belief 生成，路径全部位于当前已知 free voxel，安全上不进入未知空间；它只改变候选动作空间和选择器看到的计划路线长度，不放松 0.50 m 物理间距、0.90 m 规划分离余量、静态净空或碰撞合同。新增 viewpoint kind 已同步到 PublicFrontier、任务 reservation、共同匹配优先级和 runner 审计字段。

QD 的创新定位不因此降低，反而更适合路线级行为轴：区域/楼层推进、路线连续性、实际路线长度、垂直访问、观测重叠、planned-realised gap。后续 300 决策采集必须记录每轮最大计划路线长度、每机实际路线长度、同步等待秒数、actual/planned ratio、反向率和有效运动时间；只有这些指标先改善，才能讨论 RL 是否优于规划基线。

actual_start >= token_window_start - tolerance
actual_end <= token_window_end + tolerance

路径、静态净空、碰撞、分离、通信、观测和硬超时检查全部保留；timing model 的偏差仍通过 transit timing contract 审计。新增测试覆盖“事件驱动提前完成允许复用”和“超出 token 窗口拒绝”，并用指定解释器通过相关单元测试。
