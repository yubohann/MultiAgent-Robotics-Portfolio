# HM3D 场景分层与完整实验规模合同

日期：2026-08-04
状态：`ACTIVE / METHOD-INDEPENDENT SELECTION / FOUR-CF2X / REVISED 2026-08-06`

> **2026-08-06 修订**：本文档中的 145 train / 68 validation / 8--16 天是历史规划，不再作为正式规模或工期承诺。最新主合同采用约 60 张 train、12--18 张 dev、24--36 张 holdout 作为资产过滤前的规划范围；最终数字必须在 P0 通过后按真实吞吐、四机飞行资格和预注册分层抽样冻结。2--3 周只是现实排期估计，不能替代实测。

## 结论

正式训练不再使用 48 或 75 张作为目标，而是从官方 800 个 HM3D train 场景中冻结 145 个高保真候选（2026-08-06 起为历史分层候选，正式规模以主合同约 60 张为准）。75 仅是 FSE 2023 使用过的较小 HM3D 语义子集规模，不是因为该论文依赖实机，也不是本文可以照搬的小样本豁免。本文没有实机结果，因此必须用更强的跨场景、多楼层和冻结 holdout 设计补偿外部有效性风险。

正式评测从官方 100 个 validation 场景开始资格审查，一次性冻结 12 个 `validation-dev`、12 个 `qd-high-opportunity-holdout`、12 个 `qd-low-opportunity-counterfactual` 和 36 个 `main-representative-holdout`；四组互不重叠，另留 28 个同协议候补。本文关于 QD + RL 优越性的核心证据来自两组机制 holdout：高机会组检验其在理论适用条件下是否优越，低机会组检验收益是否按理论减弱。36 个代表性场景只承担外部有效性与适用边界报告，不替代机制主实验。每个 holdout 场景使用三个冻结的合法四机起点种子。任何方法表现都不得参与场景或起点筛选。

## 训练场景选择

输入是官方 800 个 train 场景。两阶段选择如下：

1. 元数据冻结队列：按楼层组 `1/2/3/4+` 分层；每个楼层组内部按可导航面积三分位、导航复杂度三分位组成联合单元；在单元平衡的基础上，对房间数、面积、总楼面、复杂度、拥挤度、单位楼层面积、房间密度和面积比例的分位向量做确定性 maximin 采样。
2. 四机飞行资格：检查碰撞 USD、双面碰撞、0.30 m 净空、四个分离起点、稀疏测距一致性、连通自由空间和真实垂直机会。失败只能由同一楼层/面积/复杂度单元的预冻结候补替换。

禁止输入包括方法覆盖率、AUC、奖励、QD 占用、RL value、基线排名和人工观看某方法轨迹后的主观偏好。

当前元数据队列：`E:\asset\hm3d_train_stratified_maximin_v2_20260804.json`。

- 145 个 primary（历史分层候选），655 个同协议候补；
- 楼层配额：1 层 50、2 层 58、3 层 29、4+ 层 8；
- 面积范围：16.92--336.64 m²；
- 面积×复杂度联合单元在 1--3 层全部覆盖；4+ 层覆盖实际存在的 8 个单元；
- 元数据向量完全重复对为 0；
- 同楼层最小/中位/平均成对差异距离为 0.1595 / 0.3979 / 0.4057。

这只能证明元数据层面有差异，不能证明自由飞行拓扑有差异。几何审查后还要报告自由体积、垂直跨度、连通分量、可飞高度带、瓶颈和四机起点容量的分布。

验证冻结文件为 `E:\asset\hm3d_validation_cohorts_v2_20260804.json`，冻结哈希为 `d0854608761b136e28a61a70bba687129a93078e552aaf3939f9e367d3fdf1f6`。v1 的 `10+10` 机制组在未访问任何方法结果时被 v2 的 `12+12` 取代，旧文件只保留为变更证据，不再用于实验。高机会机制组按 QD + RL 的方法无关适用条件筛选：存在真实可飞的多个高度带或明显三维分支、四机有至少两种互不等价的合法任务分配、局部信息不足以让单一贪心规则始终占优，并存在由净空、避让、通信或执行时长造成计划--执行分歧的结构性机会。低机会反事实组选择单层、低分支或协作角色较单一的合格场景。元数据代理使用楼层数、房间数、导航复杂度、拥挤度和房间密度，只负责生成冻结审查队列；最终资格由方法无关的 P03 几何、连通性和候选结构审计确认。不得用任何方法的 AUC、覆盖率、archive 占用、RL value 或输赢决定入选或替换。

筛选最适合 QD + RL 的场景是合理且必要的，但“适合”必须由预先声明的任务结构定义，而不能由本文方法已经获胜来定义。论文的首要问题是：在多策略、强状态依赖、存在真实计划--执行分歧的复杂三维协作探索中，realised-QD + RL 是否优于 planned/no-QD 和相邻强基线。代表性组回答的是次要问题：这种收益能否外推到更广泛的 HM3D 分布。若只在高机会组有效，论文必须明确主张为条件性优越性；这不是失败，但不能写成 HM3D 全分布领先。

## 为什么不按每层面积最大排序

只选最大图会产生四个问题：

1. 样本偏向豪宅和极端大扫描，不代表 HM3D 的主体分布；
2. 固定 240 秒预算下，大图覆盖率天然更低，会把场景尺寸效应误写成算法能力；
3. 面积大不等于多楼层可连通，也不等于能容纳四机；
4. 大面积、房间数和总楼面高度相关，实际多样性可能反而下降。

因此最大场景应作为高面积分位的一部分和规模压力测试，而不是训练集全部组成。主表必须同时给出按楼层组和面积分位分层的结果，防止总体均值掩盖失败。

## 起点合同

训练阶段从每张合格场景的合法四机起点池按冻结种子抽样，起点之间满足净空、机间分离和初始通信合同。允许跨 episode 改变起点，以增加状态覆盖；不允许方法自行选择有利起点。

评测阶段每张场景固定三个不同起点种子。所有方法共享完全相同的起点、物理随机键、候选池、传感、通信和预算。三个起点先在场景内聚合，再跨场景统计，不能把同场景起点当成三张独立地图。

## 避免“全部跑完才发现无效”

正式 holdout 之前只用 train 与 `validation-dev` 做三步否证，不读取 24+36 个 holdout 的方法结果：

1. 在至少四张差异训练图上跑 40 秒 canary，检查所有方法是否真实移动、预算利用率、覆盖量级和候选差异；共同低覆盖先修执行/候选，不启动长训练。
2. 用 train 执行结果检查 planned--realised gap、三个 realised descriptor 的方差/相关性、联合格和 archive 改选；QD 高机会训练图仍退化时先修描述符或候选结构。
3. 在 12 张 dev 上比较 heuristic、普通 SAC、planned-QD、realised-QD 和完整方法的学习曲线及置信区间；没有独立 RL 信号时先修状态、奖励或训练闭环。

一旦访问正式 holdout，禁止依据部分结果改模型。若必须修改，则当前 holdout 结果作为开发证据封存，新版本只能使用未访问的 32 个候补重新冻结；不能边看边挑图。

长任务按 `scene_id × start_seed × method × model_seed` 形成原子作业。P07 持久采集器使用 `--resume` 校验并跳过已完成执行结果，每个 episode 后原子更新 manifest；中断最多损失当前 episode。离线 RL checkpoint 必须包含在线/目标网络、全部优化器、熵温度、成本乘子、随机数、更新步、配置哈希和数据清单哈希，因此允许跨进程等价续训，但不同 checkpoint 段的墙钟和更新范围必须保留。

## 反过拟合证据

场景差异大只能降低过拟合风险，不能证明没有过拟合。论文必须同时报告：

- train、validation-dev、两个 mechanism holdout 和 main holdout 的严格 scene-level 不重叠哈希；
- mechanism/main holdout 从冻结后不再用于调参；
- 按楼层、面积、复杂度分层的效果和失败率；
- train 与 holdout 的性能差距；
- 三个起点种子的场景内方差；
- QD archive cell 和 RL 选择是否只在少数大图或某一楼层有效。

若完整方法只在某个场景分层有效，应缩小论文主张，而不是通过重新抽图改善总体均值。
