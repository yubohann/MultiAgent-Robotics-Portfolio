# 异步完成设计：逐机滚动决策（Per-Agent Rolling Decision）

日期：2026-08-08（v1）
状态：设计规格，待实施。关联：docs/执行计划_打断短视循环完成主实验_2026-08-08.md 阶段 3b。

## 0. 问题与动机（阶段 3 A/B 结论）

- 同步完成（`hm3d_cf2x_execution.py` 2531-2534：`all(failed or observation_end)` 才结束决策）
  使每决策物理时长 = 最慢机 transit+dwell。
- 长路线偏好（2a，+15% 覆盖于 00626）在 00459 净负（-12%）：长路线 → 每决策 9.5-12s
  → 40s 只 4 决策（vs 基线 6）→ 决策次数损失无法被等待期采样补偿（46.4% < 52.2%）。
- **解**：快机完成自己的 transit+dwell 后立即进入下一周期（不等全队），
  决策次数不再被最慢机限制。目标：40s 决策数 ≥12、里程 ≥60m、
  00626 覆盖 ≥25%、00459 覆盖 ≥65%（阶段 3 验收）。

## 1. 设计原则与不可违反约束

1. 安全合同不变：静态净空 0.5/0.9m、路线管间距 0.50m、端点间距 0.95m、
   通信中继连通、碰撞/越界/分离违规归零。
2. 公平性不变：所有方法（基线+主方法）在同一异步协议下比较；
   传感器、预算、种子、指标完全共享。
3. 公共信念共享：所有机观测实时合并（现机制不变）；任何机不读评估器真值。
4. 观测合同不变：稀疏测距 10Hz、dwell ≥1s、H15 传感器窗口
   （reset_bootstrap/transit/observe/dwell）语义保留。
5. 论文主张不变：异步是执行语义修正，不是新机制；QD 仍以真实回执维护行为多样性，
   RL 仍学选择。
6. 可审计：每个"机-决策"记录自己的 state/candidate/outcome/回执，
   与当前 P07 字段兼容或显式迁移。

## 2. 架构方案对比

| 方案 | 描述 | 改动面 | 风险 | 裁决 |
|---|---|---|---|---|
| A 完全异步 | 每机独立候选池+独立决策流 | 执行器/候选层/协议全改 | QD 团队描述符失效、论文"团队协作"语义破坏 | 否 |
| B 逐机滚动决策（选定） | 保留共享池与守卫；快机完成 dwell 后**单独重规划自己的下一候选**；慢机继续 | 执行器（中）+候选层（小）+协议（小） | 团队联合分配被逐机准入替代，tube/endpoint 冲突需增量守卫 | **是** |
| C 决策内流水线 | 团队决策保持，快机等待期执行候选池顺路探测 | 执行器（大） | 追加动作与 token/回执语义纠缠 | 否 |
| D 固定窗口异步 | 短窗口+未完成机跨窗口 | 执行器（中） | 窗口与 dwell 合同耦合、边界语义模糊 | 否 |

## 3. 方案 B 详细设计

### 3.1 核心机制
- 每机状态机：`TRANSIT → DWELL → (完成) → READY_FOR_NEXT`。
- 团队级循环改为**事件驱动**：任意机 `READY_FOR_NEXT` 时触发"该机下一候选生成"。
- 快机重规划期间，其他机继续物理执行（并行推进，不阻塞）。
- 决策记录从"团队决策"细化为"机-决策"（per-agent decision），
  但**保留团队时段信息**（滚动窗口内的团队足迹）供 QD 描述符使用。

### 3.2 候选生成（逐机准入 + 增量守卫）
- 每机空闲时，从当前公共前沿生成自己的候选：
  observation / route_progress / region_access（复用现有生成器）。
- 守卫改为**增量准入**：新候选与"当前在飞/已预约的其他机路线"做
  路线管间距（≥0.50m）、端点间距（≥0.95m）、中继连通检查——复用现有
  `assess_route_tube_separation` 与 joint guard 的成对逻辑。
- 原"团队联合分配"（4 机一次选齐）降级为**建议排序**（可复用 `_feasibility_first_assignments`
  的输出作为每机选点优先级），不再作为硬同步边界。
- 每机候选数上限 K 与现协议一致；预算、时序窗口（pass_through v5）不变。

### 3.3 执行器改动（hm3d_cf2x_execution.py）
- 移除"全队完成才 break"；改为：
  - 每机完成 dwell → 标记 `agent_ready[i]`，**立即**触发该机下一候选的生成与执行；
  - 慢机继续执行，互不阻塞（物理步进共享，动作独立）。
- 传感器：dwell 后若等待（未拿到新候选）继续等待期采样（已实现，保留）。
- token 语义：每机动作独立 token；公共回执（belief 更新）仍全局合并。

### 3.4 协议与 schema 兼容（关键）
- 新增字段（向后兼容）：
  - `decision_count` → 保留（团队级语义：一轮滚动 = 一次团队时段）；
  - 新增 `agent_decision_count`（每机决策数，40s 内 ≥12/机 为目标）；
  - 每机决策记录 `agent_id / candidate / outcome / realised_qd` 独立可审计。
- training transitions：改为**每机决策一个样本**（论文主张本来就要求 per-decision
  sample，见主合同 08-04 修改）；团队时段样本（现有 single_rl 格式）保留为
  "团队快照"消融。
- QD 描述符：`team_spatial_dispersion`/`public_observation_complementarity`
  在异步下用**滚动团队窗口**（最近 N 秒内各机足迹）计算，定义写入 P08 协议。
- `realised_qd` 入档条件不变（真实回执、无碰撞、片段完成）。

### 3.5 与 2a（长路线偏好）的关系
异步落地后重新启用 2a（`PUBLIC_POTENTIAL_GAIN_*` 常量保留）：
- 长路线不再减少团队决策数（每机独立推进）→ 00626 与 00459 应同时受益；
- A/B 复验两场景 ≥3 回合。

## 6. 风险与对策

| 风险 | 对策 |
|---|---|
| 逐机准入导致路线冲突（tube 竞争） | 增量守卫严格复用现有成对评估；冲突时该机 hold 一窗口（有记录） |
| 协议字段迁移破坏训练/QD 历史 | schema 向后兼容；旧数据按旧语义保留，新数据显式标记 async |
| 异步下团队描述符失真 | 滚动团队窗口定义冻结并写入 P08；消融对照同步版本 |
| 实现回归（物理安全） | 每阶段全量单测 + 安全计数断言零违规 |

## 8. 与论文主张的关系

- 异步完成修正执行语义（消除同步 hold），是**工程正确性**，不是新增算法贡献；
- 它让"长路线偏好（2a）+ QD/RL 选择"的真实收益可被测量；
- 论文方法章节将"事件驱动逐机滚动决策"作为协议定义的一部分描述，
  与 RACER/FUEL/FAEP 的"动态起点重规划/流畅执行"文献对齐。
