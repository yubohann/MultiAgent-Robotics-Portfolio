# 四机 HM3D 强基线作者代码大测试审查

日期：2026-08-04

## 1. 最终结论

MARL-IPP 是真实的 RA-L 2026 同行评审论文，也确实做了四架真实 Ryze Tello 无人机实验。但是，论文的真实实验只是小场地可行性演示：场地为 `7.62 x 3.25 x 2.4 m^3`，有随机障碍和 6 个 ArUco 目标；正文没有给出真实实验的主表、方差、碰撞率、任务失败率或统计检验。因此应准确写成“有四机真实演示和可行性验证”，不能写成“已完成充分的真实定量验证”。

MARL-IPP 仍是当前最适合迁移到本文的外部强化学习强基线候选，因为它原生处理三维候选节点、动态候选图、多机器人、有限通信、动作掩码和循环状态。它不是 HM3D 无目标覆盖算法，原任务是目标映射，必须在 HM3D train 场景上按本文任务重训，并明确命名为 **MARL-IPP 受控迁移**。

当前本地 `MARL-IPP-port` 还不具备论文主表资格。它严格复用了作者 `AttentionNet` 和官方检查点，但本地训练器不是作者 PPO：每个图都重置循环状态，样本是独立的单步终止转移，没有旧策略概率、PPO 比率、裁剪目标、多步回报或多轮 PPO 更新。它现在只能称为“作者网络骨架受控迁移原型”，不能称为已完成的 MARL-IPP 强基线。

非强化学习规划强基线首选 GVP-MREP。它的原任务就是未知三维空间中的多无人机无目标探索，有真实六机实验、同行评审论文和完整 MIT 仓库，任务层比 HM3D 的地面 ObjectNav/PointNav 论文更接近本文。但当前 `GVP-MREP-port` 也不合格：它没有复现作者的 MR-DTG 作业状态和原始增益公式，在 1000 组状态中与普通 auction 有 `94.1%` 选择相同，说明当前端口退化成了 auction 的轻微变体。

所以当前结论不是“这两个强基线已经实现”，而是：**候选选择已经确定，作者源码、论文和结构测试已经完成；两条正式迁移仍分别卡在 PPO 训练忠实度和 GVP 拓扑分配忠实度。任何现有数字都不能进入论文性能主表。**

## 3. MARL-IPP 到底做什么

MARL-IPP 解决的是多机器人信息路径规划和目标映射：在未知三维环境中，多个无人机受总路径预算限制，需要选择下一批三维观测位点和传感器朝向，尽可能发现静态目标。

它的主要假设和接口是：

1. 每个无人机有 RGB-D 相机，视场角 90 度；传感距离按环境尺度设定。
2. 机器人位置已知，候选动作包含 `x/y/z` 和离散传感器朝向。
3. 机器人之间按距离通信，论文用通信半径参数控制可达性。
4. Gaussian Process 估计目标收益、不确定性和其他机器人已访问区域。
5. 每个机器人在动态候选图上使用注意力网络和 LSTM 选择动作。
6. 使用集中训练、分散执行的 PPO；训练时汇总多环境、多机器人经验。

算法结构可以概括为：

```text
局部三维候选与目标不确定性
        -> 动态协调图
        -> 注意力编码候选、预算和其他机器人已探索区域
        -> LSTM 保留时序状态
        -> PPO 选择下一观测位点
        -> 执行后更新目标地图、通信状态与回报
```

它与本文相似的是“三维、多机器人、局部信息、候选图、有限通信、RL 选择”；最根本的不同是“发现预设目标”对“无目标自由空间覆盖”。因此作者论文的 `% targets` 不能与本文的自由体积覆盖率直接比较。

## 4. 原论文训练与评价

论文训练设置为 3 架无人机、结构化训练环境、随机测试环境。训练预算随机取 `[7, 9]`，每个 episode 最多 256 步，36 个并行环境，PPO 每批更新 8 轮，batch size 1024，epsilon clip 为 0.2。论文称使用一张 NVIDIA A30，并需要约 120,000 次环境交互收敛，但没有报告完整墙钟训练时间。

作者在 25 个随机测试环境中，每个环境运行 10 次，共 250 次测试。主指标是发现目标比例，辅指标是每步规划时间：

| 方法 | 发现目标比例 | 规划时间/步 |
|---|---:|---:|
| MARL-IPP，全局通信 | `66.00 +/- 5.59%` | `1.58 s` |
| MARL-IPP，有限通信 | `62.16 +/- 8.25%` | `1.58 s` |
| Intent destination | `52.31 +/- 9.29%` | `25.39 s` |
| CAtNIPP greedy | `45.31 +/- 10.59%` | `3.84 s` |
| MCTS | `48.50 +/- 7.81%` | `153.49 s` |
| RIG-Tree | `47.38 +/- 10.43%` | `60.46 s` |
| Random | `31.83 +/- 15.23%` | `0.06 s` |

论文还报告两组训练消融：

- 建模其他机器人已探索区域：`66.00 +/- 5.59%` 对 `61.97 +/- 7.34%`，未配对 t 检验 `p=3.91e-9`。
- 使用通信奖励：`66.00 +/- 5.59%` 对 `62.92 +/- 7.01%`，`p=5.11e-6`。

作者随后在 gym-pybullet-drones 和 Houses3K 中构造 `60 x 60 x 30 m^3` 的物理仿真，3 架无人机最大速度为 `1 m/s`。这一部分只与 Random 比较。作者明确承认，把其他规划器改造成能处理未知障碍和机间碰撞并不容易，因此没有把前述全部基线搬进物理仿真。这个事实反而提醒我们：不能把结构化栅格中的 MARL-IPP 数值直接当成 HM3D/CF2X 性能。

## 5. MARL-IPP 的真实无人机实验有多强

论文确实使用了 4 架 Ryze Tello。场地尺寸是 `7.62 x 3.25 x 2.4 m^3`，随机放置障碍，目标是 6 个 ArUco 标签。

可以主张：

- 作者确实把方法部署到了真实多无人机系统。
- 三维飞行、真实传感和多机执行并非仅停留在 Python 栅格。
- 真实演示支持方法的基本可部署性。

不能主张：

- 真实实验已证明对复杂多层室内空间有效。
- 真实实验已给出可复现的平均性能和失败分母。
- Tello 小场地结果可直接支持四机 HM3D 多楼层结论。
- 作者已解决未知障碍下的完整多机碰撞安全问题。

因此，对用户问题“有没有做真实无人机”的严格回答是：**有，四架 Tello；但真实部分是小规模演示，不是完整的真实定量评测。**

## 7. 为什么选 MARL-IPP，而不是其他候选

选择不是因为它年份最新，而是因为迁移后仍能保留可辨认的作者算法核心。

| 候选 | 与本文接近之处 | 不适合作四机三维强 RL 基线的原因 |
|---|---|---|
| MARL-IPP，RA-L 2026 | 原生三维节点、动态图、多机器人、有限通信、掩码和 LSTM | 原奖励是目标映射，需要重训；当前本地训练还不忠实 |
| ReCuriosity，2026 预印本 | HM3D、无目标探索、长期记忆 | 单个地面智能体、RGB 球形相机、四个离散动作；改成四机三维后作者方法身份几乎消失 |
| MARVEL，ICRA 2025 | 多机器人探索、正式发表、官方检查点 | 作者输入只有 `x/y`，实测任意 `z` 扰动后输入不变，不能表达跨层候选 |
| IR2，IROS 2024 | 多机器人、间歇通信、作者检查点 | 二维地面探索，适合作通信参考，不适合多楼层主基线 |
| RVN-Bench，2026 预印本 | PPO、碰撞负样本 | 单 Jackal、顺序 PointGoal、地面离散动作，且仓库未声明许可证 |
| HM3D-OVON，IROS 2024 | 原生 HM3D、成熟 Habitat 训练 | 单地面 ObjectNav，目标任务、传感器和动作空间都不同 |
| VisFly，ICRA 2025 | 能加载 HM3D 的连续四旋翼 RL 平台 | 是平台而不是协作探索算法，动力学也不是本文 CF2X/PhysX |

ReCuriosity 在“HM3D 无目标探索”这个任务名上最接近，但算法主体差距最大。MARL-IPP 不使用 HM3D，却在三维候选图和多机器人决策接口上最接近。对于受控迁移，保留算法身份比只保留数据集名称更重要。

这不是说 MARL-IPP 完美适配。它最大的迁移风险是：将目标不确定性图替换成自由空间前沿图后，作者 GP 和目标奖励被移除，最后可能只保留注意力网络和 PPO。论文中必须清楚写出保留项、替换项和删除项，并同时给出作者原任务检查点复现，不能把它包装成“原版 MARL-IPP 在 HM3D 上运行”。

## 8. 当前 MARL-IPP 端口的真实状态

结构压力测试结果：

- 作者 `AttentionNet` 和官方检查点严格载入。
- 1000 组四机、变候选数、含非法动作的图输入中，非法选择数为 0。
- 概率和误差不超过约 `1.50e-7`。
- CPU 平均推理约 `1.8 ms`。
- 高度扰动会改变概率，平均概率 L1 变化约 `0.0187`。

这些只能证明网络接口、掩码和数值稳定，不能证明训练算法或 HM3D 性能。

新增的训练忠实度审计检查作者 `driver.py/worker.py` 与本地端口。作者源码具备：256 步 episode、跨决策 LSTM 状态、旧策略 log probability、PPO ratio、裁剪 surrogate、8 个 PPO epoch 和折扣时序回报。本地端口缺少全部这些关键语义，并且显式存在“单步终止样本”和“每图重置 LSTM”。审计因此给出：

```text
current_port_preserves_author_ppo_semantics = false
current_port_main_table_qualified = false
```

阻塞项共 9 个：

1. 没有多步 episode 转移。
2. 没有跨决策循环状态。
3. 没有旧策略概率快照。
4. 没有 PPO 概率比率。
5. 没有裁剪 surrogate。
6. 没有多轮 PPO epoch。
7. 没有折扣时序回报。
8. 训练样本被固定为单步终止。
9. 每个候选图都重新清零循环状态。

在这些问题修复前，即使本地训练损失下降，也不能把结果标成 MARL-IPP。

## 9. 怎样保证 MARL-IPP 结果达到论文级

论文级资格不由“数据是否好看”决定，而由以下审计条件决定：

1. **来源忠实度**：作者网络、动作掩码、PPO 裁剪、LSTM 时序、图特征和源代码哈希可核验。
2. **迁移透明度**：明确列出目标映射奖励、GP、原候选图被什么无目标覆盖组件替换。
3. **训练边界**：只使用预注册 HM3D train 场景；调参只看 train/dev，holdout 不参与选择。
4. **共同物理条件**：四架 CF2X、公共传感、起点分布、物理预算、安全守卫和失败定义相同。
5. **同等调参预算**：MARL-IPP 和本文方法使用同数量训练交互、种子与允许的超参数搜索次数。
6. **完整失败分母**：碰撞、卡死、候选为空、超时、断联和守卫拒绝均保留。
7. **统计充分性**：至少 3 个训练种子；holdout 按场景和执行种子配对，报告均值、置信区间和每场景散点。
8. **原任务回归测试**：修订后的训练器先在作者环境复现作者检查点附近的行为，防止端口只在 HM3D 上“看起来能跑”。
9. **方法作用证据**：输出选择熵、候选切换、垂直候选比例、覆盖曲线和失败类型，而不只报最后一个均值。

失败实验的处理规则必须提前写清：

- 代码错误、PPO 语义缺失、候选退化、未跑满预算等是**无效实现记录**，只进入工程审计，不进入论文性能表。
- 在来源忠实、训练收敛、调参预算公平且 holdout 协议合格后，若 MARL-IPP 仍表现差，这是**有效负结果**，必须报告，不能因为不好看而删除。
- 优化只能使用 train/dev。看到 holdout 后继续改到好看属于数据泄漏。
- 若一个强基线持续失败，应先判断任务迁移是否破坏其算法身份；不能无限调参，也不能把未优化成功的失败冒充算法本身很差。

## 10. 本机重训时间：1000 个训练场景意味着什么

1000 张 HM3D train 场景不是 1000 个独立模型。合理含义是：一个共享策略在从这些场景分层抽样得到的 episode 上训练。若总交互仍为 120,000 次，平均只是每场景 120 次交互，而不是每张图训练 120,000 次。

本机已有 18 个完整四机 HM3D/CF2X 记录可用于墙钟估算：

- 每个记录物理预算 40 秒、4800 个物理步。
- 当前每个记录只有 1 次上层决策和 1 个真实执行结果。
- 墙钟最小 `143.86 s`，中位 `152.29 s`，均值 `162.65 s`，最大 `202.64 s`。
- 平均墙钟/物理时间约 `4.07`。

因此，当前瓶颈不是 60 万参数的 PPO 网络，而是 HM3D 稀疏射线、公共地图、前沿、候选、PhysX 和执行结果生成。

按作者约 120,000 次交互给出三种估算，所有估算都只是上线前预算，不是承诺：

| 假设 | 单模型数据收集墙钟 | 结论 |
|---|---:|---|
| 每次团队决策执行 15 秒，吞吐按当前 4.07 倍物理时间线性估计 | 约 `84.7 天` | 不可接受 |
| 每次团队决策仍占一个完整 40 秒 episode | 约 `225.9 天` | 完全不可接受 |
| 120,000 指单机动作，四机每轮提供 4 个样本，乐观除以 4 | 约 `21.2-56.5 天` | 计数语义与本文团队候选不一致，只能作极乐观下界 |

当前记录“一回合只有一个训练样本”说明直接在线重训不可行。必须先把 40 秒 episode 改成多个真实重规划片段，例如 5 个 8 秒决策，并实测每个决策的增量墙钟；否则不能启动长训练。

### 1000 场景的可行用法

1. 先离线筛选可飞、存在垂直机会、能容纳四机的场景。
2. 将合格场景按单层/多层、自由体积、狭窄度和通信难度分层。
3. 1000 个资产作为场景总体和抽样框，不要求每个梯度批次都载入全量场景。
4. 将公共稀疏地图和候选图缓存为训练样本；网络更新批量离线进行。
5. 对 MARL-IPP 的 PPO 必须保持 on-policy 语义，旧策略采集轮次和更新轮次不能混用；不能把任意旧执行结果混成 PPO batch。
6. 对本文离策略 SAC 可以复用符合来源合同的 train 执行结果，但不得复用 validation/holdout。
7. 每隔固定更新轮次回到 Isaac 做真实物理闭环验证。

在完成“多决策 episode + 4/8 个并行环境吞吐 + 峰值显存”实测前，不能声称一张 4090 一定能在几天内完成。现有记录没有峰值显存字段，因此显存是否会在多环境下超过 24 GB 仍是未测风险。

## 11. 全部消融训练需要多久

规划基线 `random/frontier_3d/auction/GVP-MREP` 不需要神经网络训练，只需要运行评测 episode。真正昂贵的是会改变策略分布或 replay 分布的学习方法。

最小科研训练族是：

1. MARL-IPP 受控迁移，3 个训练种子。
2. 无 QD 的同骨架 RL，3 个种子。
3. planned-QD + RL，3 个种子。
4. realised-QD + RL，3 个种子。
5. realised-QD + outcome-gated OGFR + RL 完整方法，3 个种子。

若 `no_ogfr` 只是推理时禁用检索且不改变训练 replay，可以复用第 4 组检查点；若 OGFR 会改变训练样本或信用分配，就必须独立重训。SF、成本 critic 等也只有在改变学习目标时才需要重训，不能把每个开关机械做成笛卡尔积。

按当前纯在线吞吐，15 个训练运行的朴素上界约为 `1270-3389 天` 串行墙钟，显然不具可行性。即使只训练 MARL-IPP 和完整方法两类、各 3 种子，也约为 `508-1355 天`。这些数字说明当前实验设计必须改变数据生成方式，而不是说明论文必须放弃 QD+RL。

可行目标应是：先用 2 个场景、2 个种子、每回合 5 个决策做吞吐 pilot；测出“每小时有效执行结果数”和学习曲线的交互数，再决定场景规模。只有真实吞吐提高至少一个数量级，并且候选图缓存能支持大部分网络更新，才有可能把完整训练压到数天到数周。当前没有证据支持更乐观的固定天数。

## 12. 规划强基线：GVP-MREP 论文

- 标题：*Fast and Communication-Efficient Multi-UAV Exploration Via Voronoi Partition on Dynamic Topological Graph*
- 会议：IROS 2024
- DOI：`10.1109/IROS58592.2024.10801613`
- 页码：14063-14070
- 作者：Qianli Dong 等
- 本地 PDF：`E:\Outcome_Grounded_Repertoire_Literature_2026\papers_pdf\GVP-MREP_IROS2024_arXiv2408.05808.pdf`
- 本地 HTML 全文：`E:\Outcome_Grounded_Repertoire_Literature_2026\papers_source\GVP-MREP_IROS2024_arXiv2408.05808.html`
- 官方仓库：`https://github.com/NKU-MobFly-Robotics/GVP-MREP`
- 本地仓库：`E:\Outcome_Grounded_Repertoire_Literature_2026\official_repositories\GVP-MREP-main`
- 许可证：MIT
- 在线核验：约 188 stars、15 forks；这些数字同样不用于证明算法质量。

GVP-MREP 的任务是让多架无人机在未知三维空间中尽快建立完整体积地图，同时降低多机通信量。每架无人机维护 MR-DTG：历史节点表达已探索可通行区域，可探索节点表达前沿，边表达可达路径。无人机只发送拓扑图增量，而不是不断发送完整点云或占据地图。

它的关键机制是：

```text
局部三维体积地图
    -> 增量 MR-DTG
    -> 交换必要拓扑增量
    -> 图 Voronoi 按真实路径代价分区
    -> 局部/全局两级任务分配
    -> MINCO/轨迹优化
    -> 分布式执行与重规划
```

作者增益中明确考虑前沿数量、已有作业数量、作业剩余时间和图距离：

```text
g = (max(g, 0) + frontier_count * allowance) / (work_count + 1)
g = g * exp(-distance * lambda)
```

仓库默认参数为 `lambda=0.2`、`allowance=0.1`、`tau=0.3`。

## 13. GVP-MREP 的原论文结果

作者在 Small Maze 和 Large Maze 中与 RACER 比较，测试 3、5、10 架无人机。Large Maze 是 `40 x 40 x 3 m^3`，每种方法最长 300 秒。论文报告：

- Small Maze 探索时间比 RACER 短约 `18.3%-30.8%`。
- Large Maze 探索时间比 RACER 短约 `22.0%-38.3%`。
- 通信量比 RACER 低约 `93.5%-95.6%`。
- GVP 图分区计算开销比 RACER 的大规模 CVRP 低至少一个数量级。
- 真实实验使用 6 架无人机，在 `40 x 24 x 3 m^3` 户外灌木场地中约 `67.2 s` 探索大部分空间，总通信量 `14.47 MB`。

这些结果证明 GVP-MREP 是完整的多无人机三维无目标探索系统，但高度只有 3 米，不能证明其已经解决多楼层室内跨层探索。

## 15. 为什么选 GVP-MREP，而不是其他规划方法

规划候选按“同任务、三维多机、源码可用、迁移量、近年正式发表”排序：

| 排名 | 方法 | 优点 | 主要问题 | 结论 |
|---:|---|---|---|---|
| 1 | GVP-MREP，IROS 2024 | 多 UAV、未知三维、无目标覆盖、有限通信、真实六机、MIT 完整代码 | 非 HM3D，原仓库重 ROS；当前端口不忠实 | 正式强规划基线首选 |
| 2 | RACER，T-RO 2023 | 多 UAV、异步有限通信、完整代码和实飞 | 更老、ROS/规划栈重；GVP 已在原论文中直接对比并优于它 | GVP 复现参考和二级核验 |
| 3 | C2-Explorer | 多 UAV、三维低层、ACVRP 和连通协调 | 高层源码明确有单层 grid 和 `dz=0` 路径；完整迁移成本更高 | GVP 失败时的备选，不是当前首选 |
| 4 | Distributed Frontier + NBV，Drones 2024 | 正式期刊、三维 LiDAR、多 UAV、无 RL | 最多三机，未找到可核验作者仓库 | 方法参考，不能承担作者源码强基线 |
| 5 | FUEL | 三维前沿和轨迹结构成熟、开源 | 主要是单机，2021，协作接口差距大 | 只复用前沿结构 |

当前没有检索到同时满足“原生 HM3D、四机、连续三维、无目标覆盖、非 RL、非多模态、正式发表且完整开源”的规划论文。不能因为用户希望用 HM3D 就虚构一个。

同数据集并不自动比同任务更公平。HM3D 的大多数同行评审算法是地面 PointNav/ObjectNav，指标为 Success/SPL，动作是离散前进和转向。把它们改成四机连续三维无目标覆盖，算法身份会比 GVP 迁移得更严重。因此应选择 GVP 的任务机制，再在共同 HM3D/CF2X 条件下重新测。

## 16. 当前 GVP 端口为何不合格

当前代码只使用本地组合评分：单位时间收益、Voronoi、均衡、连通和 makespan。它没有稳定 MR-DTG 节点、前沿数量、其他机器人作业状态、剩余时间，也没有作者原始 `lambda/allowance/tau` 公式。

1000 组四机三维候选压力测试结果：

```text
auction 与 GVP-port 选择不同的比例 = 0.059
auction 与 GVP-port 选择相同的比例 = 0.941
current_port_main_table_qualified = false
```

这不是“GVP 与 auction 本来就一样”的证据，而是端口退化的证据。修复要求：

1. 用公共稀疏观测维护稳定的三维拓扑节点和前沿簇。
2. 接入每架无人机当前 job、剩余时间和节点 frontier count。
3. 精确复现作者公式和图 Voronoi 所有权，不再使用本地任意加权。
4. 在作者原场景运行一条源码回归，验证节点、分区和作业转移。
5. 在至少两个 HM3D train 场景中，证明 GVP 与 auction 会产生不同分区、轨迹和覆盖足迹。

## 17. 公平迁移不能把算法核心抹掉

外部强基线与本文消融需要两种不同的公平性：

### 外部系统基线

GVP 可以使用自己的 MR-DTG、图分区和高层任务生成，因为那正是作者算法。所有方法必须共享的是传感器权限、初始状态分布、CF2X/PhysX、物理时间、静态/动态碰撞合同和最终指标。若强迫 GVP 只能在本文生成的同一个候选池里打分，可能会抹掉它的核心差异，最终只剩 5.9% 的选择变化。

### 本文机制消融

`no_qd / planned_qd / realised_qd`、普通 RL / QD+RL、无 OGFR / 执行结果门控 OGFR 必须共享完全相同的候选池、训练交互预算和执行结果。这里比较的是本文机制，候选生成不能变化。

论文应同时给出：

- 系统级主表：算法忠实的 GVP 对本文完整方法；公共传感、执行和预算相同。
- 选择器级诊断表：在完全相同候选池上比较 auction、MARL-IPP、普通 RL 和 QD+RL。

这样既避免“不同候选池不公平”，也避免“同候选池把外部算法阉割掉”。

## 18. 本文无目标覆盖任务的论文级指标

主任务是：四架 CF2X 在未知 HM3D 室内几何中，只根据公开稀疏观测和成功投递的消息，在固定物理时间内安全地发现尽可能多的可飞自由体积。它不是 ObjectNav，也没有人工目标点。

主指标和必要辅指标应为：

| 类别 | 指标 | 作用 |
|---|---|---|
| 主指标 | Explored-Free-Flight-Volume-AUC_time | 比较整个物理时间内发现自由体积的速度，而不只看终点 |
| 终点覆盖 | Final explored free-flight volume fraction | 防止早期快但最终停滞 |
| 效率 | 新增自由体积/飞行距离、/能耗 | 区分盲目高速飞行和有效探索 |
| 协作 | 重复观测比例、各机独有新增体积、负载均衡 | 判断四机是否真正互补 |
| 三维性 | 高度带覆盖、垂直候选执行率、固定高度反事实差值 | 证明无人机和三维空间是必要的 |
| 安全 | 碰撞率、最小净空、守卫拒绝率、未跑满预算率 | 完整失败分母 |
| 通信 | 投递率、过期率、连通占空比、字节数 | 判断协作代价和断联影响 |
| 计算 | 每次决策墙钟和 P95 延迟 | 判断是否可在线运行 |
| QD 机制 | 档案占用、有效格数、planned-realised gap、错格率 | 证明 QD 是否真实作用，不是主任务得分 |
| RL 机制 | 学习曲线、选择熵、相对 auction 的改选率、候选 regret | 证明 RL 是否改变选择并带来收益 |

所有方法在相同场景、起点和执行种子上配对。报告场景层均值、95% bootstrap 置信区间、每场景散点和失败计数。不能拿 MARL-IPP 的 `% targets` 或 GVP 原场景的探索秒数直接与 HM3D 覆盖 AUC 横向排序。

## 19. 论文最可能被拒绝的原因

按严重程度排序：

1. **强基线身份不成立。** 若当前单步训练器被写成 MARL-IPP，或当前 94.1% 同 auction 的端口被写成 GVP，审稿人可以直接否定比较。
2. **自定义任务缺乏外部锚点。** HM3D 没有官方四机连续三维无目标覆盖榜单；必须给任务定义、场景筛选、分母、起点和指标的可复现 artifact。
3. **候选生成器决定上限。** 若所有方法只能从本文偏置候选池中选，QD+RL 的优势可能只是候选工程；需要系统级与同候选池两条比较。
4. **QD 没有真实作用。** 若三个 realised descriptor 退化、档案不改变后续选择或 planned-realised gap 很小，QD 只是存档包装。
5. **RL 没有真实作用。** 若训练后仍与 auction/frontier 选同一候选，或收益来自更多训练数据而不是策略，RL 主张不成立。
6. **多个机制叠加无法归因。** QD、RL、OGFR、SF、通信图和安全守卫同时变化，会让审稿人无法判断贡献来源。
7. **训练规模不可复现。** 单张 4090 上若依赖数月在线 PhysX 交互，论文即使跑完也很难被其他团队复现。
8. **仿真可信度不足。** HM3D 到 Isaac 的碰撞转换、CF2X 动力学、稀疏传感和同步通信是自建组合，没有实机主实验；必须做几何一致性、控制稳定性和失败审计。
9. **场景筛选偏差。** 只挑方法表现好的 HM3D 场景会被视为 cherry-picking；筛选只能依据预注册的可飞性和三维机会，不得依据方法得分。
10. **统计单位错误。** 把多个时间步或多个无人机当独立样本会夸大显著性；统计单位应是场景-起点-种子 episode 或场景层聚合。

论文最大的问题不是“没有最新算法名”，而是**当前尚未证明外部基线忠实、QD 改变选择、RL 学到有效策略，而且现有在线数据吞吐不足以支撑完整训练。**

## 20. 这么多人研究，凭什么本文可能做成

不能回答成“别人做不出来而我们更聪明”。目前没有证据支持这种说法。更准确的判断是：本文处在一个很窄、工程成本很高的交叉点，近邻工作通常只覆盖其中一部分：

- HM3D 工作多为地面目标导航或语义导航。
- 多 UAV 探索工作多用自建小场景、RotorS/Gazebo 或实机环境。
- QD 工作通常不处理连续物理执行后的候选错格。
- MARL-IPP 处理三维多机信息规划，但按目标映射奖励训练。
- GVP 处理无目标三维多机探索，但没有 realised-QD 和候选级 RL。

本文有可能成立的唯一理由是已经具备一些可组合的基础设施：合法 HM3D 资产、Isaac/CF2X 连续执行、公共稀疏观测、执行结果、计划/执行双账本、作者源码仓库和统一失败审计。它们降低了研究交叉点的工程门槛，但不自动产生理论创新或性能优势。

真正需要证明的四条证据是：

1. 计划描述符与真实执行描述符存在稳定、实质的差异。
2. 该差异会造成 planned-QD 错格、错误选择或后续 regret。
3. realised-QD 确实改变后续候选选择，并提高覆盖/效率或降低失败。
4. RL 在相同候选、相同执行结果和相同训练预算下，优于启发式选择，并与 QD 产生可归因的互补收益。

任何一条不成立，都必须收缩主张。我们“可能做成”依赖可证伪实验，而不是依赖方向稀少。
