## 1. 先给结论：这篇论文到底研究什么

Paper I 暂定题目：

> **AeroCityBench: Controlled Generalization under Target-Process Shift and Fleet Attrition in Physics-Grounded 3D Urban Search**

核心问题不是“我们能否自动造很多城市”，而是：

> 在统一三维几何、物理执行和确认合同下，目标空间过程、城市拓扑/尺度与机队减员如何改变多无人机搜索性能、失败机制和方法排序？

城市生成器是实现受控干预的实验仪器，不是论文的全部科研贡献。论文必须给出可重复的因素控制、可证伪假设、方法排序变化、难度解释和失败分析。若最终只得到“一行命令生成很多 USD”，应转为软件/数据论文，不冒充强算法或强科学论文。

本仓库和本对话只完成 Paper I，不提出 CCUQD，也不使用任何自有方法调 benchmark。自有方法研究已隔离到本地 `experiments/aerocity-method`，由新对话在 Paper I 合同约束下独立推进；其成败不得改变本 benchmark 的地图、目标、指标或 split。

## 2. 为什么撤回灾后伤员模型

相近工作通常采用五类目标定义：

1. 没有离散目标，只评价未知空间覆盖，如 FUEL、RACER、MARVEL、Explore-Bench；
2. 单目标或多目标均匀随机，如 Visual Drone Swarm Target Search；
3. 预定义隐藏位置或固定标记，如 STAR-Searcher 的 AprilTag；
4. 建筑窗口、ArUco 或其他语义对象，如 MRIPP Target Mapping；
5. Gaussian、热点或概率栅格，如 adaptive informative path planning；SAREnv 的经验 lost-person map 是少数领域化例子，但属于二维 wilderness SAR。

没有证据表明完整的“灾害类型 -> 建筑占用 -> 逃生 -> 坍塌 -> 伤员”因果链是三维多无人机 benchmark 的通行要求。没有真实城市灾害人员数据和专家校准时，这条链只会增加不可识别参数，并诱导方法拟合生成者偏见。

因此目标统一命名为 `evaluator-private search target`。目标可以代表 marker、parcel、opening cue 或待确认对象，但不得声称其位置服从真实伤员统计。完整证据与裁决见 `docs/目标模型与论文定位审查_2026-07-29.md`。

## 4. Paper I 的研究问题与可证伪假设

### RQ1：目标空间过程是否改变方法排序

- H1：控制布局、目标数量和 opportunity 后，`uniform_surface`、`clustered_surface`、`height_stratified` 仍产生显著 method x process interaction。
- 反证：交互效应接近零，排名置信区间高度重叠，或差异完全由 raw target count 解释。

### RQ2：无故障性能能否预测减员韧性

- H2：F0(N) 的 nominal 排名不能可靠预测 Fk(N) 的 paired resilience loss 排名。
- 反证：无故障性能近乎完全预测单/双机损失表现，故障 track 没有新增测量信息。

### RQ3：二维量能否解释三维难度

- H3：地图面积、2D built ratio、2D coverage 和 raw target density 不能充分解释 confirmed-recall AUC；三维可见性、垂直跨度和观测机会具有增量解释力。
- 反证：加入三维特征后，交叉验证解释力没有稳定提高。

### RQ4：opportunity normalization 是否提高可比性

- H4：在布局和目标过程变化下，opportunity-conditioned recall 的方差与目标数量敏感性低于 raw recall，同时保持对方法质量的区分。
- 反证：归一化指标压平真实差异、对 witness 阈值极敏感或跨 simulator rerun 不稳定。

### RQ5：程序化多样性是否是真多样性

- H5：祖先级 split 后，test topology/scale 在道路图、建筑形态、可飞空间和遮挡特征上与 train 可分，但不能从无关资产颜色或公开 metadata 中预测。
- 反证：仅换 seed，图结构近重复；或一个 shortcut classifier 通过公开字段识别 split。

## 5. Paper I 的贡献边界

计划贡献：

1. 一个开放、确定性、物理几何一致的三维多无人机搜索生成器；
2. 一个把 target-process shift 与 fleet attrition 作为受控因素、并保持三维观测确认合同的城市搜索评测；是否具有“首个”地位必须经投稿前系统检索，当前不作该主张；

## 7. 场景尺寸、效率与难度

旧 224/288 m 高频训练方案失活。以 3 m/s 计算，160 m 对角线无绕障穿越下界已约 75 s，224 m 约 106 s；相机、碰撞、绕障、观察和返航会继续放大成本。

当前只冻结 pilot 搜索空间，不冻结正式 release：

| 用途 | 候选边长 | 状态 |
| --- | --- | --- |
| CI/debug | 48/64 m | 轻量正确性 |
| 高频 pilot/train | 80/96/128 m | v0.2 主候选 |
| core validation/test | 96/128 m，是否保留 160 m 由吞吐决定 | 待 G3 |
| scale OOD | 160 m | pilot 候选 |
| custom stress | 224 m | 非官方主表 |
| 288 m | 无 | 失活 |

规模不能只按 wall-clock 选。每个尺度同时报告：prim/collider 数、GPU 显存、相机吞吐、physics real-time factor、episode wall-clock、有效目标机会、planner 难度和 timeout 原因。若 160 m 不能在资源上限内达到预注册功效，scale OOD 降到 144/160 m 中可承受者，不靠减少 baseline seed 掩盖成本。

可选优化是编译大城市但 episode 只激活一个 AOI。采用前必须证明 AOI 边界、起点和 coarse prior 不泄漏目标区域，且 AOI 结果不能冒充全城搜索。

## 8. 城市语法与三维物理合同

生成顺序：

```text
road-graph ancestor
  -> constrained blocks and parcels
  -> component-based buildings
  -> rubble/obstacles and flyable volume
  -> visual assets through AssetRegistry
  -> CitySpec
  -> render USD + collision USD + surface index + coarse prior
  -> evaluator-private EpisodeSpec
```

必须覆盖而非随机堆盒子的结构：矩形、L/U 形、庭院、长条、塔楼裙房和退台；多种道路连通、街宽、街区长宽比、建筑高度混合、庭院/窄街/屋顶设备和有限瓦砾。

同一 CitySpec 是 collision、depth、occlusion、support surface、可飞域和 evaluator ray query 的唯一几何权威。视觉资产默认不得带入未登记 collider；需要物理作用时必须有显式 proxy、对齐 witness 和角色声明。

生成候选至少做四层去重：规范化内容 hash、道路图同构特征、连续几何最近邻、三维 flyable/visibility 特征。不同 seed 不是多样性证据。

## 9. 三维目标过程

### 9.1 合法支持面

v2 support 类为：

- `roof`：真实 component 顶面；
- `opening`：真实 component 侧面上的可检测 opening/marker 位；
- `entrance`：明确入口锚点；
- `rubble`：瓦砾顶面或之后经 witness 验证的边缘位。

禁止从建筑 footprint 外接矩形生成任意 facade 点。每个目标必须记录 component/surface lineage、三维坐标、法向、允许观测锥和 offset，并通过 CPU 与 Isaac ray witness。

### 9.2 三类受控过程

- `uniform_surface`：在合法 surface sites 上均匀抽样；
- `clustered_surface`：按三维 anchor 距离核聚簇；
- `height_stratified`：显式控制 `<4/4-12/12-25/25-40/>=40 m` 高度带。

核心 episode 不强制每局覆盖所有高度或所有 support 类。强制 3/4 类目标会制造人工规律。只有 height-stratified 过程承担预注册高度覆盖合同。

### 9.3 目标数量不是面积函数

每个候选 target 先计算：合法 view 数、可见立体角、最短确认成本、遮挡率、与其他目标共视数、可达性和同类 distractor 数。随后用 planner 与 oracle pilot 决定目标数量和预算。

拒收条件包括：

- 无 N1/N2 观测机会；
- 单个普通 viewpoint 可确认过高比例目标；
- 某一 support/高度确定性暗示存在目标；
- 目标太少导致所有方法饱和，或太多导致所有方法 timeout；
- 起点到目标的最近距离分布退化；
- clustered 与 uniform 的空间统计不可区分。

## 10. 机队减员与故障合同

机群数量按科研问题分层，不能用一个数字覆盖全部实验：

| Track | 机群规模 | 矩阵范围 | 要回答的问题 |
| --- | --- | --- | --- |
| `core-search` | `N=4` | 完整 10--14 基线矩阵 | 标准搜索、拓扑与目标过程排序 |
| `fleet-scaling` | `N={2,4,8}` | 代表性子矩阵 | 方法是否随 team size 稳健扩展 |
| `resilience` | `N=8, k={0,1,2}` | 代表性子矩阵与 oracle | 减员后的检测和重协调，而非仅容量损失 |
| `large-swarm-stress` | `N=12` | 条件性压力测试 | 仅在 Isaac 吞吐、通信与碰撞 pilot 通过后启用 |
| `CUSTOM` | `N=1..32` | 不进官方榜 | 用户自定义与工程探索 |

更多无人机不会自动证明 QD 有用。Paper I 不以 QD 校准规模；任何后续 QD 方法都必须用 repertoire coverage、跨 context 选择收益、selection regret 与切换/重评估成本证明其必要性，不能把 `N` 大当作理论证据。

v1 mandatory interventions：

- `none`；
- 单机 temporary communication isolation；
- 单机 hard loss；
- 双机 hard loss；
- 单机 `local_geometry` observation-channel loss。

定位漂移、动力退化、false alarm 与 compound cascading failure 先作为 optional stress。只有 mandatory 轨完成后才扩展。

每个故障组共享完全相同的 layout、targets、starts、smoke、基础通信和能量：

```text
F0(8): 八架且无故障
Fk(8): 八架起飞，中途损失 k=1/2 架
F0(8-k): 从开始只有 7/6 架
Oracle: fault-aware centralized reassignment
```

前两者估计 paired attrition effect；`F0(8-k)` 区分容量损失与重协调损失。当前 v2 pilot 已以八机生成 F0/Fk EpisodeSpec 配对，`F0(8-k)` 和 oracle 仍属于 evaluator/baseline 下一步，不得声称已经实现。

方法不能读取 `fault_spec` 或 failed agent IDs。只能从心跳、消息缺失、传感器质量、能量和运动反馈形成 health belief。hard-loss 残骸是否保留 collider 必须按故障类型冻结；无论哪种选择都要报告二次碰撞风险。

## 11. 任务视图、观测能力、飞行与确认 ABI

### 11.1 同一 CitySpec 的三个任务视图

1. `exploration-3d`：无离散目标，评价可飞体积/表面观测覆盖、时间、能量与安全，使 FUEL、RACER、MARVEL 和 frontier 方法无需伪造 detector 即可接入；
2. `geometry-search-3d`：Paper I 主任务，目标由 evaluator-private 几何证据确认，隔离搜索规划与对象识别；
3. `perception-search-3d`：optional，目标具有可见 marker/parcel/opening cue，评价 detector 与搜索闭环，独立分榜。

三者是 task view，不是新的 layout split；共用相同 CitySpec 和物理世界，避免任务数乘地图数。`perception-search-3d` 未完成 detector 数据、标注和标定前不得拖延 geometry 主论文。

### 11.2 五级 observation capability

| Tier | 方法可见信息 | 典型适配 | 排名规则 |
| --- | --- | --- | --- |
| `T0_state_prior` | 本机状态、时间/能量、合法 coarse prior | sweep、known-map planner | 同 tier 比较 |
| `T1_occupancy_voxel` | T0 + 局部/共享 occupancy 或 voxel 更新 | frontier、auction、部分 MARL | geometry 榜 |
| `T2_range_fov` | T0 + 有限 FoV range/ray/point observation | LiDAR/FoV planner | geometry 榜 |
| `T3_rgbd` | T0 + 标定 RGB-D 与允许的局部地图 | ego-depth/visual policy | T3 单榜或等信息 geometry 榜 |
| `T4_full_perception` | T3 + 方法自己的 detector/semantic output | end-to-end target search | perception 榜 |

高 tier 不等于更强算法，不同 tier 禁止混成一个排名。每个提交必须写入 observation-profile hash；同一论文可提交多个 tier，但 checkpoint、训练预算和结果必须分开。RGB-D 因三维局部建图、避障和视觉方法兼容性而保留，但不是所有 baseline 的强制 tensor 输入。

### 11.3 飞行与动作合同

官方比较聚焦高层多无人机搜索规划，所有方法共享低层控制器、轨迹跟踪、collision guard 和传感器合同。

速度 profile 必须绑定完整动力学而非单一数字：水平/垂直速度、加速度、制动距离、yaw rate、相机率和最小净空。

- `standard`：3 m/s，已有 FlightBench 与旧 Isaac 证据，作为当前 official pilot；
- `inspect`：1.5 m/s，只用于近障/观察诊断；
- `fast_unvalidated`：约 5 m/s，只有通过原生制动、近障、geometry confirmation 与可选 detector 标定后才能成为正式 track。

旧代码慢的主要原因之一是短 transit waypoint 后强制停稳。新 timing contract：transit 连续通过；仅 frontier/observation/hold 执行 settle/dwell；规划器、Isaac executor、admission 和 receipt 使用同一 timing model ID。

### 11.4 geometry-search 确认合同

纯欧氏距离自动确认永久禁止，因为会允许穿墙、背向相机和猜坐标成功。候选 detection 必须绑定 `agent_id/event_time/source_observation_id`，evaluator-private witness 同时检查：冻结 range、水平/垂直 FoV、无遮挡 LOS、support surface 朝向、最小 dwell/合法 observation action、事件时效与去重。当前 3 m、68°×51°、0.5 s 只是 pilot 候选，须做 2/3/5 m 与 FoV/dwell 敏感性后再冻结。

目标确认必须经过 N0--N5：真值存在、几何机会、传感器机会、合法动作、原生执行、evaluator 确认。方法自报 detection 不能直接增加 confirmed target；缺少 `source_observation_id` 的事件 fail closed。

### 11.5 perception-search 确认合同

T4 方法必须输出真实 detector event，单独报告 frame/event precision、recall、PR-AUC、calibration、latency、距离/角度/遮挡分层以及最终任务 AUC。geometry oracle 不得自动补全 detector 失败，perception 结果不得和 geometry 主榜混排。

## 12. 评价指标：分层报告，不造总分

### 12.1 主任务指标

Paper I 唯一主质量指标候选：时间归一化 `confirmed-recall AUC`。最终 recall、precision、F1、time-to-first-confirmation、time-to-k% recall 和 mission completion 为 secondary。

同时报告 `opportunity-conditioned recall`，但在 H4 通过前不能取代 raw confirmed recall。

### 12.2 减员主效应

主韧性效应：

```text
paired resilience loss = AUC_fault - AUC_no_fault
```

另报 recovery regret、time-to-detect、漏检/错误隔离、首次合法重分配时间、稳定重分区时间、orphan region、重复覆盖、二次损失和幸存机返航率。

### 12.3 安全、资源与协同

- 环境/UAV 碰撞、最小净空、越界、硬约束违反；
- 幸存 UAV return rate、受损 UAV 安全处置；
- 能量、路径长度、wall-clock、每目标成本；
- planning latency 的 median/p95/p99、deadline miss；
- 通信 bytes、packets、drop、stale-message rejection、断连时间；
- workload Jain/Gini、重分配率和重复搜索率。

### 12.4 三维公平性与泛化

- 按 altitude band、support class、opportunity quantile 的 worst-group recall；
- IID 到 topology/target-process/scale 的绝对下降；
- 排名 Kendall/Spearman 稳定性与 bootstrap 区间；
- 每个 layout ancestor 的 failure spectrum。

安全指标是硬约束，不和 recall 任意加权。排行榜分别给质量、安全、韧性和资源表，不发布不透明总分。

## 13. Paper I 基线与兼容层

基线不以名字数量取胜，而以方法家族覆盖、真实闭环执行和公平权限取胜。正式主表以 10--14 个通过 admission 的 adapter 为上限；fleet-scaling 与 resilience 只跑预注册代表子矩阵。每个主榜至少包含一个非学习方法、一个学习方法和一个诊断上界。

### 13.1 非学习与规划

1. 2D lawnmower/sweep（仅作 2.5D/projection 下界诊断）；
2. 3D volumetric sweep；
3. nearest frontier；
4. information-gain frontier；
5. decentralized auction/market allocation；
6. Voronoi/partition coverage；
7. FUEL、RACER、FALCON/EPEE 风格强三维系统中至少两个许可证与 ABI 均可成立的实现；
8. STAR-Searcher/target-search planner 风格方法。

### 13.2 学习与协同

9. IPPO；
10. MAPPO；
11. RMAPPO；
12. MARVEL-style graph communication policy；
13. Visual Drone Swarm 或 MRIPP-style 方法，仅在对应 sensor/task view 权限成立时进入。

### 13.3 诊断上界与下界

- random-safe 下界；
- centralized assignment oracle；
- oracle map/information-gain upper bound；
- fault-aware oracle。

诊断项不和可部署方法混排名。若某开源方法无法满足相同 observation/action contract，报告 incompatibility，不为凑数量偷偷给 oracle 输入。

提供 `PlannerAdapter`、PettingZoo ParallelEnv 风格多智能体接口、`GymnasiumFleetWrapper`、`ROSBridge` 和 `ReplayAdapter`。适配器只转换格式，不能升级可见信息；import 成功、离线 replay 或非空 depth 都不等于闭环 baseline 成立。

每个 adapter 锁定 upstream commit、许可证、容器、训练步数、environment interactions、wall-clock、网络容量、seed、消息预算、planner deadline、observation tier 和失败分母。学习方法允许 CTDE，但执行端只能读取其声明的 decentralized projection。所有方法共享相同低层 controller、安全 guard、simulator 和同 tier evaluator；geometry 主榜不强制共享 RGB detector。

## 14. 统计设计与防伪独立

独立单位是 layout ancestor，不是 target、frame、time step，也不是同布局重复 episode。模型采用 layout-level paired summaries 或层级模型，method、process、fault、topology 为固定效应，ancestor/layout 为随机效应。

主要分析：

- H1：method x target-process interaction 和方法排序区间；
- H2：paired Fk-F0 差值、F0(N-k) 分解和 rank correlation；
- H3：2D-only 与 2D+3D difficulty model 的 nested/held-out 比较；
- H4：raw 与 opportunity-normalized 指标的方差、敏感性和排序保持；
- 多方法总体用 performance profile/IQM 与 stratified bootstrap，不只报均值。

正式样本量由 pilot 的 layout-level 方差、最小有意义效应 MDE、alpha、目标功效和资源上限决定。不能通过增加同一 layout 的 episode 冒充更大 n。若预算不够，应缩小主张或 track，而不是删困难 seed。

预注册同时冻结 exclusions、timeout、missing data、collision failure、multiple comparisons、confidence interval 和代码 hash。正式结果必须包含失败 episode。

## 15. 公开/私有边界与防过拟合

方法可见：传感器流、合法 coarse prior、允许的本地状态、合法消息、时间/能量和 ActionToken feedback。

方法不可见：

- split、family、ancestor、holdout/OOD 标签；
- generation/episode seed；
- target process、目标数量/位置、support sites 和 witness；
- exact FaultSpec、affected agent IDs 和 onset；
- evaluator receipt 的私有部分。

公开 CitySpec 工件可以重建城市，但正式 evaluator 不把带 split lineage 的 index 挂载给方法容器。每个公开 JSON 运行 forbidden-key scan，并训练 shortcut probe；若公开 metadata 能高精度预测 split，发布失败。

正式 test 的私有 EpisodeSpec 由外部 evaluator 持有。开发 test 与 blind test 必须祖先隔离；每个容器一次提交，超出次数进入公开 submission log。

## 16. 一行复现与用户自定义

官方目标接口：

```powershell
aerocity-bench build --release .\configs\releases\v0.2-pilot.json `
  --asset-root E:\md_qd_swarm_assets --output E:\aerocitybench\pilot
aerocity-bench validate E:\aerocitybench\pilot
```

配置拆成四层：

- `GeneratorProfile`：尺度、道路、built ratio、高度、障碍、资产；
- `TaskProfile`：fleet count、target process、通信、烟雾、能量、故障；
- `DynamicsProfile`：速度、加速度、yaw、相机、clearance；
- `BenchmarkProfile`：官方冻结组合与 hashes。

目标 custom 接口：

```powershell
aerocity-bench build --release custom.json --set city.extent_m=128 `
  --set city.built_ratio=0.38 --set fleet.count=8 `
  --set dynamics.active_profile=standard
```

当前 CLI 已支持配置文件，不支持 `--set`；这是明确未完成项。非法参数必须 fail closed，禁止静默截断、自动换 seed 或自动降低目标数。CUSTOM 产物必须标记 custom，不能与 official leaderboard 混报。

一行生成的可复现定义是规范化结构和 hash 相同，不要求不同 GPU renderer 像素逐位相同。发布记录 Python、Isaac Sim/Lab、driver、GPU、asset registry、converter 和 schema 版本。

## 17. Isaac Sim 原生验收

每类代表布局必须由 Isaac Sim 5.1 原生打开并保存：overview、street-level、roof-level、depth、semantic segmentation 和 evaluator-private target overlay。截图只证明可视健康，不证明任务成立。

原生 gate 还必须执行：

- collider/visual alignment ray test；
- 无穿透 takeoff、连续 transit、近障制动、observation dwell 和 return；
- 合法/非法 detection 的 N0-N5 receipt；
- core 四机与 resilience 八机同时飞行、UAV-UAV collision 和相机/物理吞吐；
- temporary comm、hard loss 1/2、`local_geometry` observation-channel loss；
- heartbeat-only failure detection，确认方法未读 fault truth；
- city switch 后 collider、sensor/contact buffer、packet queue、target、fault 和 RNG 无残留；
- fixed scene 多次 rerun 的性能、geometry-confirmation 容差与可选 detector 容差。

截图抽样按尺度 x topology x density x height x target process 分层，不能只挑漂亮地图。任何空画面、悬浮目标、过密遮挡、大片空地、树尺度错误、collider 错位或目标一眼过量都进入 failure ledger。

## 19. 自有方法接口边界，而非本仓库任务

旧 QD/RL 工程代码没有被删除，但它不属于 AeroCityBench 的论文贡献或执行阶段。QDAC、DCRL、MIQD、Uncertain-QD、Extract-QD、CARE、层级 QD damage recovery、COPA 和 open ad-hoc teamwork 已使“QD + RL + SF + 多智能体 + 故障”的组合主张高度重叠；旧 CCUQD 名称和三项标准统计保证不再作为既定理论贡献。

本仓库对 Paper II 只冻结以下接口：公开 CitySpec/Episode observation projection、task/action/message/timing ABI、train/validation 权限、blind evaluator、receipt/failure ledger 和 baseline budget accounting。方法理论、训练代码、novelty matrix 与外部 benchmark 实验全部位于本地 `experiments/aerocity-method`。

当前唯一值得优先查证、但尚未成立的新方法假设是：在 active agent set 和通信图变化、故障身份只能从延迟 health evidence 推断时，使用 permutation/set-equivariant 团队责任组合算子，把三维搜索责任 repertoire 重组给存活成员，并研究 **agent-deletion stability of composable responsibility repertoires**。暂定代号 SCRR 只是检索标签，不是既定算法。若 CARE/COPA/ad-hoc teamwork/fault-tolerant MRTA/MIQD/普通 graph MAPPO + dropout + greedy reassignment 已解释其核心收益，该方向必须停止或重构；不得把 benchmark 改得只对它有利。

## 23. 立即停止或回退条件

任一情况出现必须回退：

- 公开文件可预测 split/family/fault/target truth；
- collision、local geometry observation、support 或 evaluator ray 几何不一致；
- uniform/clustered/height-stratified 空间统计不可区分；
- 目标普遍无机会或一眼确认过量；
- 机队故障真值直接暴露给方法；
- reset 后有 collider、packet、target、fault 或 RNG 残留；
- 160 m 资源成本破坏预注册功效；
- baseline observation/action/budget 不公平；
- 结论依赖 episode 伪独立或删除失败 seed；
- 第三方无法一行重建；
- 不同 observation tier 被混榜，或某 adapter 通过转换获得额外真值。
