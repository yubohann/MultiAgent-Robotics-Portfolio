# AeroCityBench 主题与评测器私有真值说明

版本：`说明文档-v1`

日期：2026-07-29

状态：`试验性原型阶段 / 非正式发布`

适用仓库：`yubohann/AeroCityBench`

## 1. 先给结论

AeroCityBench 的主题是：

> 在具有真实三维遮挡、碰撞、飞行动力学、通信和能量约束的程序化城市中，评测多架无人机协作搜索隐藏三维目标的能力。

它最重要的科研问题不是“能否生成很多城市”，而是：

> 一个方法覆盖了很多区域，是否真的意味着它能够从正确距离、正确方向和正确高度发现隐藏目标？

AeroCityBench 不是普通的图片数据集，也不是单纯的三维模型集合，而是由以下部分共同组成的开放基准测试体系：

- 程序化三维城市生成器；
- 无人机物理执行环境；
- 隐藏三维目标任务；
- 评测器私有真值；
- 标准动作、观测和通信接口；
- 训练集、验证集和测试集划分；
- 基线方法适配器；
- 指标、统计和盲测协议。

## 2. 什么是“评测器私有真值”

“评测器私有真值”是 `evaluator-private ground truth` 的中文表述。

它的含义是：

> 某些信息只有负责判定和打分的评测程序知道，参赛算法在运行期间永远不能读取。

可以把它理解为一次考试：

- 城市、传感器数据和任务规则是试卷；
- 无人机算法是考生；
- 目标位置、故障时间和正确判定条件是标准答案；
- 评测器是阅卷程序。

如果把标准答案交给算法，算法就可以直接飞向目标，搜索任务将退化为访问已知坐标，整个评测失去意义。

### 2.1 评测器私有信息包括什么

正式测试时，算法不能看到：

- 目标总数；
- 每个目标的三维坐标；
- 目标位于哪栋楼、哪个屋顶或哪个立面；
- 目标属于均匀、聚簇还是高度分层分布；
- 所有可能的目标候选位置；
- 哪些位置能够合法观察目标；
- 测试地图属于哪种测试类别；
- 城市生成随机种子；
- 目标生成随机种子；
- 哪架无人机将发生故障；
- 故障发生时间；
- 故障持续时间；
- 评测器内部使用的射线、视野和遮挡判定结果。

### 2.2 算法允许看到什么

算法只能看到任务合同允许的信息，例如：

- 无人机自身状态；
- 允许使用的粗略城市先验；
- 当前传感器观测；
- 时间和剩余能量；
- 允许接收的队友消息；
- 已经合法确认的目标信息；
- 无人机自身能够观测到的健康、通信和运动异常。

### 2.3 目标如何被合法确认

算法不能直接读取目标坐标，也不能仅仅靠飞到目标附近完成确认。

正确流程是：

```text
算法决定飞往某个区域
  -> 无人机在物理仿真中实际飞行
  -> 算法发出观察动作
  -> 传感器生成带编号和时间戳的观测
  -> 评测器使用私有目标真值检查这次观测
  -> 满足全部条件时确认目标
  -> 向算法返回合法确认结果
```

评测器至少检查：

- 无人机与目标的距离是否在允许范围内；
- 目标是否位于传感器水平和垂直视野内；
- 无人机是否朝向目标；
- 目标与传感器之间是否被建筑或障碍物遮挡；
- 是否从目标允许观察的一侧进行观察；
- 无人机是否完成要求的稳定观察时间；
- 观察数据是否足够新，没有使用过期观测；
- 同一目标是否已经确认，避免重复计数；
- 这次确认是否绑定到真实产生的传感器观测。

因此，下列行为都不能成功：

- 隔着墙靠近目标；
- 从建筑背面确认正面目标；
- 在高楼下方确认屋顶目标；
- 猜测一个坐标并直接上报；
- 使用过期相机或距离观测；
- 重复上报同一个目标；
- 读取评测器内部文件。

### 2.4 为什么必须使用评测器私有真值

它主要解决四个问题。

1. 防止答案泄漏：如果测试目标坐标公开，任务将从搜索退化为坐标访问。
2. 防止针对测试集过拟合：算法不能根据地图名称、测试类别或随机种子切换专门策略。
3. 公平比较不同方法：规划、强化学习和多无人机协同方法都必须通过同一个评测器确认目标。
4. 支持盲测：正式测试可由独立评测服务器持有目标和故障真值，参与者只提交冻结算法。

## 3. AeroCityBench 不是什么

AeroCityBench 不是：

- 无人机竞速数据集；
- 单纯的路径规划地图；
- 只有图片和标注的视觉数据集；
- 把三维城市压成二维栅格的覆盖任务；
- 真实灾后伤员分布模型；
- 仅仅依靠接近距离触发目标的游戏环境；
- 专门为后续自有强化学习或质量多样性方法设计的私有测试场；
- 因为使用了 Isaac Lab 或 Isaac Sim 就自动具有创新性的项目。

目标可以代表：

- 待确认标记；
- 包裹或物资；
- 建筑开口附近的线索；
- 屋顶、入口或瓦砾附近的待搜索对象。

在没有真实伤员数据和专家校准之前，不能宣称这些目标符合真实灾后伤员统计规律。

## 4. 最核心的科研特点：覆盖不等于搜索

传统探索方法主要评价：

- 探索面积；
- 地图覆盖率；
- 未知区域减少速度；
- 路径长度；
- 完成覆盖所需时间。

但是，无人机飞过一栋楼旁边，不代表它真正观察到了楼顶目标。

例如：

- 无人机从楼下经过，二维地图上已经覆盖该区域，但没有看到屋顶；
- 无人机位于目标附近，但中间有墙；
- 无人机飞得太高，目标超出有效观察距离；
- 无人机朝向错误；
- 无人机没有稳定观察足够时间；
- 多架无人机重复搜索同一街区，覆盖率很高，但有效确认很少。

AeroCityBench 将同时记录：

- 空间覆盖程度；
- 合法目标观察机会；
- 实际确认目标；
- 没有发现目标的具体原因；
- 不同高度和不同目标类型的搜索表现。

由此检验：

> 覆盖率排名最高的方法，是否仍然是三维目标搜索中排名最高的方法？

## 5. 开放的程序化三维城市

城市不是手工固定制作，而是按照受约束的城市生成规则构建：

```text
生成道路图
  -> 划分街区和地块
  -> 生成建筑组件
  -> 生成屋顶设备和障碍物
  -> 生成瓦砾和道路阻断
  -> 计算可飞空间
  -> 加载开放许可证资产
  -> 编译视觉场景和碰撞场景
  -> 生成隐藏目标任务
```

城市应当支持：

- 不同地图尺寸；
- 不同建筑密度；
- 不同道路宽度；
- 不同道路连接关系；
- 低层、中层和高层建筑混合；
- 矩形、长条形、L 形、U 形、庭院和退台建筑；
- 窄街、庭院、屋顶设备和局部障碍；
- 不同起飞区域；
- 不同目标空间分布；
- 不同无人机数量和飞行参数。

程序化生成不能只是随意堆放方块。每张地图都必须通过密度、连通性、可飞空间、遮挡、目标机会和近重复检查。

## 6. 三维目标分布

目标不能只在二维平面上随机生成，而应位于真实三维支持面上，例如：

- 建筑屋顶；
- 建筑立面上的合法标记位置；
- 建筑入口；
- 瓦砾顶部或边缘；
- 不同高度的合法观察区域。

### 6.1 表面均匀分布

目标按照合法三维表面所代表的面积采样，避免某类离散候选点因为数量多而被过度抽中。

### 6.2 三维聚簇分布

目标在部分建筑、街区或高度附近形成空间聚簇，用于测试方法面对空间热点时的表现。

### 6.3 高度分层分布

显式改变低空、中层、高层和超高层目标的比例，用于评价方法的垂直搜索能力。

### 6.4 每个目标必须具有的证据

每个目标必须记录并验证：

- 三维坐标；
- 所属建筑或障碍物；
- 所属真实表面；
- 表面法向；
- 允许观察方向；
- 至少一个合法观察位置；
- 可达性和遮挡；
- 与其他目标的空间距离；
- 可见立体角；
- 最短确认成本。

## 7. 物理几何一致性

同一份城市定义必须同时生成：

- 视觉模型；
- 碰撞模型；
- 深度或距离观测；
- 遮挡判定；
- 可飞空间；
- 目标支持面；
- 评测器射线检查。

不能出现：

- 画面里有楼，碰撞模型里没有；
- 深度观测看到一面墙，射线判定却可以穿过；
- 目标悬浮在空中；
- 装饰模型带入未登记碰撞体；
- 评测器认为道路畅通，物理仿真中却存在障碍。

基础建筑可以使用简单几何体，但碰撞、遮挡、深度和评测器必须来自同一几何权威。

## 8. 多无人机协作

基准测试计划支持不同规模的无人机群：

- 核心搜索使用四架无人机；
- 规模测试使用两架、四架和八架；
- 韧性测试从八架无人机开始；
- 十二架及以上只有在仿真吞吐和通信测试通过后才进入压力测试；
- 用户自定义模式可以支持更广泛的无人机数量。

重点评价：

- 如何划分城市区域；
- 如何分配搜索任务；
- 如何减少重复搜索；
- 如何协调高层和低层搜索；
- 如何处理通信延迟；
- 如何避免无人机之间碰撞；
- 如何平衡不同无人机的工作量；
- 无人机数量增加后性能是否真正提高。

无人机数量多并不自动证明质量多样性方法有用。质量多样性属于后续方法论文，需要独立证明。

## 9. 无人机失联和减员

韧性任务可以包括：

- 临时通信隔离；
- 单架无人机永久失联；
- 两架无人机永久失联；
- 局部几何观测通道失效；
- 后续可选的定位漂移、动力下降和错误告警。

算法不能直接知道哪架无人机被评测器判定为故障，只能根据以下可观测证据形成判断：

- 心跳消失；
- 消息长期未到达；
- 运动反馈异常；
- 传感器质量下降；
- 能量或控制状态异常。

正式比较应包含：

```text
相同数量且无故障
相同数量起飞但中途损失一架或两架
从开始就减少一架或两架
提前知道故障真值的集中式诊断上界
```

这样可以区分：

- 少了无人机造成的容量损失；
- 故障检测太慢；
- 任务重新分配太慢；
- 通信网络分裂；
- 幸存无人机重复搜索；
- 故障无人机残骸造成二次碰撞。

韧性损失定义为：

```text
韧性损失 = 无故障时的确认召回率时间曲线面积
         - 发生故障时的确认召回率时间曲线面积
```

机群减员具有科研价值，但在小规模试验尚未证明它提供独立方法排序信息前，不应压过“覆盖不等于搜索”这一核心主题。

## 10. 训练集、验证集和测试集

数据划分不能只是使用不同随机种子，应当按城市生成祖先和结构规则隔离。

### 10.1 训练集

用于训练学习方法和调整参数，只包含训练阶段允许使用的城市结构和目标过程。

### 10.2 验证集

使用未见过的城市祖先，用于选择模型和参数，但仍属于允许开发的范围。

### 10.3 同分布测试集

城市规则与训练集相近，但布局、目标和祖先完全不同。

### 10.4 拓扑分布外测试集

包含训练阶段没有出现过的道路连接和建筑组合方式。

### 10.5 目标过程分布外测试集

保持城市几何和基础条件不变，只改变目标空间分布规律。

### 10.6 尺度分布外测试集

使用更大或结构更复杂的城市。

### 10.7 机群韧性测试集

使用严格配对的无故障和故障任务。

正式测试目标、故障身份和测试类别由私有评测器持有。

## 11. 如何兼容更多已有方法

基准测试计划兼容：

- 二维覆盖方法；
- 三维体积扫描方法；
- 最近前沿方法；
- 信息增益前沿方法；
- 分区和市场竞价方法；
- 三维无人机探索规划方法；
- 独立强化学习；
- 多智能体强化学习；
- 图通信协作方法；
- 多无人机目标搜索方法；
- 集中式诊断上界。

但不同信息权限的方法不能混在同一个排行榜中。

例如，以下方法具有不同的信息条件：

- 使用完整地图的方法；
- 使用粗略地图的方法；
- 使用局部占据体素的方法；
- 使用有限视野距离观测的方法；
- 使用彩色图像和深度图的方法。

每种方法必须声明自己的信息权限、动作权限、通信预算、训练预算和运行时间预算。正式主榜只冻结一个统一的三维几何搜索权限，其余权限作为独立兼容轨道。

## 12. 评价指标

### 12.1 核心质量指标

核心质量指标是：

> 随任务时间变化的已确认目标召回率曲线面积。

它同时反映：

- 是否找到目标；
- 找到目标的速度；
- 是否只在任务结束前集中找到目标；
- 整个任务过程的搜索效率。

### 12.2 搜索指标

- 最终确认目标比例；
- 首次确认时间；
- 达到一定召回率所需时间；
- 任务完成率；
- 不同高度目标的召回率；
- 不同支持面目标的召回率；
- 最困难目标组的召回率；
- 空间覆盖表现与目标确认表现之间的差距。

### 12.3 安全指标

- 与建筑碰撞次数；
- 无人机之间碰撞次数；
- 最小安全距离；
- 越界次数；
- 硬安全约束违反；
- 幸存无人机安全返航率。

### 12.4 资源指标

- 路径长度；
- 能量消耗；
- 每确认一个目标的成本；
- 物理仿真时间；
- 算法运行时间；
- 规划延迟；
- 超时比例。

### 12.5 协作指标

- 重复搜索率；
- 未分配区域；
- 工作量均衡；
- 任务重新分配次数；
- 通信量；
- 丢包和过期消息；
- 无连接持续时间。

质量、安全、资源和韧性应当分别报告，不能任意加权成一个不透明的总分。

## 13. 开放性、许可证和复现性

公开发布内容应包括：

- 城市生成代码；
- 场景配置；
- 城市定义格式；
- 任务接口；
- 无人机动作和消息接口；
- 公开训练与验证评测器；
- 资产登记表；
- 许可证清单；
- 文件校验值；
- 基线适配器；
- 数据卡和基准测试说明；
- 失败记录；
- 软件版本和硬件要求。

正式公开场景只使用：

- 原创基础几何；
- 允许再分发的零版权限制资产；
- 允许署名再分发的开放资产。

Isaac Lab 的开放代码许可证不自动覆盖 Isaac Sim 或官方资产库中的模型和纹理。未经逐项许可证确认的官方资产只能用于本地诊断，不能随公开数据集重新分发。

## 14. 科研创新边界

不能把以下内容单独作为科研创新：

- 使用 Isaac Lab；
- 使用多架无人机；
- 使用程序化城市；
- 生成大量地图；
- 加入隐藏目标；
- 加入无人机失联；
- 提供一行生成命令。

真正可能成立的创新是：

> 在统一三维物理、观察动作和信息预算下，使用受控目标空间过程检验“覆盖表现能否预测目标搜索表现”，并证明现有方法的排序、失败机制或方法选择建议发生稳定、可重复的变化。

如果小规模试验发现覆盖表现几乎完全预测目标搜索表现，或者目标过程变化不改变任何方法结论，则核心科研假设被证伪。此时应将项目诚实定位为开源软件或数据资源，而不能通过继续增加地图和指标掩盖负结果。

## 15. 当前完成状态

截至 2026-07-29，AeroCityBench 仍处于试验性原型阶段。

已经具备或部分具备：

- 程序化城市生成原型；
- 三维目标候选和三类目标过程原型；
- 评测器私有文件划分；
- 故障任务静态规格；
- 公开文件隐私和完整性审计；
- 小规模构建和软件合同测试。

尚未全部完成：

- Isaac 原生闭环评测器；
- 真实运行时故障注入；
- 目标观察机会编译器；
- 完整的几何确认回执；
- 正式基线适配器；
- 大规模训练、验证和测试数据；
- 统计功效分析；
- 外部独立复现；
- 盲测服务器；
- 正式论文实验。

因此，当前不能把原型测试结果写成正式 benchmark 结论。

## 16. 最终定义

AeroCityBench 是：

> 一个使用开放程序化城市、物理一致三维几何、评测器私有目标和严格观察证据，对多无人机协作搜索、三维泛化和机群韧性进行统一评测的开放基准测试体系。

它最重要的科学问题是：

> 现有方法在覆盖率上表现优秀时，是否真的能够在未知目标分布、三维遮挡和真实飞行约束下有效发现目标？
