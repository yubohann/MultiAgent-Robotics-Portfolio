## 1. 普通论文目标与中心命题

### 1.1 暂定题目

> AeroCityBench: Physics-Grounded 3D Multi-UAV Search Beyond Coverage

题目允许在 pilot 后收缩，但不得在结果出来后扩大主张。

### 1.2 唯一主问题

> 在相同城市、时间、信息权限、控制器和物理预算下，传统 coverage 指标能否充分预测具有有限视场、遮挡、观察方向和停留时间约束的三维多无人机目标搜索表现？

主假设：coverage AUC 不能充分解释 evaluator-confirmed recall AUC；加入高度、法向、遮挡、合法观察机会和确认成本后，能够得到稳定的样本外增量或失败机制差异。

主反证：

- coverage 排名与 confirmed-search 排名高度一致；
- 三维特征没有样本外解释增量；
- 差异完全由方法权限、adapter tax、目标数量、生成器指纹或失败删除造成；
- 固定高度或二维策略接近完整三维方法。

若主假设被反证，不包装“排名反转”。可以降级为三维搜索软件/数据资源论文，但必须有稳定 release、真实下游使用价值和诚实的负结果。

### 1.3 次问题

> 在控制城市、目标数量、起点和预算后，目标空间过程是否改变方法表现、排序区间或失败类型？

普通论文只比较可控的 `uniform_surface`、`clustered_surface` 和 `height_stratified`。为了避免把“过程效应”和“未见过程 OOD”混为一谈：

- 用于主交互分析的三种过程都必须在训练/开发分布中出现；
- 目标过程 OOD 另用未见参数范围或未见过程族测试，单独报告；
- 不能把仅在测试阶段出现的 height-stratified 与训练可见过程直接解释为纯过程效应。

次问题不成立时不阻塞主问题论文，但不得继续把 target-process interaction 写成贡献。

### 1.4 明确不声称

- 不声称目标符合真实灾后伤员统计；
- 不声称使用 Isaac Sim/Lab 就等价于真实飞行；
- 不声称程序生成数量本身构成创新；
- 不声称提出新 RL、QD、VLM、VLA 或世界模型算法；
- 不声称兼容所有外部方法；
- 不声称普通论文版已经是长期社区 challenge；
- 不声称 schema-reserved 等于 adapter-implemented；
- 不声称 pilot 参数已经冻结。

## 3. Canonical geometry-search-3d / G2-I 合同

### 3.0 当前状态与版本边界

当前已实现的是 `G1_occupancy_voxel`。它只向方法提供粗略建筑先验、局部 occupancy 和安全天空聚合信息，适合未知空间探索；它**不是**一个已经合格的隐藏表面目标搜索主榜。原始完整表面扫描的公开运动下界约为每机 1,100--1,500 s，超过 300 s 的正式仿真预算；缩减后的 `sweep-3d` 只有 coverage diagnostic 意义，不能被称为 target-search baseline。

未来唯一候选的 geometry-search 主榜为 `G2-I`（`I` 指 inspection atlas，不等同于历史 `G2_range_fov` capability）。截至 2026-08-03，G2-I 已实现严格 L0 合同、mission sector、CPU 几何 admission、coarse/full prior 投影、Planner/JSONL process ABI、面积加权 footprint 计分和审计工具。v4 L0 bracket 中 private oracle 在 5/5 ancestor 全员返航且零碰撞；两个公开方法分别在 3/5、4/5 ancestor 非零，仍只属于 calibration。历史 v15 的 L1 和排名证据已因公开边界/schema 失效而退役；当前边界 v16 已完成三 ancestor、三方法公开四机 L1/L0 配对校准，但 `formal_score_eligible=false`，且 MARVEL 仍只有 12 秒二维接口诊断。不得读取 formal test，也不得开始 MAPPO、QD+RL 或任何自有方法的长训练。证据：`reason/benchmark-external-methodology-audit-20260802/current-boundary-l1-panel-20260803/cf2x-b-gate-verification-v16-current-boundary.json`。

### 3.1 任务过程

~~~text
reset
  -> 四机起飞
  -> 使用公开城市先验和目标无关公共检查图选择检查单元
  -> 方法发出显式 OBSERVE
  -> 形成带 timestamp 和 source_observation_id 的观测
  -> 私有评测器检查 range/FoV/LOS/normal/dwell/freshness
  -> 返回匿名 ConfirmationReceipt
  -> 去重并继续搜索
  -> 返航或到达固定任务时限
~~~

geometry 主榜使用确定性理想几何检测器，隔离搜索规划和对象识别。方法不能读取目标位置、support site、目标数量、目标过程、合法观察 witness 或测试标签，也不能猜目标 ID。

geometry 主榜不报告 precision、F1、PR-AUC 或 detector calibration。它们只属于未来 perception track。

### 3.2 公开与私有边界

`G2-I` 方法可见：

- 自身状态与冻结 coarse prior；
- 公共检查图：`coarse-regions` 只公开屋顶、立面、入口、瓦砾邻域等区域的 ID、类别、粗略边界、面积和高度带；`full-cells` 额外公开检查单元、姿态包络、显式表面几何与目标无关安全转场图。两个 prior 独立哈希、分别消融，不得混榜；
- canonical profile 允许的局部地图或传感器投影；
- 合法队友消息、时间、能量与预算；
- 已合法确认的匿名目标回执；
- 自身能够观察到的运动、通信和健康异常。

方法不可见：

- 目标总数、位置、ID、空间过程、support site、检查单元中是否有目标、私有合法观察位姿或 ray/LOS 真值；
- split、ancestor、OOD 标签与随机种子；
- 私有 evaluator ray 和合法 view；
- 未启用韧性轨中的私有 fault spec；
- 评测器原始内部文件。

检查图从 CitySpec 的**目标无关**结构派生，目标和匹配干扰点只在检查图冻结后由 evaluator-private 过程生成。任何把 target label、target count、support-site ID、private witness、候选点密度、split、seed 或由这些字段派生的统计量写入 atlas 的行为都使 release 失败。每一版 atlas 必须有 schema、compiler hash、CitySpec hash、公开字段审计、private-field rejection 测试和跨 target-process 不变性测试。

`G1-U` 仅公开粗略先验与局部 occupancy；它的任务是 `exploration-3d`，报告 free-space/地图覆盖、时间、能量和安全。`G2-I` 在 G1-U 可见信息外增加 atlas；它的任务是 geometry-search。二者不可混榜，也不得把 G1-U 方法的 confirmed recall 与 G2-I 主榜直接比较。

### 3.3 动作、回执与失败

v1.0 冻结以下高层动作：

- `GOTO_WAYPOINT`；
- `OBSERVE`；
- `HOVER`；
- `RETURN_HOME`；
- `SEND_MESSAGE`。

公共 ABI 最少包含 `TaskSpecPublic`、`ObservationPacket`、`ActionPacket`、`MessagePacket`、`ObservationReceipt`、`ConfirmationReceipt`、`ExecutionReceipt`、`FailureRecord`、`BudgetLedger` 和 `EpisodeSummary`。

episode、agent、sequence、timestamp、source_observation_id 和 hash 必须绑定。timeout、stale message、duplicate action、reset、collision 和 crash 都进入失败分母。

### 3.4 Canonical Execution Semantics

以下语义必须在任何 calibration 运行前写入 release 配置并由 evaluator 强制执行：

| 项目 | 普通版 canonical 语义 |
| --- | --- |
| 任务时钟 | simulated execution time 加 planning deadline overrun；计算不能获得免费暂停 |
| 任务预算 | `task_time_s = 300 s` 是仿真执行预算，不是每轮墙钟等待；Isaac capture 的 host timeout 只用于终止卡死进程，不进入算法得分 |
| 控制周期 | 固定周期；超时执行上一个安全动作或 HOVER，并记录 deadline miss |
| OBSERVE | 与移动动作互斥，要求连续 dwell；中断后重新累计 |
| 稳定阈值 | 线速度、角速度、姿态误差和位置漂移均低于配置阈值 |
| 观察冷却 | 同一 agent 两个新 observation 之间存在固定最小间隔 |
| 传感器几何 | 固定 body-to-sensor 外参、前向/上向轴、FoV 和可选云台范围 |
| 确认去重 | 每个 source observation、agent、target 最多产生一个 receipt；全队目标全局去重 |
| 碰撞 | agent 立即失效；质量分保留用于诊断，但存在硬碰撞的 run 不具正式安全排名资格 |
| 越界 | 动作拒绝并 HOVER；重复越界达到阈值后 agent 失效 |
| 返航 | 到时限必须位于 home volume；未返航进入失败和安全分母 |
| 通信 | 固定带宽、payload 上限、延迟、drop、TTL 和队列策略；禁止隐式全局共享 |
| 安全控制器 | 统一 action clipping 和低层 controller；所有干预写入 ExecutionReceipt |

OBSERVE 不能按每帧无成本滥发。默认要求 HOVER 或近似静止，dwell 只能由时间连续、姿态稳定、来源新鲜且 observation ID 唯一的帧累计。正式阈值在独立 calibration split 冻结。

目标有效性必须在方法运行前完成编译，至少绑定 support lineage、合法观察体积、动力学可达性和 evaluator witness hash。任何方法运行结果、碰撞或未发现事件都不得把目标重新判为 invalid。零有效目标 episode 禁止进入正式 release。

## 4. Canonical observation profile 与相机边界

### 4.1 当前 G1-U 与未来 G2-I

当前代码同时提供两个严格分轨：

> `G1-U`：本机状态 + 粗略先验 + 有限范围局部 occupancy voxel 更新 + 合法队友共享投影。

它使 frontier、FALCON 类探索器和 coverage 方法能在相同权限下较低成本接入，同时不提供完整真值地图；但它不足以让公开方法在 300 s 内系统覆盖私有的精细表面目标。`G1-U` 保留为 exploration/compatibility track。

普通论文的候选 geometry 主榜使用已实现但尚未放行的 `G2-I`：

> G1-U + 目标无关公共检查图 + 受 atlas 约束的检查单元状态/已检查历史。

`G2-I` 的 CPU 编译、public projection、mission-sector、footprint 几何、coarse/full prior 消融和 L0 calibration 已落地；公开四机 CF2X/L1、外部 upstream 闭环、split/OOD 充分 cohort、参数冻结和发布验证仍未完成。

`G2-I` 不提供精确全局 occupancy、目标候选点、目标概率、目标数、私有 support 或完美共享真值地图。历史 `G2` 的有限 FoV range/point capability 可作为一个独立传感器 profile 与 G2-I 组合，但不能将两者混作同一名称，也不得在未做权限等价验证时混榜。

禁止提供精确全局 occupancy、目标候选点、私有 support 或完美共享真值地图。

### 4.2 传感器几何必须保留，RGB 像素是可选输入

- Isaac 场景继续保留 RGB/depth 相机，用于几何一致性、回放、视频和未来 perception/VLA；
- geometry evaluator 必须使用与该相机 rig 相同的固定外参、视锥和时间戳；关闭 RGB 渲染不等于删除传感器几何；
- geometry 主榜默认不向方法提供 RGB；
- depth/range 可以作为局部 occupancy 的来源，但不能自动确认目标；
- RGB-D 权限进入独立 capability profile，不能与未来 G2-I geometry 主榜混排；
- 保存内外参、时间戳、延迟、丢帧和有效 mask，为后续扩展留接口。
- RGB/depth/instance segmentation 可用于 L2 视觉审查；逐实例可见性与每个起飞点的 marker 可见性均为审查硬门，其他 RGB 饱和颜色统计只作接触表可读性诊断，均不参与 geometry 评分。

### 5.2 生成器反规律黑名单与当前缺口

- building index 周期高度；
- 奇偶索引控制屋顶设备；
- 仅贯穿全图的正交道路；
- 瓦砾固定角点循环；
- 视觉资产固定复制和同心圆放置；

ordinary-v3 已不再使用旧 v2 的索引周期、同心圆资产和固定中心起点实现，并生成 offset-grid、T-junction、dead-end、ring-spokes、staggered-loop 与 edge/intersection/distributed 起点语法。这个实现事实不等于红队通过：正式道路仍需补齐阻断边、非正交连接和多入口组合，并完成 nuisance classifier、近重复和图像 shortcut probe 后才能冻结。

### 5.3 障碍语义与美观

- 路障位于道路边缘、受损道路或事故区；
- 车辆只位于道路、停车区或事故区；
- 树位于绿化带、庭院或建筑退界；
- 路灯位于人行道并具有受控间距抖动；
- 瓦砾靠近结构但不穿插完整建筑；
- 屋顶设备位于合法支撑面。

发布 admission 要求零非法穿插、零悬空、零越界、可飞域连通、起点与观察位姿可达。允许设计上合理的接触，不把包围盒接触误判为穿插。

美观是发布质量门，不进入排行榜。按城市类型分层保存 overview、street、roof、depth 和 segmentation 截图，禁止只挑漂亮样本。

#### 5.3.1 `ordinary-v3.1` 的语义分层、难度边界与当前证据

正式城市不能靠无限增加随机网格或专有大资产“变丰富”。当前实现把细节分为三层：

1. **结构语义层**：建筑主体、有限数量的女儿墙、入口雨棚、屋顶设备和语义障碍物。它们具有 collider 并进入 ray、可飞域和 `task_geometry_hash`；这些细节可以改变遮挡或窄通道，因此必须作为任务几何的一部分审计。细节本身全部标记 `target_support=false`，不能成为目标采样面或目标捷径。
2. **城市地表细节层**：道路表面风格、人行道和虚线。它们只改善可读性，当前不拥有 collision API，也不进入 `task_geometry_hash`。
3. **外部视觉装饰层**：仅来自 allow-list 的开放许可证资产。它们是 visual-only，当前不拥有 collision API，也不进入 `task_geometry_hash`；更换颜色、道路样式或装饰子集不得改变 hidden targets、起点或 coarse prior。

2026-08-03 新增的 `procedural-urban-detail-v1` 属于第三层：它只生成每栋至多四块立面饰板，
用于帮助 L2 审查识别建筑朝向和垂直尺度。它不引用外部资产，并在 USD 中显式写为
`physics:collisionEnabled=false`；碰撞层、任务哈希、目标支持面、coarse prior 与公共检查图均不读取它。
任何将该层升级到 `official-core` 的尝试，必须重新做 visual-only 反事实、USD/PhysX 审查和相机吞吐审计；
不得把“看起来更丰富”当作难度、可搜索性或正式分数的证据。

新源码物化的首个 calibration 开发城市已在冻结的 `960x640` L2 profile 下通过原生审查：
32 个目标和四个起点各有身份绑定的局部上下文帧，帧多样性、审查 marker、host guard 和
overlay/visual collider 隔离均通过。首轮带饰板审查及同任务几何、无饰板的严格对照都只因
`target_002`、`target_018` 未出现在固定高空总览而失败；二者局部证据均完备，故根因是审查器将
场景级固定总览错误地当成逐实例可见性要求，而不是饰板遮挡。L2 现将固定总览保留为
`unseen_in_scene_overviews` 诊断，仍硬性要求每个目标的私有局部帧；这不改变 L1 的 FoV、LOS、
dwell、OBSERVE、确认或正式评分。该通过记录仍仅覆盖一个开发城市，不关闭 D 门；其余 split 的
新源码复核以及 L1 吞吐/碰撞/恢复检查仍为必做项。

每栋建筑的女儿墙候选有固定上限，雨棚至多一个，屋顶设备至多一个；这使正式场景的 collider 数量随城市规模受控，而不是随视觉随机性失控。`official-mini` 的五项资产只够安装/CI/开发审查，不能被表述为最终视觉资产规模；普通版 `official-core` 仍需在法律、USD 闭包、尺度、语义和吞吐 QA 后逐项扩展。

v3.1 的开发门禁已覆盖：同建筑构件零正体积交叠、语义障碍物不穿插建筑、结构细节真实附着于宿主构件、visual-only 变体不改变目标/起点/粗先验、以及目标支持面排除所有 `target_support=false` 细节。`tools/audit_scene_geometry.py` 以每布局至多 8 次生成尝试、一次一份原子 receipt 的方式审计 train/validation/calibration，且拒绝 formal split；它在内部遍历该布局的所有开发 episode，但公开报告不含私有任务数、坐标、witness、process 或原始 admission 原因。2026-08-02 的可恢复 cohort runner 已完成三 split 各四座、共 12 座独立开发城市的静态审计；布局 hash 全异且全数通过。这不替代 L2 截图审查和 L1 吞吐/碰撞复核；任何失败均拒绝该布局而不是降低检查阈值。

### 5.4 合法三维目标

支持面包括 roof、facade_marker_site、entrance 和 rubble。没有真实 opening 几何时不得把 facade marker 称为窗户或开口。

目标必须：

- 依附真实三维表面并记录法向；
- 位于具有真实 collider 的结构上下文；
- 具有部分遮挡、观察方向或观察高度约束；
- 至少存在一个稳定、可达、非数值脆弱的合法观察通道；
- 不能位于完全空旷、任意方向远距离可见的位置；
- 不能被完全封死。
- valid/invalid 决定、合法观察 witness 和分母 hash 必须在 episode 开始前冻结。

### 5.5 空间过程与反捷径

- `uniform_surface`：按合法表面积加权的软核过程；
- `clustered_surface`：明确的表面聚簇过程；
- `height_stratified`：显式改变低、中、高目标比例。

为目标生成上下文匹配的无目标 distractor。在 support、高度、障碍距离、遮挡、可见立体角和观察成本上匹配，防止“看到某类资产就知道有目标”。

同一几何生成反事实换标 episode。报告 Ripley K、pair-correlation、最近邻、高度熵、二维投影重叠率、support 比例和 opportunity 分布。

若固定高度、高空扫描或二维策略接近完整 3D，必须收紧任务合同或撤回独立三维主张。

- yaw rate 120°/s；
- 机体表面最小净空 0.75 m，连同 0.32 m 机体半径形成 1.07 m 中心安全裕量；
- 当前 L1/G1-U 工程门只使用 5 Hz 候选几何 ray/局部地图更新，不向方法提供 RGB；未来 L1/G2-I 仍不向 geometry 主榜方法提供 RGB，但将额外消费版本化 inspection atlas；固定 virtual camera rig 的 FoV、轴向和 body-to-camera 外参继续保存并与 evaluator 对齐；
- L2/P1 的 RGB-D/分割只在合法 OBSERVE/dwell 内事件触发，候选频率为 2 Hz，允许范围 2--5 Hz；`96x69` 与 `160x120` 是不同 sensor profile，不能在同一实验批次或排行榜混用，切换后必须重新标定；
- 目标确认范围候选 3 m；
- OBSERVE dwell 候选 0.5 s。
- 单机能量预算 24,000 J；在没有 `LAND` 动作前，配置加载器强制至少覆盖完整 300 s 悬停耗能。

正式冻结前运行 2/3/5 m 确认范围以及 1.5/3.0 m/s 速度敏感性。5 m/s 只作为压力测试，不进入普通论文主结果，除非原生制动和吞吐验证通过。

### 7.3 RL/MARL 训练步骤

只有 G2-I 的公开可搜索性校准通过后，普通版才可纳入 MAPPO/RMAPPO。统一训练流程为：

1. 在 L0 批量环境验证 observation、action、reward 和 termination；
2. 使用小城市、少量 atlas 区域和短 L0 任务验证机制；这不是缩短正式 300 s 任务来获得正式分数；
3. 逐步随机化拓扑、建筑高度、检查区域组合、目标过程、起点、通信噪声和动力学参数；
4. CTDE 训练可以读取公开训练状态，正式执行只能使用冻结 decentralized projection；
5. 奖励只使用匿名确认回执、公开 inspection-footprint coverage、时间/能量和安全成本；不读取 evaluator-private 坐标、目标总数、过程、support 或 witness；
6. 固定环境交互数、至少 3 个独立训练 seed、网络规模、GPU 时间和 checkpoint 选择规则；
7. 在未见 ancestor 的 validation 选 checkpoint；
8. 最终成绩全部在 L1 原生闭环重新执行，不能把 L0 分数作为正式结果；
9. 记录训练崩溃、超时、deadline miss 和失败 episode，不删失败 seed；
10. 自有 aerocity-method 不参与这些训练协议、atlas 参数或 benchmark 参数校准。QD+RL 仅可把 G2-I 作为冻结后的外部验证 API：QD 输出公开 atlas 上的责任分配/冗余检查方案，RL 选择下一候选，统一 CF2X controller 执行；QD archive 不得直接控制电机，也不得把确认数、recall、coverage 分数、目标真值或编队紧凑度作为行为描述符。
11. 若允许 L1 fine-tuning，必须为所有学习方法冻结相同的 L1 interaction budget；不允许时统一为零。

## 8. 最低基线与适配器

### 8.1 Compatibility spike

先接入：

1. 2D fixed-altitude sweep 与 3D volumetric sweep，限 G1-U exploration diagnostic；
2. nearest/3D frontier，先作为 G1-U exploration 方法；
3. centralized oracle，只证明 private 可解性，不参与排名；
4. `surface-inspector`：只依据 G2-I atlas 覆盖公开检查单元的透明 target-search 参考方法。

在 surface-inspector 与至少一个非 oracle 公开方法于 calibration 城市产生稳定、非零且未饱和的确认前，不得宣称 geometry-search 可公开搜索，也不得启动学习大训练。

### 8.2 普通论文正式矩阵

正式论文要求 3–5 个 substantive、真实闭环方法：

1. target-agnostic surface-inspector；
2. atlas-aware information-gain/inspection frontier；
3. atlas-aware decentralized auction/Voronoi；
4. 至少一个锁定 upstream commit 的公开三维系统或可审计 clean-room reproduction，且权限可被映射到 G2-I；
5. 资源允许时加入 MAPPO/RMAPPO，且至少 3 个独立训练 seed。

诊断项：random-safe、2D fixed-altitude sweep、3D volumetric sweep、G1-U frontier 和 centralized oracle。诊断项不计入 3–5 个 substantive G2-I methods，也不参与 geometry-search 普通排名。

每个方法必须明确标记 exact upstream、clean-room reproduction 或 named new implementation，披露完整 upstream revision、许可证、训练预算、权限、adapter tax、推理延迟和失败分母。外部 URL 与 revision 必须成对存在；GPL/AGPL/LGPL 必须在真实的 process/container/ROS 边界后运行，container 必须给出不可变 OCI `sha256` digest。当前 `ExternalProcessPlannerBridge` 已实现 G1-U/G2-I 的 public-only reset/step ABI，并递归拒绝私有字段和 G1/G2-I 投影错配；它仍只允许真实 `process` 声明，拒绝 container/ROS 伪装和去中心化虚假声明。它不是 sandbox、容器运行器或外部系统闭环。Python 内嵌 adapter 继续拒绝所有 process/container/ROS 声明。禁止使用“FUEL-style”“MARVEL-style”等模糊名称，也不得把 declaration/ABI/bridge 测试写成外部方法闭环。

### 8.3 v1.0 接口边界

必须实现：

- PlannerAdapter；
- GymnasiumFleetWrapper 或 PettingZoo ParallelEnv，至少一个真正可训练入口；
- Replay transcript 导出格式，但不要求世界模型 adapter；
- capability manifest 和机器可读不兼容原因。

ROS、完整 ReplayAdapter、多模态模型权重和语言接口后移。接口保留字段不能被宣传为已集成。

当前公开兼容矩阵冻结如下；“已实现”只表示 ABI 和合同测试通过，不等于外部方法已经闭环复现：

## 9. Split、指标与统计

### 9.1 普通版 split

| Split | 结构 | 目标过程 | 用途 |
| --- | --- | --- | --- |
| train | core grammar，祖先隔离 | 三种主过程 | 学习与开发 |
| validation | 未见祖先 | 三种主过程 | checkpoint 与超参 |
| calibration | 未见且独立祖先 | 三种主过程 | 只用于确认范围、速度、难度和功效冻结 |
| test_iid | 未见祖先、同 grammar | 三种主过程配对 | 主结果与过程交互 |
| test_topology | 未见 road-graph grammar | 固定配对过程 | 模拟器内部 topology OOD |
| test_process_ood | 同城市或同祖先配对 | 未见参数范围/过程族 | 目标过程 OOD，单独报告 |

普通版不设置正式 `test_resilience`。当前 `smoke.json` 和 `v0.2-pilot.json` 中的韧性、T0–T4 多榜字段属于 pre-plan 兼容配置，不是 v1.0 canonical 配置，后续需要重新生成 ordinary-v1 preset。

calibration ancestor、episode seed、目标随机流和布局派生不得进入任何 formal test。formal test 的私有内容在合同、阈值、exclusion 和分析脚本 hash 冻结后才允许首次执行；首次执行后只能修复预注册允许的实现错误，任何语义变化必须升 benchmark major version 并重跑全部方法。

独立统计单位是 road-graph/layout ancestor，不是 frame、agent、target、time step 或同布局 episode。

### 9.2 唯一主指标

时间归一化 confirmed-recall AUC：

\[
AUC_{recall}=\frac{1}{T}\int_0^T \frac{N_{confirmed}(t)}{N_{valid\ targets}}dt
\]

目标总数可以对方法私有，但由 evaluator 用于统一评分。任务在固定时限、返航完成或硬失败时终止，方法不需要知道何时达到100%目标。

`N_valid targets` 来自 episode 开始前冻结的 target-validity manifest，运行后不得改变。未达到 k% recall 的 time-to-k 按预注册右删失规则报告，不能删除该 episode 或用任务时限伪装为成功到达。

### 9.3 必报指标

- G1-U 的 free-space/occupancy coverage AUC；
- G2-I 的 inspection-footprint coverage AUC：以 `represented_area_m2` 为分母，只有 evaluator 接受且同时满足 source/freshness、pose envelope、range/FoV/facing/LOS、连续 dwell、pose drift、机体净空和运行时安全的 `OBSERVE` 才计入；等权 cell coverage 只作采样密度诊断；
- confirmed-recall AUC；
- final recall；
- time-to-first confirmation；
- time-to-k-percent recall；
- free-space coverage 与 confirmed recall 的 paired gap，以及 inspection-footprint coverage 与 confirmed recall 的 paired gap；
- Kendall/Spearman 排名变化；
- method × process interaction；
- altitude/support/worst-group recall；
- collision、最小净空、越界和返航率；
- 路径、能量、planning latency 和 deadline miss；
- 通信量、重复搜索率和工作量均衡。

安全是硬约束，不与 recall 加权成不透明总分。质量、安全、资源和计算分别报告。

### 9.4 统计协议

- 使用 ancestor-level paired summaries、层级模型或分层 bootstrap；
- pilot 估计 ancestor-level 方差和最小有意义效应；
- 样本量由功效和资源共同决定，不提前承诺固定 layout 数；
- 预注册主指标、主 RQ、exclusion、timeout、collision、missing data 和多重比较；
- 崩溃、超时、无法适配和失败 episode 全部进入分母。
- calibration 只估计阈值、方差和样本量；formal test 在冻结前对开发者不可见，且不得用于二次调参。

## 14. 停止、回退与降级条件

任一情况出现必须停止当前阶段：

- 公开字段、atlas、资产或 nuisance 特征可预测目标/split；
- atlas 缺失、atlas 随 target process 改变，或非 oracle 公开方法在中等 calibration 城市仍无稳定搜索机会；
- visual、collision、depth/range、support 和 evaluator ray 不一致；
- 目标普遍不可解、完全空旷或单次观察确认过量；
- 固定高度或二维策略接近完整3D且无法合理修复；
- adapter 获得额外地图、目标或私有真值；
- reset 后存在几何、sensor、packet、target 或 RNG 残留；
- 统计依赖同布局伪重复或删除失败episode；
- NVIDIA/专有资产、许可证不明代码或不合规GPL派生进入公开核心；
- 正式预算无法达到最低统计功效。

若普通论文核心主张不成立，优先诚实降级，不通过加入VLA、世界模型、机群故障或更多指标制造“功能很多”的假创新。

### 17.3 尚未完成，继续 NO-GO

代码已实现 CF2X 哈希/结构合同、逐旋翼推力执行器后端构造、预飞行和单机 private vertical-slice 入口。2026-07-31 已在本机 CUDA/PhysX 完成长时稳定性复核：两个独立进程的 `shared-long-hold` 均执行 30.0 个模拟秒，均保持 `z=1.5 m`、末端 `vz=2.14e-06 m/s`、10 秒后高度斜率 `0 m/s`、零接触，末状态跨进程差为零；同配置 `open-loop-hover` 30.0 秒的末端高度误差为 `-0.332 mm`、后段斜率为 `-1.45e-05 m/s`；`shared-long-lateral-hold` 在最大俯仰 `0.0385 rad`、横移并保持至 `0.35 m` 时仍有末端高度误差约 `-1.07e-06 m`、后段斜率约 `2.04e-07 m/s`、零接触。该证据关闭了“短时悬停掩盖慢性下沉”和“明显总升力偏差被闭环掩盖”的候选控制器预飞行风险，但参数来源仍为 `parameter_audit_pending`，不能声称真实机标定。此前 1.0 s `shared-hold`、2.5 s 侧移/爬升、3.0 s 偏航、6.0 s 制动和 3.0 s `open-loop-drop` 接触信号门仍有效。回执因含本地资产路径不提交；这些证据不关闭城市障碍/窄通道碰撞、三城 slice、四机闭环或正式分数门。历史 DynamicCuboid 11/11 PASS 仍仅为 capability probe，不能计为 CF2X 验证或正式 L1 episode。

上述顺序是 v16 之前的历史工程链：CF2X 原生 preflight、三城单机 private slice、公开四机 action/OBSERVE/confirmation/return/score 闭环与 calibration L0/L1 排名审计现已完成，但均保持 `formal_score_eligible=false`。当前固定顺序为：锁定实质性外部三维方法及隔离环境 -> 只读公共 ABI smoke -> 同边界三 ancestor 四机 L1 -> ancestor 级统计冻结 -> 场景/法律与干净发布恢复验证 -> 再决定是否开放 formal test。任何一步失败都保留 failure receipt 并阻止正式 test。

### 17.4 2026-07-31 单机切片证据链加固

`vertical_slice_contract.py` 已为内部单机 CF2X private slice 增加纯 Python、fail-closed 的证据审计。它逐条验证：

- action、source observation、measured before/after state 与 L1 `ExecutionReceipt` 的哈希绑定；
- 单机 action sequence、时间、previous receipt 和 state hash 链连续；
- evaluator confirmation 只能来自被接受的 `OBSERVE`，并且必须由同一 execution receipt 绑定；
- private evaluator audit、collision/越界状态、失败记录、最终机位和返航半径彼此一致；
- 只有“确认、返航、无终端失败、无碰撞/越界且存在 RETURN action”才能让这个**内部切片**的 closure 记为 PASS。

该验证器不读取或输出公共目标答案；公共报告只携带 validation 摘要和私有文件哈希。回归测试已覆盖删除 receipt、将 confirmation 改挂到非 `OBSERVE`、以及重哈希后伪造“无 RETURN 但 PASS”的攻击。它只关闭“单机 preflight 证据自相矛盾”这一工程漏洞，**不**关闭三城实跑、四机正式 executor、城市窄通道碰撞、参数标定、L0/L1 偏差或正式评分门，因此总状态继续 `NO-GO`。

### 17.5 2026-07-31 外部方法 process bridge

`ExternalProcessPlannerBridge` 将外部集中式 G1-U/G2-I planner 接入为持久 JSONL 子进程，并非将其源码导入 BSD 核心。每条 reset/act 请求只包含清洗后的 public episode 或相应 public projection：用于审计的 `target_count_public=false`、`target_process_public=false` 会先验证，再从**所有嵌套层级**的 process wire 移除；递归字段检查会拒绝 `targets`、target ID/process/coordinates、evaluator/private seed、support sites、witness、distractor 与 split label，并将字段名大小写、连字符规范化后检查，非 ASCII JSON 键直接失败。响应必须带同一个 request ID、唯一允许字段、完整 active-drone action roster 和 canonical action 语义；超时、超长行、异常关闭或 schema 漂移立即失败、终止仅由该 bridge 创建的进程树并记录桥接时间。锁定 MARVEL 的 L0 smoke 和短时 L1 进程诊断已通过此路径，但不等同于 G2-I 三维方法闭环。

同日，三种配对目标过程的安全天空走廊证明加入了进程内有界缓存。缓存键绑定 `task_geometry_hash`、支持点哈希、起飞状态和完整执行合同，命中时返回深拷贝，容量固定且只存在于当前生成进程；它不改变 episode、evaluator 或评分语义，也不把私有证明写入公开包。缓存回归验证三种 process 在同一成组起飞点只编译一次，且调用方修改返回值不会污染后续 episode。几何等价优化还把天空水平段、起飞上升段和目标下降段的碰撞检查从“每个 witness×每架无人机”降为各自不变量检查；必须保持 segment-expanded-collider 证明和 release hash 不变。

该桥只接受声明为 `process` 的方法。container 仍须在可验证 OCI digest 下由独立 runner 启动；ROS 仍须真实 graph/runner；blind submission 仍须只读挂载、网络隔离及独立服务。故 bridge 的定向回归只是“真实协议存在且不会从 benchmark-owned wire 泄漏私有字段”的证据，**不是** FlightBench/FALCON/MARVEL 已适配、也不是正式 L1 或 blind 安全完成。

### 17.7 2026-08-03 FUEL ROS 烟雾的否定结果
