# AeroCityBench 目标模型与论文定位审查

状态：`accepted research decision`

日期：2026-07-29

本文件记录为什么 AeroCityBench 撤回“真实灾后伤员分布”主张，以及该决定如何改变论文问题、代码和实验。它不是对救援价值的否定，而是拒绝在没有城市灾害人员数据、灾害专家标注和外部效度验证时制造虚假的真实性。

## 1. 审查问题

审查针对四个问题：

1. 相近的多无人机搜索、目标搜索、信息路径规划与探索工作实际使用什么目标模型？
2. 完整的“灾害类型到伤员位置”因果模型是不是该领域 benchmark 的通行做法？
3. 一个伤员模型会增加科学可识别性，还是会引入更多无法验证的自由参数？
4. AeroCityBench 的独立论文价值应该落在哪里？

证据来自本地文献全文、公开论文元数据和对应项目材料。检索日期固定为 2026-07-29。论文摘要只能用于定位，目标生成细节以本地全文为准。

## 2. 相近工作采用的目标模型

| 工作 | 任务 | 目标过程 | 主要指标 | 对 AeroCityBench 的含义 |
| --- | --- | --- | --- | --- |
| Xiao et al., Collaborative Target Search With a Visual Drone Swarm | 视觉无人机群目标搜索 | 单个 parcel box；在球形区域或预定义遮蔽位置中随机放置 | success rate、time to reach | 强搜索方法并不要求伤员因果模型 |
| STAR-Searcher | 自主空中目标搜索 | 每个场景固定 8 个 AprilTag，目标数量对方法未知，强调表面完整检查 | completeness、flight time、path length | 离散语义标记和几何检查可以形成有效任务 |
| Vashisth et al., MRIPP Target Mapping | 多机器人目标建图 | 随机建筑的窗口或 ArUco target；全文实验约 60 x 60 x 30 m、约 161 个窗口对象 | detected-target ratio、planning time | 目标可依附真实三维表面，但密度必须与我们的确认任务重新校准 |
| Westheider et al., Multi-UAV Adaptive Informative Path Planning | 自适应信息路径规划 | 随机连通、非均匀二值热点区域，覆盖场地约 30%--60% | information gain、entropy、F1 | 热点是空间过程，不是人员因果模型 |
| MARVEL、FUEL、RACER、Explore-Bench | 多机器人或无人机探索 | 通常没有离散目标；优化未知空间覆盖与探索效率 | coverage、time、distance、collision | 探索基线不能自动等同目标确认，但可作为 target-free 对照 |

## 3. 裁决

完整的“灾害类型 -> 建筑占用 -> 逃生与阻断 -> 坍塌可生存空间 -> 伤员位置”不是相近 benchmark 的通行前提。若 AeroCityBench 在没有实测城市灾害人员数据时自行指定这些条件概率，会产生一个外观合理但不可证伪的 synthetic story。方法可能只是在拟合生成者偏见。

因此立即执行以下裁决：

- 不再把 evaluator-private target 称为 victim、casualty 或真实伤员；
- 不再声称目标分布符合真实灾后人员统计；
- `disaster-conditioned search target` 降级为未来可选领域扩展，不进入 Paper I 主张；
- benchmark 的目标对象是可检测的三维 search target，可用 marker、parcel、opening cue 或其他统一渲染对象实例化；
- 科研变量是 target spatial process，而不是未经验证的人类行为模型。

## 4. v2 三类目标空间过程

### 4.1 Uniform surface

从真实 collider/component 派生的合法表面候选中均匀抽样。候选数量随表面积近似变化，因此不是对建筑 ID 均匀。用途：中性 IID 基准。

### 4.2 Clustered surface

先抽样表面 anchor，再按三维距离核加权抽样其余目标。cluster 数和带宽是预注册参数。用途：模拟常见的空间热点，同时不声称热点来自伤员行为。

### 4.3 Height stratified

对 `near_ground/lower/mid/elevated/highrise` 五个高度带显式设权，并要求最低带覆盖。用途：构造可控的 target-process shift，检测方法是否把二维覆盖误当成三维搜索能力。

三类过程共享：

- 相同真实三维 component surface；
- 相同最小目标间距；
- 相同 detector/confirmation 合同；
- 相同目标数量范围与任务预算校准流程；
- 大量同类无目标表面作为 distractor；
- evaluator 私有的具体过程标签、seed、位置和数量。

`roof/opening/entrance/rubble` 是几何支持类别，不是人员类别。`opening` 必须来自真实 component face，不能再从整栋建筑 footprint 的外接矩形生成。

## 5. 论文从“造城项目”转为可识别实验

Paper I 的核心问题改为：

> 在统一三维几何、物理执行和评价合同下，目标空间过程偏移、城市拓扑偏移与机队减员如何改变多无人机搜索性能和方法排序？

三个受控因素是：

1. `Target-process shift`：uniform、clustered、height-stratified；
2. `Topology/scale shift`：未见城市语法和未见尺度；
3. `Fleet attrition`：相同 layout/target/start 下的无故障、通信隔离、单/双机 hard loss 与传感器失效。

可证伪假设：

- H1：控制 target opportunity 后，目标过程仍显著改变方法排序；
- H2：无故障性能不能可靠预测单机或双机减员韧性；
- H3：二维覆盖率和 raw target density 不能充分解释三维搜索难度；
- H4：opportunity-normalized recall 比 raw target count 下的结果更稳定。

若所有方法排序在三类目标过程和故障条件下都稳定，或二维覆盖已经解释全部方差，论文必须报告这个否定结果，不能继续宣传 benchmark 测到了新的泛化缺口。

## 6. 仍未解决的效度问题

v2 目标过程解决的是“可控”和“可比较”，不是“真实”。以下证据未完成前不能升级为 paper-ready：

- Isaac ray witness 证明每个 target 有合法 N1/N2 观测机会；
- detector precision/recall 与距离、视角、遮挡和速度联合标定；
- 单个普通 viewpoint 不能一次确认过多目标；
- 目标数由 planner/oracle pilot 校准，不由地图面积拍脑袋决定；
- `clustered_surface` 的 Ripley K、pair-correlation 或最近邻统计与 uniform 显著不同；
- 各高度带的可见立体角和确认成本不退化；
- target appearance 与 split、建筑模板、颜色和 support 类之间没有确定性捷径；
- 方法容器无法读取具体 process、fault、split 或 generation seed。

## 7. 代码决定

本次审查对应 release v2：

- `targets.py` 实现三种过程、四机起点和 evaluator-private FaultSpec；
- `generator.py` 使用缩小的高度范围，并把 `facade` 规则替换为 component-face `opening`；
- `compiler.py` 公开投影删除 split、family 和 generation seed；
- `audit.py` 按过程合同审计，不再强制每局覆盖任意 3/4 类 support；
- `smoke.json` 与 `v0.2-pilot.json` 使用 64--160 m 的 pilot 尺度；224 m 只保留 custom stress 候选，288 m 失活。

这些改动的状态仍是 `pilot_only`。它们通过软件测试不等于通过 Isaac、统计功效或论文效度 gate。
