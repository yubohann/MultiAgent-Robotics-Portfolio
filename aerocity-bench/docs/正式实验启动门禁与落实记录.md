## 2026-08-03 E 门外部小型证据清单与干净源码复核

治理配置登记了校准、退役回放和外部桥接的摘要回执，但这些小型回执不应与大体积
PhysX 回放一同提交到源码仓库。此前干净 checkout 因缺少这些已登记回执而无法完成

现增加受限的外部证据清单机制：

- `tools/build_external_experiment_evidence_manifest.py` 为治理配置中的每一条已登记证据生成
  相对路径与 SHA-256；清单同时绑定当前源码 Git 提交、
  `configs/experiment-governance-v1.json` 的规范化内容哈希和配置内容哈希；
- `tools/audit_experiment_governance.py` 仅在显式同时提供 `--external-evidence-root` 与
  `--external-evidence-manifest` 时回退读取缺失的本地证据；绝对路径、路径穿越、未登记文件、
  重复路径、回执篡改、配置变化或提交不匹配都会 fail-closed；
- 清单不保存外部根目录的绝对路径，不允许引入私有真值，也不将任何外部回执提升为正式分数。

典型复核流程为先在持有回执的工作树生成清单，再在同一提交的干净 worktree 显式传入该

## 1. 为什么需要这份文件

正式实验不是“代码能跑”或“私有 oracle 能找到目标”。它必须同时证明：任务对公开方法可搜索、指标不能被位置打卡作弊、公开信息不泄漏答案、CF2X 原生执行与 L0 趋势一致、统计单位正确、外部方法能接入、资产与发布链可复现。

现有整城 G2-I 在 300 秒任务中失败：完整 atlas 每城约 4,291--4,980 个 cell；两种公开方法在五个 ancestor 上均为零确认，oracle 虽能确认目标，但三个 ancestor 不能全员返航。该结果禁止被删除或覆盖：

- `reason/g2-i-risk-audit-20260731/g2-i-l0-searchability-5-ancestor-20260731.json`
- `reason/g2-i-risk-audit-20260731/g2-i-l0-searchability-5-ancestor-20260731-v2.json`

因此 G2-I v1.1 引入每 episode 的公开 mission sector；当前可审计实现为 v2 schema。sector 不是目标提示，也不是算法：它是在目标采样前，仅由公开 atlas、公开起点、速度、dwell、任务时限和返航余量编译的有限检查任务。私有目标状态随后才在 sector 的候选检查域中实例化。

## 2. 不可变边界

1. `G1-U / exploration-3d` 与 `G2-I / geometry-search-3d` 分榜，不混合排名。
2. geometry 主榜不要求 RGB；相机只保留传感器几何合同与 L2 视觉审查。perception-search 另立版本。
3. 正式 L1 只允许哈希锁定的 `assets/new/cf2x.usd`；禁止 `assets/5_in_drone`。
4. 方法不得读取目标坐标、目标数、目标过程、support site、legal witness、确认总数或 formal split 标签。
5. benchmark 参数不得依据 `aerocity-method` 的结果调整；自有方法在 A--C 冻结后才能训练。
6. ancestor 是独立统计单位；同一城市的多个 episode 只是配对重复测量。
7. L0 只用于训练、调试和筛选；正式分数只能来自 L1 CF2X/PhysX 执行。
8. 失败、超时、OOM、碰撞和未返航 episode 必须保留在分母；禁止只清理失败行。
9. formal test 在合同冻结和预注册前保持私有且不可读取。

## 4. G1 mission-sector 合同

### 4.1 编译顺序

```text
CitySpec + execution contract
  -> target-independent full inspection atlas
  -> public starts
  -> route/dwell/return workload model
  -> public mission sector (hash frozen)
  -> private candidate states inside selected inspection cells
  -> private target process and matched distractors
  -> public episode projection
  -> public method -> unified controller -> evaluator-private confirmation
```

禁止把上述顺序改成“先看目标，再挑 sector”。同一 paired-process 组必须共享起点和 sector hash。

### 4.2 工作量而非必完成清单

隐藏目标搜索是部分覆盖任务。sector 的完整串行检查工作量必须满足严格的 `1.0x` episode-time certificate，而不是要求方法在 300 秒内扫完全部 cell。运动、离散 dwell、返航和 return reserve 已计入同一硬上限。历史 `1.35x` 候选会产生 405 s 的伪可行下界，已废止。

- sector 太小：所有方法按固定清单饱和，任务退化为调度；
- sector 太大：所有公开方法全零，方法差异不可辨识。

`1.35` 是已废止的公开 calibration candidate，不是物理常数，也不得出现在新任务合同中。2026-08-01 的 paired prior ablation 已证明该选择必须与先验级别一起报告：coarse-region 诊断 planner 在 5 个 ancestor 上全零且有 9 次碰撞，full-cell region-greedy 在 4/5 ancestor 上非零、零碰撞；该结果是表示级别诊断，不是算法排名。

### 4.3 A 门通过标准

在至少 5 个 calibration ancestor、三个目标过程上：

1. private oracle 每个 ancestor 都零碰撞且全员返航；
2. 至少两个 target-agnostic 公开方法在至少 4/5 ancestor 上非零确认；
3. 强公开方法平均 final recall 位于 `[0.10, 0.90]`；
4. 至少两个公开方法没有完全相同的 ancestor 排序；
5. 结果不因某个单一城市或 episode 复制数而成立；
6. 公开输出不包含 episode ID、目标数、目标 ID、坐标、confirmation handle 或 route 坐标。

2026-08-02 的更新：旧密度消融因未证明私有目标实现配对而被拒绝；修复后的 `g2-i-density-ablation-5-ancestor-20260802-v4-merged.json` 复用同一源私有 episode，只改变公开采样策略，配对哈希、三种密度×两种公开方法、失败分母和返航/安全条件均通过。结合同一批次的先验、目标过程、搜索性和独立 split 审查，`g2-i-a-gate-freeze-20260802-v2.json` 为 `VERIFIED`。这只关闭方法无关的 A 校准合同，不产生正式分数；B 真实四机 CF2X L1、外部方法、功效分析和发布复现仍是阻塞项。

未达到时只允许修改 sector policy 或任务合同并升版本，保留全部失败报告；禁止直接启动 RL 长训练。

## 5. 逐门落实顺序

### 阶段 A：CPU/L0 科学括号

1. 完成 mission-sector 编译、验证、篡改测试和 paired-process invariance。
2. 从 sector cell 编译私有候选状态；保证候选、目标、distractor 均在同一冻结 sector。
3. 运行 private oracle、budgeted surface inspector、region-greedy/atlas-aware planner。
4. 运行 coarse/full prior 消融和 sector-only 泄漏探针。
5. 只在 G1 bracket 稳定后冻结 sector policy 和 atlas sampling policy。

### 阶段 B：真实 CF2X/L1

1. CPU 预检每个 shortlist cell、起点爬升、sector 转场和返航路线。
2. 三个 ancestor 上运行公开四机 L1 episode，不使用 private witness route。
3. 记录姿态跟踪、最低高度、碰撞/净空、deadline、OBSERVE 接受、确认、返航和原始 replay hash。
4. 对齐 L0/L1 的相同方法和 ancestor，报告排序相关及每个差异原因。
5. 若 CF2X 越飞越低、持续高度偏差或 rotor/质量/推力 contract 漂移，G5 失败并停止。

### 阶段 C：外部方法与统计冻结

1. 用固定 commit 接入一个真实公开方法；GPL 方法必须独立容器/进程，不进入 BSD core。
2. 断网、只读 public mount、写入独立 run 目录，限制消息大小、时间和内存。
3. 冻结 seed、训练步数、checkpoint 选择、失败分母、ancestor bootstrap 和排除规则。
4. 用 calibration 方差完成功效分析；在此之前不生成正式结果表。

## 7. 证据解释规则

- `PASS_CPU`：只说明静态几何、哈希和 schema 成立。
- `L0 nonzero`：只说明任务存在公开搜索信号，不是正式方法成绩。
- `private oracle pass`：只说明目标可解，不说明外部方法公平。
- `private CF2X fixture pass`：只说明原生能力链可能闭合，不是公开方法证据。
- `L1 public closure pass`：说明一个公开方法真实执行闭合，仍需多方法、多 ancestor 排名审计。
- `FORMAL READY`：只在 A--E 五个综合门全部满足后使用。

## 8. 外部依据与本地复核

设计原则来自任务边界而不是照搬实现：

- Habitat/ObjectNav：公开目标类别与任务先验，但隐藏实例位置；说明“隐藏答案”不等于“隐藏搜索对象”。
- Explore-Bench（ICRA 2022）：统一接口、分层平台与可比较基线是 benchmark 贡献的一部分。
- FALCON（T-RO 2025）：free-space exploration 的评分对象与前沿规划一致；不能把 exploration baseline 直接称为 hidden-target baseline。
- FlightBench（RA-L 2025）：先以可测难度和统一执行链校准，再比较 learning 与 optimization 方法，并报告具体失败机制。
- 本地 `md_qd_swarm` 历史：私有 oracle `4/8`、frontier `1/8`、固定 sweep `0/8`；旧 QD 描述符出现 archive collapse，证明任务和描述符都必须先做可控性门。

这些工作支持“公开任务先验、统一执行、难度括号、失败诊断、外部接入”原则，但不替 AeroCityBench 证明 mission sector 合理。最终证据只能来自本文件定义的独立 calibration 和 L1 闭环。
