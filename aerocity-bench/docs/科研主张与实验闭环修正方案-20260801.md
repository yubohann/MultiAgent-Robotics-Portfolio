# AeroCityBench 科研主张与实验闭环修正方案

**日期：** 2026-08-01
**用途：** 研究设计冻结前的科学审查、实验门禁与论文定位
**当前结论：** `FORMAL EXPERIMENT = NO-GO`；`MAPPO/QD+RL 长训练 = DISABLED`；`formal test split = NOT TOUCHED`

**唯一权威状态：** `configs/authoritative-readiness-status-v1.json`。本文档不能独立授权正式实验。

## 2026-08-03 执行合同更新后的证据更正

三座重新物化的 calibration ancestor 已完成公开四机 CF2X/PhysX 九条回放与配对 L0 审计。所有回放
通过公开边界、哈希绑定、主机隔离、零碰撞/越界/deadline 和全员返航检查；两种 atlas 方法在 L1 仍有

`reason/benchmark-external-methodology-audit-20260802/current-boundary-l1-panel-20260803/cf2x-b-gate-verification-v16-current-boundary.json`。

上述结果只对其冻结的旧执行合同成立。当前版本已把高层规划从每个 0.2 秒控制周期调用，改为 1 秒
固定周期加公共事件触发；执行合同哈希随之改变。旧 A 门和 v16 均不能跨哈希继承。较晚回放还保留了
两种 atlas 方法各一次规划超时，因此当前 A/B 门均未关闭。正式主矩阵、正式 test 和 QD+RL 长训练
继续关闭；下一个可执行问题是当前合同下的方法无关 A 门校准，而不是直接扩展外部方法或训练。

## 2026-08-03 执行层证据追溯更正

v15 三城三方法九条四机 CF2X/PhysX 回放不再关闭任何风险。追溯审计发现其历史公开任务文件
泄露 `fixed_target_count_private`，且该代 mission-sector schema 已失效；因此原有安全闭环和

锁定 MARVEL 上游提交与 checkpoint 的 L0 源码 smoke 已通过；在当前公开边界审计通过的开发重采样
布局上，独立进程还完成了 12 秒共享 CF2X 诊断。该过程无碰撞、越界或适配器失败，但没有
`OBSERVE`、确认和返航，且 MARVEL 是二维探索迁移。它证明 ABI 可复现，不证明外部三维闭环。
随后曾从当时的公开边界和 mission-sector schema 完成 v16 三 ancestor 完整 L1 开发校准面板；它现为
历史工程证据。下一项实际工作是当前执行哈希下的 A 门校准、三上下文行为审计与新的 B 门回放。

## 2026-08-01 合同修复补充

G2-I mission-sector 当前实现为公开 schema `org.aerocity.bench.inspection-mission-sector-public.v2`。它新增 `cell_assignment_by_drone`，并要求 evaluator 根据公开 assignment 重算每机 optimistic route lower bound；证书不再是可被重写后重新哈希的信任输入。编译器 route-region metadata 错误、assignment 缺失/重复、面积/区域投影不一致和严格 `1.0x` 过预算现在均 fail closed。

这项修复本身只提高了构念效度的底线；历史 v15 已因公开边界/schema 问题退役，不能再提供
公开四机 CF2X L1 或 L0/L1 一致性证据。它仍没有提供充分 split/OOD cohort、实质性外部三维方法、
统计效力或正式 test 结果。因此不能据此启动长训练，也不能把本记录改写为 benchmark 已完成。

## 2026-08-02 统计与供应链的可证伪更新

统计协议现将 `layout ancestor` 固定为唯一独立单位，当前五个 calibration ancestor 的估计功效
只有约 `0.215`；若以最小可检测差异 `0.10` 规划，约需 `29` 个独立 ancestor。这个结果是阻塞
证据，不是可通过增加 episode 数量规避的工程问题。五项 CC0 mini core 同时通过实际 USD 依赖
闭包审计（32 layer、零远程、零未解析）。哈希绑定的环境清单和临时干净 venv wheel 安装已经
通过开发验证，但来源被正确标记为 `UNCOMMITTED-DEVELOPMENT`，不能冒充官方 release；城市抽样
审查、干净提交重跑、CPU/GPU smoke、环境/资产/控制器哈希冻结和失败恢复演练仍是 E/D 门的必要条件。

本文不是宣传稿，也不是把已有工程工作包装成论文贡献。它回答三个问题：

1. 这篇论文最容易被审稿人击穿的地方是什么；
2. 哪些证据可以把工程系统提升为可发表的测量型 benchmark；
3. 在有限 GPU、磁盘和时间下，下一步应按什么顺序执行，哪些结果失败后必须停手。

---

## 1. 一句话判断

AeroCityBench 当前最大的风险不是城市还不够丰富，也不是还缺少 VLA、世界模型或更多基线，而是**尚未证明它测量了一个独立于作者方法的科学现象**。

目前最强、也是唯一值得保留的论文主线是：

> 在统一的四旋翼动力学、观察动作、信息权限和私有 evaluator 下，自由空间 coverage 是否足以预测三维隐藏目标搜索？如果不能，目标空间过程和城市拓扑是否会稳定地改变方法排序与失败机制？

这是一条“测量主张”，不是“我们实现了一个很大的模拟器”的主张。只有在方法无关的 calibration 和真实 CF2X L1 闭环中得到可重复证据，论文才可以声称 benchmark 发现了新的评价缺口。

## 2. 当前证据快照

### 2.1 已有但不能过度解释的证据

当前 v8 L0 calibration 报告：

结果是：

| 方法 | 非零 ancestor | 平均最终确认召回 | 能说明什么 | 不能说明什么 |
|---|---:|---:|---|---|
| `atlas-surface-inspector` | 3/5 | 0.030 | 公开检查对象并非完全不可搜索 | 不能证明它是强基线或 L1 有效 |

## 3. 最大痛点排序

### P0-1：构念效度没有闭合，benchmark 可能测量的是人为 workload

#### 审稿人会怎样攻击

Atlas 的区域和检查单元、mission sector、目标过程、cell 密度、FoV、dwell、确认距离和 300 秒预算共同决定了结果。审稿人可以认为：方法排名不是来自搜索算法，而是来自作者手工指定的检查顺序和任务容量。

这不是抽象担忧。此前的 `capacity_fraction=1.35` 允许约 405 秒的运动学路线进入 300 秒任务，已经证明任务合同存在过预算漏洞。现在虽然已改为严格 `1.0x`，但 v3 仍必须完成完整的 workload 审计。

#### 必须补的证据

1. **coarse/full prior 消融**：
   - `coarse-regions` 只公开区域类别、边界和粗略难度；
   - `full-cells` 再公开检查单元和公共候选姿态；
   - 比较 navigation、inspection scheduling、private confirmation 三部分的贡献。
2. **cell density 消融**：密度由固定的 range/FoV/dwell/安全净空规则推导，并预注册 0.75x、1.0x、1.25x 版本；不能依据自有方法结果选密度。
3. **target-process 消融**：同一城市、同一 atlas、同一任务预算，只换目标点过程；所有 paired episode 使用相同 layout ancestor。
4. **target/distractor 反事实**：交换私有标签，公开 atlas 和城市 hash 不变。
5. **atlas-only leakage probe**：只用公开 atlas 字段预测 target process、目标类别、split 和难度组；把 region/cell 数量、图度数、ID 排序、padding mask、资产计数都当作潜在 nuisance。
6. **method-independent workload freeze**：在自有方法长训练前生成 manifest、规则版本和决策日志，后续不能因为方法结果改变 sector、目标数量、预算或排除规则。

#### 关闭条件

- 反事实公开字段 hash 不变；
- atlas-only 预测不能超过预注册阈值（默认 AUC 0.60，具体阈值在 calibration 前冻结）；
- 所有公开 cell 通过同一 collider authority 的可达性检查；
- 任务的运动学下界加上规划/干预/返航 reserve 后仍不超过 episode budget；
- coarse/full 的差异被明确报告，而不是只发布有利版本。

任何一项失败都不是“多跑 GPU”能解决的问题，应回到任务合同。

### P0-2：尚未得到论文的 killer measurement result

当前 L0 只证明“有一个非 oracle 方法在部分城市得到非零确认”。这可以证明任务开始可搜索，不能证明 benchmark 发现了现有 coverage 指标看不到的现象。

#### 主张必须变成可证伪假设

| 假设 | 操作化定义 | 支持结果 | 反证结果 |
|---|---|---|---|
| H1 Coverage gap | free-space coverage 与 evaluator-confirmed recall AUC 的 ancestor 级相关性低于预注册阈值，或 coverage 相近的方法确认成绩显著不同 | 低相关、稳定置信区间、非零方法排序差异 | 高相关且排序几乎一致，benchmark 只需报告 coverage |
| H2 Process interaction | 固定城市/预算/权限，仅改变目标空间过程，出现稳定 `method × process` 交互 | 交互效应跨 ancestor 重复，且伴随可解释失败机制 | 只有目标数量改变分数，无交互 |
| H3 Topology interaction | 固定目标过程和任务难度，改变道路图/层级/阻断结构，方法排序或失败谱改变 | 拓扑 OOD 的排序变化不被 nuisance 解释 | 所有方法只随面积/目标数变化 |
| H4 Physical validity | L0 与 CF2X L1 的排序相关性达到预注册下限，且 L1 失败能归因于控制/碰撞/观察时序 | L0 可作为筛选器而不是替代品 | 排名反转，L0 不能用于筛选 |

#### killer result 的最低形式

至少需要在独立 ancestor 上同时看到：

1. `coverage AUC` 与 `confirmed-recall AUC` 不是同一个量；
2. 至少两个公开方法在目标过程或拓扑改变后交换名次，或出现不同失败机制；
3. 该现象在 CF2X L1 仍保持方向一致；
4. 结果不能由 cell 数量、目标数量、任务时长或资产类别泄漏解释。

如果 H1-H3 全部被反证，正确结论不是继续包装，而是把论文降级为物理搜索任务/软件基准报告，并诚实删除 coverage beyond 主张。
### P0-3：L0 到真实 CF2X L1 的证据鸿沟

#### 为什么致命

L0 是离散路线和简化执行，不能证明四旋翼在城市障碍、窄通道、真实碰撞和观察时序下完成任务。`assets/new/cf2x.usd`、共享控制器、PhysX、四个旋翼推力、OBSERVE、FoV、LOS、dwell、planning deadline、返航和失败回执必须在同一闭环中出现。

#### L1 的不可删语义

```text
public action
 -> fixed CF2X controller
 -> PhysX state/contact
 -> OBSERVE gate (FoV + LOS + dwell + freshness)
 -> private evaluator receipt
 -> return/terminate
 -> ExecutionReceipt or FailureRecord
```

每一条结果必须绑定：

```text
layout_hash
atlas_hash
task_contract_hash
dynamics_hash
controller_hash
episode_seed
replay_hash
```

不能用私有 fixture 的 pose 轨迹代替公开方法；不能用单机悬停/横移能力证明四机城市闭环；不能以没有碰撞的简单场景证明复杂城市安全。

#### L1 正式候选的硬条件

- `assets/new/cf2x.usd` 的 hash 和依赖闭包通过；
- 共享 controller 和动力学参数冻结；
- 真实 PhysX contact/collision 计数为零；
- OBSERVE 通过方向、距离、LOS、连续 dwell、freshness 和安全净空；
- planning deadline 不失败；
- 所有无人机返航，或按合同记录可解释的 terminal failure；
- evaluator 只返回匿名 receipt，不返回目标坐标或总目标数；
- L0/L1 的每次 replay 可以离线重新审计。

除 capability/private slice 外，v16 曾提供旧执行合同下的四机 CF2X L1 与 L0/L1 开发校准；历史
v15 已退役，v16 也已被当前规划节拍合同取代。它既不能升级为正式分数，也不能关闭当前 B 门；当前
A/B 门重跑完成后，仍须关闭外部三维方法、
充分独立祖先、场景法律和发布复现门全部关闭。

### P0-4：QD+RL 的理论创新尚未成立，且存在 benchmark 反向调参风险

“QD archive + RL policy”本身不是创新。descriptor-conditioned RL、QD critic、责任分配、MAPPO/IPPO 和多智能体恢复已经覆盖了这种组合的基本形式。

#### QD+RL 只有在以下条件下才值得写成方法论文

1. **描述符是目标无关且可执行的**：例如已检查结构类别/高度带的责任签名、区域切换熵、冗余比例，而不是目标数、confirmed recall、coverage 分数或编队紧凑度。
2. **描述符可控**：改变 descriptor 会以可重复方式改变责任分配，不发生 archive collapse。
3. **计算匹配**：与 MAPPO、IPPO、auction/greedy 使用相同仿真步、观察次数、wall-clock、参数预算和 seed 数。
4. **严格消融**：固定 archive、随机 archive、无 QD、无恢复、无多样性奖励、单一责任策略。
5. **增益来源可归因**：不能只是看了更多观测、用了更多 rollout 或获得了更长训练时间。
6. **安全不以多样性换取**：不同 archive 区域的碰撞率、越界率、deadline failure 不得因为召回提升而恶化。

在上述条件通过前，QD+RL 只做短程机制门，不启动长训练。benchmark 论文不依赖 QD+RL 成功；这能防止“为证明方法而修改 benchmark”。

### P0-5：统计样本与独立性不足

5 个 calibration ancestor 是启动门，不是正式论文样本。相同城市下的多个 episode、多个目标过程或多个 seed 不能冒充独立城市。

正式设计必须：

- 以 `layout ancestor` 为 bootstrap 单位；
- calibration/train/validation/test 使用不相交 ancestor 和生成语法；
- paired target process 共享 layout、atlas、起点和预算；
- 报告 Kendall/Spearman 排名置信区间；
- 报告 deadline failure、collision、not-returned-home 的失败分母；
- 报告 L0/L1 排名相关性及淘汰误杀率；
- 预注册 co-visibility、重复确认、unknown target count 和 early return 的处理；
- 根据 calibration 方差做功效分析，不以 episode 数量掩盖 ancestor 数量不足。

### P1-1：公开方法还没有真正无痛接入 G2-I

有 G1 JSONL bridge 不等于外部作者已经完成 G2-I。外部方法必须能：

```text
pip install aerocity-bench
读取公开 atlas projection
实现统一 action ABI
调用共享 CF2X controller
只得到匿名 ExecutionReceipt
运行 evaluator 并复现失败分母
```

不能要求外部方法导入私有 truth、访问本地绝对路径、理解作者内部类层级或手工改 adapter。至少要有一个锁定 commit 的外部/上游方法通过 G2-I public-only runner；否则只能说“接口已设计”，不能说“社区可复现”。

### P1-2：论文叙事过宽

当前同时包含程序化城市、三维目标搜索、四旋翼动力学、多无人机、物理安全、目标过程泛化、减员、QD+RL、VLA、世界模型、资产供应链。任何一个都可能成为审稿人追问的独立论文。

Paper I 应只保留：

> 物理受限的三维隐藏目标搜索不能由传统 free-space coverage 单独刻画；公开、目标无关的检查图与统一 CF2X 执行合同可以揭示新的方法排序和失败机制。

以下内容降为后续工作或独立论文：

- QD+RL 方法机制；
- 八机减员/恢复；
- RGB/RGB-D 感知；
- VLA、世界模型；
- 真实灾害语义和搜救结论；
- 资产大规模扩展。

### P1-3：发布供应链是 release blocker，但不能替代科学证据

CC0-only 清单、NVIDIA/Nucleus 路径拒绝、USD 依赖闭包、LICENSES、NOTICE、资产 BOM、数据许可证、GPL 独立容器、release hash 都必须完成。

但许可证闭合只能证明“别人可以合法重建”，不能证明 benchmark 测量了新现象。科学门和发布门必须分开记录。

这些工作的共同特质是：先把“方法能看到什么、任务成功是什么、怎样复现失败”冻结，再用实验发现证明 benchmark 改变了方法选择。它们不是靠地图数量或视觉资产数量发表。

## 5. 重新冻结研究问题和主张

### 5.1 Paper I 主问题

**RQ1：** 在相同城市、动力学、观察合同、时间和信息预算下，free-space coverage 是否能稳定预测 evaluator-confirmed 3D search？

**RQ2：** 在固定目标数量和基础难度后，目标空间过程或城市拓扑是否产生稳定的 `method × process/topology` 交互、排序变化和不同失败机制？

### 5.2 辅助有效性问题

- `V1`：inspection-footprint coverage 相比 free-space coverage 是否具有增量解释力？
- `V2`：公共 atlas 是否目标无关且不泄露 split/target process？
- `V3`：L0 能否作为 L1 的筛选器，而不是错误替代？
- `V4`：外部方法能否仅凭公开 ABI 完成一条无私有字段的闭环？

### 5.3 明确放弃的主张

- 不宣称真实灾害搜救能力；
- 不宣称 simulator 内 OOD 等价现实泛化；
- 不宣称 QD+RL 组合本身是理论创新；
- 不宣称 RGB 是 geometry 主榜必需输入；
- 不宣称一个 300 秒设置能覆盖任意完整城市；
- 不把资产丰富度写成科学贡献。
## 6. G2-I 合同的正确形态

### 6.1 两个公开轨道，不混榜

| 轨道 | 方法可见信息 | 适合方法 | 评价重点 |
|---|---|---|---|
| `G1-U / exploration-3d` | 粗先验、局部 occupancy、在线建图 | FALCON、frontier、sweep、information gain | free-space coverage、探索效率、安全 |
| `G2-I / geometry-search-3d` | 粗先验 + 目标无关公共检查图 | surface inspector、auction/Voronoi、MARL、QD+RL | private confirmed-recall、inspection footprint、失败机制 |

`perception-search-3d`（RGB/RGB-D）单独延期，不阻塞 Paper I。

### 6.2 公共检查图公开什么

可以公开：

- 屋顶、立面、入口、瓦砾邻域等结构类别；
- 粗略边界、面积、高度带和公开区域 ID；
- 目标无关的检查单元/姿态包络；
- 安全转场图和公开代价界；
- atlas 版本和 hash。

不能公开：

- 目标坐标、目标数量、target process、support site；
- private witness、射线结果、目标/干扰标签；
- 用私有字段派生出的“最优”访问顺序。

### 6.3 cell 不是拍脑袋格点

检查单元尺度必须由以下量联合推导：

```text
confirmation_range
FoV_horizontal / FoV_vertical
dwell_time
允许的姿态误差
机体净空与安全站距
CF2X controller 的实际停稳误差
```

同一城市的 coarse/full projection 只能改变公开先验精度，不能改变私有 evaluator 的目标和确认语义。

### 6.4 inspection footprint 不能位置近似计分

一个 cell 只有在下列条件全部满足后才产生面积覆盖或检查 credit：

- 当前 action 明确是 OBSERVE；
- observation source/freshness 合法；
- 距离和水平/垂直姿态在 envelope 内；
- 表面 facing、yaw/pitch、FoV 通过；
- LOS 通过；
- 连续 dwell 达标且无漂移超限；
- body clearance、碰撞和 runtime safety 通过。

按 `represented_area_m2` 或预注册的机会权重归一化，不能按 cell 数量给相同分数，也不能让改变采样密度改变任务含义。

## 7. L0 / L1 / L2 的分工

| 层 | 目的 | 允许 | 禁止 | 产物 |
|---|---|---|---|---|
| 静态编译 | 预计算目标无关结构 | atlas、邻接、公开成本、hash 缓存 | 私有目标、witness、ray 结果 | immutable manifest |
| L0 | headless 机制和公开可搜索性校准 | 向量化、2 机短任务、无 RGB、方法筛选 | 正式分数、查看 formal test | calibration report |
| L1 | 正式物理闭环 | CF2X、PhysX、真实碰撞、完整 300 秒、匿名 receipt、返航 | 缩短模拟时钟、删失败 episode | formal replay/score |
| L2 | 视觉审查或事件触发 RGB-D | OBSERVE 时按 profile 触发、分层截图 | 把 RGB 吞吐当成 geometry 排名 | review evidence |

关键原则：L0 可以节省 host 时间和渲染成本，但不能替代 L1 的模拟执行时钟、动力学和失败分母。

## 8. Baseline 与 QD+RL 方案

### 8.1 Paper I 最低基线矩阵

正式候选至少包括：

1. `centralized-oracle`：只作可解性上界，不参加普通排名；
2. `random-safe`：只作下界/安全诊断；
3. `budgeted-volumetric-coverage`：G1-U 诊断，不叫 target-search；
4. `frontier-3d`；
5. `information-gain-frontier`；
6. `atlas-surface-inspector`；
7. `atlas-region-greedy`；
8. `decentralized-auction/Voronoi`；
9. 一个锁定 commit 的公开上游方法，通过独立 runner 接入；
10. 至少一个 MAPPO/IPPO 作为学习控制对照。

`FUEL-style`、`MARVEL-style` 等描述不能直接进入论文表格，除非有明确实现、版本、权限和复现记录。

### 8.2 QD+RL 只做条件性方法

QD archive 维护目标无关的责任方案；RL 只选择当前公开候选和恢复动作；CF2X controller 不进入 archive。

建议 descriptor：

- 结构类别责任分布；
- 高度带责任分布；
- 区域切换熵；
- 冗余检查比例；
- 公开转场图上的负载不均衡。

不得使用：目标数、confirmed recall、私有目标类别、coverage 分数、编队紧凑度作为硬凑 descriptor。

必须执行：

```text
MAPPO/IPPO (compute matched)
QD+RL
fixed archive + RL
random archive + RL
no-QD RL
no-recovery ablation
```

只有当 descriptor 可控、archive 不 collapse、在相同计算量下稳定提升，并且安全/恢复收益可归因时，才把它写成 Paper II 的主方法。否则保留为冻结 benchmark 上的外部案例。

## 9. 统计和数据划分

### 9.1 训练/验证/测试不是“生成很多地图”

先定义 split 规则，再生成城市。每个 split 必须由不相交的 `layout ancestor` 和生成组合语法构成：

| split | 用途 | 能否调规则 | 是否产生论文分数 |
|---|---|---|---|
| calibration | 任务可搜索性、阈值和功效预估 | 可以，但需记录 | 否 |
| train | 方法训练/课程 | 只能按预注册规则 | 否 |
| validation | checkpoint、超参和 early stopping | 只能按预注册规则 | 否 |
| test | 一次性盲测 | 不可查看、不改规则 | 是 |

目标过程的 paired 版本共享 layout、atlas、起点、预算和动力学，只更换私有 realization。不得生成一个城市后再“临时决定”它属于哪一组。

### 9.2 独立统计单位

- 主 bootstrap 单位：layout ancestor；
- episode 只作为 ancestor 内的重复测量；
- 报告 ancestor 数、episode 数和每个 ancestor 的失败分母；
- 用 Kendall/Spearman 和 bootstrap CI 报告排序稳定性；
- 对 H1/H2/H3 预注册效应量、置信区间和停止规则；
- 发生 OOM、timeout、crash、not-returned-home 时保留为失败，不从分母删除。

### 9.3 结果表必须分开

至少分四张表：

1. confirmed-recall AUC / final recall；
2. free-space 与 inspection-footprint coverage；
3. safety、deadline、return、collision；
4. compute、communication、energy 和 planning latency。

安全不能与召回率任意加权成一个总分。

## 10. 长任务成本怎么降，而不改变任务

公开平台的共同做法是分层成本，而不是缩短正式任务：

1. **headless 与向量化**：L0 关闭不必要渲染，批量运行不同 seed，但保留独立 episode hash；
2. **静态预编译**：atlas、邻接和安全候选只编译一次，以 hash 缓存；
3. **低频高层决策**：planner/RL 低频选择下一个公开候选，CF2X controller 和物理小步不降级；
4. **事件触发传感器**：geometry 主榜不要求 RGB，RGB-D 只在合法 OBSERVE/L2 触发；
5. **successive halving + L1 回查**：L0 只筛选少量候选，并随机回查被淘汰方法，估计 L0 误杀率；
6. **只保留必要 replay**：完整失败原因、hash 和小型摘要永久保留，大体积无复用价值的渲染视频可清理；
7. **先小矩阵后扩展**：先 3--6 个 calibration ancestor、少数方法和 2--4 机闭环，未通过门禁不得扩展。

不能做：把 300 秒模拟执行时钟改短、删掉 deadline failure、用 L0 成绩替代 L1、删除难例后重新计算分母。

### O0：合同冻结

- [ ] v3 strict `1.0x` sector manifest 固定；
- [ ] coarse/full atlas schema、cell density 和 sampling constants 固定；
- [ ] 目标过程、目标数量可见性、确认/返航/失败分母固定；
- [ ] 记录 method-independent decision log；
- [ ] 禁止访问 formal test。

- [ ] atlas-only target/process/split leakage probe；
- [ ] target/distractor swap 和 paired process test；
- [ ] 所有 cell、climb、transit edge 经过 collider authority；
- [ ] area/opportunity-weighted inspection metric 与 runtime 语义一致；
- [ ] coarse/full、density、process 消融完成。

### O2：L0 公开可搜索性

- [ ] oracle 可行并返航；
- [ ] 至少一个非 oracle 在中等难度 ancestor 稳定非零；
- [ ] 公开方法未全饱和、未全为零；
- [ ] 所有 deadline、safety intervention 和 return 失败均保留；
- [ ] 若公开方法不返航，不能通过 O2。

### O3：CF2X L1 闭环

- [ ] 真实 `assets/new/cf2x.usd`；
- [ ] 四机城市障碍/窄通道/转场闭环；
- [ ] action → controller → PhysX → OBSERVE → receipt → return；
- [ ] 零碰撞、零越界、无未解释 deadline failure；
- [ ] 每次 replay 绑定六类 hash。

### O4：L0/L1 排名有效性

- [ ] 预注册 Spearman/Kendall 相关性；
- [ ] 记录 L0 淘汰误杀率；
- [ ] 对 L1 失败按控制、碰撞、观察新鲜度、规划延迟分类；
- [ ] 若排名反转，不得继续用 L0 作为筛选器。

### O5：外部接入

- [ ] G2-I public projection 和 action ABI 文档；
- [ ] 一个锁定上游方法或 clean-room 方法通过独立 runner；
- [ ] 无私有字段、无绝对路径、无手工补丁；
- [ ] clean environment 可安装并复现小型 development release。

### O6：正式矩阵与统计功效

- [ ] 根据 ancestor 方差完成 power analysis；
- [ ] 固定 train/validation/test ancestor；
- [ ] 先跑少量 L1 shortlist，再扩展；
- [ ] formal test 只在所有前置门通过后打开。

### O7：发布门

- [ ] CC0-only 或每种许可证的完整 notice；
- [ ] NVIDIA/Nucleus/private hash 拒绝；
- [ ] USD 依赖闭包；
- [ ] data license、asset BOM、software SBOM、manifest 签名；
- [ ] CF2X 分发权明确；否则保持 local-runtime-only，不能随 wheel/数据包发布。

## 12. Fail-closed 规则

以下任一条件出现，正式实验必须停止，且不能通过删除结果解决：

- 非 oracle 全部零确认；
- 所有非 oracle 都在 deadline 前无法返航；
- atlas 字段能预测 target/process/split；
- cell density 改变导致分数定义改变；
- L1 发现 L0 的核心排序是由简化执行制造的；
- 公共 adapter 读取私有字段或补给全局真值；
- 目标或障碍生成器存在未解释的索引周期；
- 资产路径、许可证、USD 依赖或 CF2X 分发权不闭合；
- failure ledger、raw replay 或 environment fingerprint 丢失。

正确的恢复动作是：锁定影响的 layout/atlas/result lineage，保留失败摘要，生成新版本 hash，重新跑受影响 calibration；不是降低门槛或覆盖旧报告。

## 15. 当前状态结论

截至 2026-08-01，本项目是一个**设计方向合理、已有大量工程基础、但尚未通过科学有效性和真实 L1 证据门的 calibration prototype**。

之前的工作没有白费：资产审计、私有 evaluator、atlas schema、target-process pairing、CF2X controller contract、L0 运行时、失败记录和 external bridge 都是后续闭环的必要基础。它们现在的正确定位是“可审计基础设施”，不是“已经证明论文主张”。

最重要的下一步不是继续增加功能，而是完成 O1→O4 的最小证据链。若该链成立，论文将有一个清晰且可防守的制胜点；若该链不成立，应尽早缩小主张，避免在不可搜索任务、L0 假象或 QD+RL 组合创新上继续消耗 GPU 与时间。

## 16. 2026-08-02 反复试错审查修正

本轮发现一个具体的证据污染案例：历史 `layouts-v9` 将
`fixed_target_count_private` 写入 `method_public/task_spec.json`。所以历史三 ancestor
CF2X `v12` 回放虽曾在其自身汇总器中显示通过，但不再具备公开方法、L1、外部兼容或论文主张
证据资格。它说明“公开输入边界曾失效”，不是“B 门曾关闭”。

这件事同时定义后续纪律：工程问题可以在**不改变合同**的条件下修复并重跑；任务可搜索性、
公开信息、预算、指标、样本和排除规则只能通过方法无关 calibration 决策改变，且必须升版本。
`experiment-governance-v1` 已把旧 A 门与 v16 作为不同执行哈希下的历史校准隔离。由于注册表哈希已经
变化，旧外部证据清单不能复用；源码独立审计在未提供当前注册表绑定的新清单时应封闭为
`CONTAINMENT_FAIL_FORMAL_NO_GO`。即使新清单把隔离审计提升为
`CONTAINMENT_PASS_FORMAL_NO_GO`，也不授权正式主矩阵或 MAPPO/QD+RL 长训练。下一步是在当前规划
节拍合同下重做方法无关 A 门，随后完成三上下文行为审计和 B 门，而不是继续引用旧结果。
