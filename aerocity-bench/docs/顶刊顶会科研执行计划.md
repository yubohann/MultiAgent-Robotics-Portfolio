## 0. 激活规则

本文件定义 AeroCityBench 从可信普通论文版升级为顶刊顶会级 benchmark 的增量路线，不是当前并行开发清单。

只有同时满足以下条件，才能把本计划状态改为 ACTIVE：

1. 普通论文版 O0–O5 全部完成；
2. 普通版 release candidate、科学报告、分析脚本和结果 hash 已绑定 Git commit；
3. 原生 geometry evaluator、OBSERVE、ConfirmationReceipt、返航和 reset 闭环通过；
4. generator/target red-team 不再存在决定性规律或几何违规；
5. 至少 3 个 substantive 非自有方法在相同权限下原生闭环；
6. 独立 calibration pilot 显示 coverage-to-search 存在可重复测量增量、稳定失败族或方法选择价值；
7. 公开 core 资产最小法律门通过；
8. 团队书面冻结投稿族、硬件/计算资源、人员、负责人和增量周期；
9. 顶刊路线不会通过查看 `aerocity-method` 结果污染 benchmark 校准。

若第5项不成立，不通过增加故障、多模态、资产数量或排行榜功能制造表面创新。可以继续维护普通版软件，但停止顶刊benchmark路线。

## 1. 顶刊顶会目标

### 1.1 暂定题目

> AeroCityBench: Beyond Coverage in Physics-Grounded 3D Multi-UAV Search

### 1.2 完整中心命题

> 在统一物理、观察动作、有限视场、信息权限和资源预算下，coverage-centric 评价是否会系统性误判三维多无人机目标搜索能力；受控目标空间过程、未见城市拓扑和真实/跨系统执行是否揭示稳定的方法排序变化与失败机制？

顶刊顶会版的关键不是功能数量，而是完成以下证据闭环：

~~~text
现有评价缺口
  -> 严格任务与权限合同
  -> 多类真实外部方法
  -> 受控三维目标过程
  -> 统计稳定的测量发现
  -> 跨系统/HIL/真机外部有效性
  -> 独立复现与长期治理
~~~

如果没有会改变研究者方法选择的实证发现，程序生成、Isaac、接口、盲测和大量资产只能证明平台成熟，不能单独构成顶刊贡献。

## 3. 研究问题与证伪

### RQ1：coverage 能否预测严格三维搜索

H1：控制城市、目标、起点、时间、信息权限、控制器和预算后，coverage AUC 不能充分预测 confirmed-recall AUC，三维合法观察特征提供稳定的样本外增量。

强证据至少包含：

- 预注册方法对出现稳定排名反转，并在 IID、topology OOD 和至少一个外部系统上重复；或
- coverage 相近的方法出现稳定不同的三维漏检失败族；或
- 2D-only 难度模型明显弱于加入高度、法向、遮挡、可见立体角和确认成本的模型。

反证：排名高度一致、三维特征无增量，或所有差异由adapter、权限、target count和生成器指纹解释。

### RQ2a：训练可见目标过程的受控交互

在 train/validation 中均提供 uniform、clustered 和 height-stratified；正式 paired test 固定城市、起点、目标数和预算，比较 `method × process` interaction。

只匹配会造成明显混杂的边际难度变量，不要求把三种过程的所有 opportunity 特征完全做成相同，否则会消除过程本身。报告匹配前后分布和残余差异。

### RQ2b：未见目标过程的 OOD 泛化

单独构造未见过程参数、support组合或新过程族。RQ2b 与 RQ2a 分榜、分模型、分结论，禁止把未见训练过程的下降直接解释为纯空间过程效应。

### V1：独立三维性有效门

固定高度、高空一次扫描、2D sweep 和2.5D planner不能接近完整3D。若接近，必须收紧确认范围、观察方向或目标布局，或者撤回三维独立性主张。

### V2：opportunity 有效门

opportunity只作诊断。合法view、可见立体角、最短确认成本和遮挡分层必须跨重复Isaac执行稳定，并对合理阈值不敏感；否则删除派生指标，保留raw confirmed recall。

### V3：生成与split有效门

道路图、建筑、可飞域和遮挡可以预测结构split；颜色、ID、模板名、资产数量、seed和路径不能预测split。nuisance classifier成功即release失败。

### 条件性RQ3：机群减员

只有普通版核心任务稳定后，并且pilot证明nominal/fault方法排名不同或容量损失与重协调损失可重复分解，才升级：

- `NOM(N)`：N机无故障；
- `LOSS_k(N)`：N机起飞、中途损失k机；
- `NOM(N-k)`：从开始只有N-k机；
- fault-aware oracle：私有诊断上界。

若不能提供独立排序信息，减员进入 `track-resilience`，不进入 Paper I 题目。正式 release freeze 前不给该轨预占语义版本号。

## 4. 不变的任务与权限合同

### 4.1 geometry-search-3d / G2-I仍是唯一候选主榜

~~~text
reset
  -> 多机起飞
  -> 依据公共检查图进行系统检查与协作
  -> 显式 OBSERVE
  -> timestamp/source_observation_id 观测
  -> evaluator检查range/FoV/LOS/normal/dwell/freshness
  -> 匿名ConfirmationReceipt
  -> 去重、继续搜索、返航或超时
~~~

geometry主榜使用理想几何检测器，不评价对象识别。precision、F1、PR-AUC和检测校准只属于perception track。

普通版 `Canonical Execution Semantics`、任务时钟、OBSERVE 稳定/冷却、virtual sensor rig、通信、安全控制器、碰撞资格和运行前 target-validity manifest 全部原样继承。顶刊升级不得静默改变这些语义；任何改变都新开 benchmark major version 并重跑全部方法。

### 4.2 G1-U 与 G2-I 的版本边界

普通版公开可搜索性审查已推翻“G1 可直接作为隐藏目标搜索主榜”的假设：G1-U 只提供粗略先验与局部 occupancy，完整公开表面扫描在300 s内不可行。顶刊版继承此结论：`G1-U` 仅是 target-free exploration/coverage track；唯一候选主榜是尚未科学冻结的 `G2-I`，即在G1-U上增加目标无关公共检查图。严格 L0/CPU 合同、mission sector、coarse/full prior 和泄漏审计已实现，但不等于公开方法、L1 或科学有效性已经通过。2026-08-01 的 v4 L0 重跑显示 private oracle 在 5/5 ancestor 返回、零碰撞；公开方法仍未达到正式 bracket，不能改写为正式结果。

`G2-I` atlas 有两个独立版本化 prior：`coarse-regions` 只给结构区域、类别、粗略边界、面积和高度带；`full-cells` 再给检查单元/姿态包络、表面几何与安全转场图。二者独立消融且不可混榜。两者都绝不公开目标坐标/数目/ID/过程、support site、私有witness/ray、target label、split或seed。atlas必须先于私有目标过程冻结，并通过配对过程不变性、private-field rejection和统计泄漏 probe。未完成公开方法与 native 门时，顶刊路线不得激活、不得读取formal test、不得将G1-U结果提升为主榜成绩。

不同权限必须分榜：

- G1-U：局部occupancy voxel，仅 exploration；
- G2-I：G1-U + target-agnostic inspection atlas，唯一候选 geometry 主榜；
- G2-R：有限FoV range/point，独立传感器 profile；
- P1：RGB-D perception；
- C1：低层控制；
- O1：完整地图oracle。

不能为增加方法数量而混榜。

### 4.3 私有真值

方法不可读取目标数、坐标、support sites、目标过程、合法view、split/OOD标签、随机种子、故障身份或评测器内部ray。容器只挂载capability profile允许的投影。

allow-list projection只是权限合同，不自动构成安全沙箱。blind evaluator需要独立进程、只读挂载、网络策略、审计日志和提交治理。

## 5. 顶刊级生成器与目标过程

### 5.1 Road-graph和城市祖先

road grammar至少覆盖：

- T型路口、断头路、环路和阻断边；
- 非正交连接、偏移路口和层级道路；
- 不同连通度、瓶颈、多入口街区；
- 低、中、高层建筑的不同组合语法；
- edge、intersection、courtyard和distributed spawn。

train/validation/test按road-graph ancestor和组合语法隔离，不只换seed。

### 5.2 几何与物理权威

同一CitySpec和collider权威派生visual、collision、depth/range、flyable volume、support、evaluator ray和coarse prior。必须验证：

- 零非法collider穿插、悬空、越界；
- 起点、目标view和返航安全可达；
- 通道、净空、制动距离和UAV-UAV separation；
- city switch后sensor、contact、packet、target、fault和RNG无残留；
- fixed scene重复执行的时序与几何容差。

### 5.3 目标与distractor

目标依附roof、facade_marker_site、entrance或rubble真实表面，记录surface lineage、面积权重、法向、允许观察锥、结构上下文、合法view、可见立体角、最短确认成本、遮挡率和可达性。

目标不能完全空旷、固定距离贴障碍或形成规则层高。为目标生成上下文匹配的无目标distractor，并做同几何反事实换标。

### 5.4 Generator red-team

必须完成：

- intended与nuisance split probes；
- 图同构和连续特征近重复检查；
- 图像embedding nearest-neighbor检查；
- 资产、颜色、文件顺序和seed shortcut检查；
- 2D-only与3D难度模型对照；
- 自动拒绝报告和人工分层视觉审查。

## 6. 资产与视觉质量

顶刊版不靠资产数量证明贡献，但必须避免视觉单调和生成器指纹。

### 6.1 资产层级

- `official-mini`：3–5个模型，用于CI和安装；
- `official-core`：普通版选择并验证的约36模型+18材质；
- `official-visual-full`：在core基础上扩展到所有经过USD闭包、碰撞、尺度、语义和性能验证的CC0资产。

完整Poly Haven源包有91项，其中61个模型、30套材质。顶刊版不承诺全部使用；损坏、重复、高成本或不合语义的资产必须排除。

Kenney只有在完成逐包作者/许可/转换链、统一USD、碰撞和性能验证后才可进入独立扩展bundle。NVIDIA/Isaac Sim官方Content始终不随benchmark再分发。

### 6.2 视觉与难度解耦

资产主题、材质和光照不得与split、目标过程或目标标签确定性绑定。视觉美观作为发布门，不作为排行榜分数。

训练可以使用低分辨率材质和简化渲染；正式geometry评分保持原生几何，论文回放使用同一CitySpec、动作、controller和evaluator进行高质量F2渲染。

### 6.3 语义细节预算与任务不变性

顶刊路线要求城市丰富度可解释、可复核且不把渲染成本伪装为任务难度。结构语义层仅包括建筑主体、受限数量的女儿墙、入口雨棚、屋顶设备和语义障碍物；它们拥有 collider/ray authority，并进入 `task_geometry_hash`。道路风格、人行道、标线和外部 CC0 装饰均属于 visual-only 层：没有 collision API，且不进入 `task_geometry_hash`。

任何 visual-only 变体都必须保持目标、起点、coarse prior、任务时钟和 evaluator witness 不变；结构细节则必须通过零正体积 collider 交叠、宿主附着、目标支持面隔离、可达性和性能预算门。论文必须报告每类城市的结构 collider 数、visual prim 数、L1 RTF、显存和渲染开销分位数，不能只展示挑选出的漂亮视频。`ordinary-v3.1` 的定向静态测试只是开发证据；顶刊激活前仍需独立分层审计、L2 图像审查和 L1 原生复核。

## 7. 多保真与外部有效性

### 7.1 执行保真层与外部验证模式

| 层级 | 内容 | 作用 |
| --- | --- | --- |
| L0 | 解析几何/体素/简化动力学 | 高吞吐训练与调试 |
| L1 | Isaac headless原生物理、ray、控制、回执 | geometry正式评分 |
| L2 | Isaac完整渲染、RGB-D和精细传感器 | perception、视频和内部一致性 |

使用配对参考策略测量 L0/L1/L2 bias、排名相关性、安全漏报和淘汰误差。execution level 写入 receipt 和 replay provenance。

跨模拟器、HIL 和真机不是单调的“更高保真 F3”，分别命名为 `X-SIM`、`X-HIL` 和 `X-REAL`。每种模式独立记录硬件、软件、传感器、控制器、场地和可复现边界，不得互相替代后仍声称完成相同证据。

### 7.2 外部有效性最低要求

topology OOD属于模拟器内部泛化，不得称为外部有效性。

顶刊版至少完成一种：

1. 跨模拟器复现相同coverage-to-search趋势；
2. HIL复现至少一个排名或失败机制；
3. 2–4架无人机在缩比模块化城市/可控marker中复现趋势；
4. 更强目标下完成真实城市或室外受控飞行子集。

具体选择必须在 T0 根据投稿族预注册，不能在看到结果后从 `X-SIM/X-HIL/X-REAL` 中挑最有利的一种。机器人系统型投稿默认要求 `X-HIL` 或 `X-REAL`；ML benchmark 型可以 `X-SIM` 为主，但必须降低真实飞行主张。

任何 `X-REAL` 在执行前必须通过场地与空域许可、飞手/观察员职责、失控与急停、保险、视频隐私、天气和事故报告 gate。`X-SIM` 必须单独审计另一模拟器的运行时、资产和许可证。

如果目标期刊强调真实机器人系统，只有跨模拟器而无HIL/真机时必须降低主张。

外部实验不要求复现全部大矩阵，但必须预先选择方法、场景和结论，禁止只挑仿真最漂亮的结果。

## 8. 顶刊正式基线矩阵

### 8.1 八个方法上限

4. decentralized atlas auction/Voronoi；

- random-safe下界；
- centralized oracle；

### 8.3 外部系统接入

顶刊版实现：

- PlannerAdapter；
- PettingZoo ParallelEnv和GymnasiumFleetWrapper；
- ROS2Bridge；
- 必要时独立ROS1容器和ROS1/ROS2 bridge；
- ReplayAdapter和标准离线轨迹；
- capability negotiation、adapter tax和机器可读失败原因。

FUEL、RACER、FALCON等GPL或许可证复杂工程保持独立仓库/容器，通过ROS、进程或文件协议接入。不能复制到BSD核心。每个外部声明必须同时给出 URL、完整 Git revision、许可证和执行边界；container 必须固定 OCI `sha256` digest。当前 `ExternalProcessPlannerBridge` 已实现 G1-U/G2-I public-only JSON ABI，但只接受真实 `process` 声明，不能伪装为容器或 ROS runner。FUEL 的锁定 GPL 来源已在独立 Focal/Noetic 容器完成最小规划包构建，并完成断网、只读 ROS 图烟雾；它接收公开风格里程计/位姿/点云但未发布路线，因为 G1-U 的 2 m 占用体素不具备其细粒度传感器射线与自由空间语义。不可用私有 mesh 或改写上游阈值弥补该差异。因此 FUEL 仍没有可发布 OCI digest、G2-I 回放或上游闭环，也不得再被列为 G2-I bridge 候选。container/ROS 声明必须由实际 container/ROS runner 启动，不能借用此 Python 子进程伪装；所有 Python 内嵌 adapter 继续拒绝 process/container/ROS 声明。

## 9. 学习方法训练与公平预算

学习方法只在 G2-I 公开可搜索性 calibration 通过后使用与普通版相同的 L0 训练、L1 正式重跑原则，并增加：

- 至少3–5个训练seed，数量由方差和预算预注册；
- 统一环境交互预算和额外GPU小时披露；
- checkpoint只在validation选择；
- CTDE训练状态与decentralized执行投影分离；
- 网络规模、预训练数据和外部模型权重单独披露；
- planning方法与学习方法同时报告wall-clock、延迟和deadline miss；
- 不使用私有test leaderboard反复调参；
- 对低保真淘汰的方法随机回查，估计successive-halving误杀。

公平不等于所有方法训练时间完全相同，而是预算透明、权限一致、停止规则预注册、正式闭环相同。

## 10. 指标与统计设计

### 10.1 主指标

\[
AUC_{recall}=\frac{1}{T}\int_0^T \frac{N_{confirmed}(t)}{N_{valid\ targets}}dt
\]

### 10.2 回答RQ的指标

- G1-U free-space coverage AUC、G2-I inspection-footprint coverage AUC与confirmed-recall AUC；
- final recall和time-to-first/k-percent recall；
- coverage-to-search paired gap；
- Kendall/Spearman排名变化；
- method × process interaction；
- topology/process/scale OOD下降；
- altitude、support、opportunity和worst-group recall；
- failure spectrum与反事实换标表现。

### 10.3 安全、资源、通信与计算

- 环境/UAV-UAV collision、最小净空、越界和硬约束违反；
- 返航率、路径、能量和每确认目标成本；
- simulator wall-clock与real-time factor；
- planning latency median/p95/p99与deadline miss；
- bytes、packets、drop、stale rejection和断连时间；
- 重复搜索、未分配区域、Jain/Gini均衡。

安全是硬约束，不与recall加权成不透明总分。

### 10.4 统计协议

- 独立单位为road-graph/layout ancestor；
- 使用ancestor-level paired summaries或层级模型；
- method和process为固定效应，ancestor/layout为随机效应；
- 报告IQM、performance profile、stratified bootstrap和置信区间；
- 预注册最小有意义效应、alpha、功效、多重比较和停止条件；
- 失败、超时、崩溃、无法适配和missing data进入分母；
- 发布原始聚合表、分析脚本和结果hash。

## 14. 多模态、世界模型与VLA路线

顶刊benchmark计划不自动把多模态纳入Paper I。它们是可选择的v2路线：

### track-world-model：世界模型和离线轨迹

- 标准化observation/action/next_observation/receipt/failure轨迹；
- 提供ReplayAdapter；
- 先验证一个小型世界模型或model-based planner；
- 闭环Isaac成绩与离线预测指标分开。

### track-perception-vlm：perception-search-3d与VLM

- 目标具有真实视觉实例；
- RGB-D、标定、延迟、丢帧和检测输出；
- precision、recall、PR-AUC、calibration和检测延迟；
- 不能用geometry evaluator自动补全视觉检测失败。

### track-high-level-vla-vln：高层VLA/VLN

- 高层VLA输出冻结的waypoint/observe/return动作；
- VLN引入语言任务后独立定义任务和指标；
- 模型、提示词、权重、训练数据和推理预算披露。

### track-low-level-vla：低层端到端VLA

直接输出速度、姿态或电机动作时进入独立control track，重新定义控制频率、安全、延迟和硬件验证。不能与使用统一低层controller的规划方法混榜。

是否选择多模态路线取决于独立科研问题和资源，不作为顶刊Paper I的保底功能。

上述名称是研究 track，不是 release 版本。只有任务 ABI、数据迁移和兼容性边界冻结后才分配 `1.x/2.x` 语义版本，避免 resilience、世界模型和 perception 争用同一版本号。

## 15. 顶刊顶会增量阶段

### T0：激活审查，1–2周

审查普通版科学发现、投稿目标、资源、外部合作、硬件和法律状态。形成书面GO/NO-GO。

### T1：扩展生成与统计，4–8周

扩大祖先语法、topology/process/scale OOD，完成shortcut probes、功效设计和预注册。

### T2：6–8正式方法，6–12周

完成两个公开三维系统、一个MARL、ROS/容器、预算与adapter tax。失败方法保留在分母。

### T3：多保真与外部有效性，6–12周

完成 L0/L1/L2 bias 和预注册的 `X-SIM/X-HIL/X-REAL` 子集，并复现至少一个预注册趋势或失败机制。

### T4：独立复现与盲测，4–8周

第二机器、第二操作者、外部adapter接入、blind evaluator和提交治理。

### T5：正式实验与统计，4–8周

执行预注册矩阵，完成层级分析、failure spectrum、消融和负结果审查。

### T6：供应链与release freeze，3–6周

完成依赖闭包、NOTICE、SBOM、签名、cards、DOI、容器和长期归档。

### T7：论文与复核，4–8周

冻结结果hash、图表、补充材料、复现实验和匿名发布包。

阶段可以部分重叠。若从零开始计算：

- 单人：约9–16个月；
- 2–3人并行：约7–12个月。

若普通版已完成，2–3 人并行的顶刊增量通常仍需约 4–9 个月；单人更现实为约 7–12 个月，主要取决于外部方法、硬件、独立复现和 blind evaluator 运维。周期指开发到投稿候选，不包含审稿与返修。

## 16. 退出、降级与停止条件

立即停止顶刊扩展的情况：

- coverage-to-search没有稳定增量；
- target-process interaction来自生成器偏差或训练分布混杂；
- 外部方法无法在公平权限下闭环；
- topology OOD被错误包装成外部有效性；
- HIL/真机趋势与仿真完全不一致且无法解释；
- 统计功效需要不可承受的计算预算；
- blind evaluator泄漏或提交治理失效；
- NVIDIA/专有资产、未知许可证代码或不合规GPL派生进入公开核心；
- 第二团队无法按文档复现核心任务。

顶刊路线停止后，普通论文版仍可以独立维护，但不得把未完成的顶刊功能写入其贡献。

## 20. 2026-07-31 顶刊路线补充门

2025--2026 的 FlightBench、FALCON、Aerial Gym、MARVEL、EmbodiedBench 和 AeroVerse 不能被当作“已有相似项目”的笼统引用。它们分别要求本计划补齐以下可证伪证据：

| 外部启示 | 对 AeroCityBench 的硬要求 |
| --- | --- |
| FlightBench | vehicle、controller、sensor、task 分离；性能、传感器和控制成本共同报告；GPL 基线保持在独立容器/进程边界外 |
| FALCON | 所有方法使用相同 vehicle/controller 环境；顶刊路线至少完成 X-SIM、X-HIL 或 X-REAL 中预注册的一种 |
| Aerial Gym | 机器人、推进器、传感器、任务模块化；把渲染成本与动力学吞吐作为可测系统变量 |
| MARVEL | 有限 FoV、去中心化执行、通信和权限是方法合同，不得由 adapter 暗中补全 |
| EmbodiedBench | evaluator 修复可能废止历史分数；必须保留 major leaderboard、withdrawal、replay migration 和公开事故记录 |
| AeroVerse | 大规模和多任务不能替代清晰的测量主张；无官方实现仓库时不得宣称复核其代码 |

CF2X 只作为本地、哈希锁定的运行时依赖，未获再分发许可前不得进入公开 release。它的四个旋翼推力经独立 `ThrusterCfg` 状态和 CF2X 几何 allocation matrix 映射为根刚体 PhysX wrench，不能表述为四个 prop-link 外力。2026-07-31 的候选控制器已通过两个独立进程的 30 s 定点原生悬停，以及一个带最大 `0.0385 rad` 倾斜的 30 s 横移保持；门禁检查后段高度斜率、全程/末端高度误差、末端垂直速度和零接触。这只消除了慢性下沉的预飞行风险，既不替代真实机参数标定，也不替代城市碰撞、多机闭环或外部有效性。顶刊实验开始前仍必须完成五项 CF2X gate、L0/L1 排名偏差研究、至少三个实质性外部方法的 L1 闭环、完整 shortcut red-team 和一个预注册的外部有效性子集。任何一项不足时，本计划继续 `CONDITIONAL / NO-GO`。

未来 L1/G2-I 主榜无 RGB 输入；当前L1/G1-U只作工程/探索预飞行。L2/P1 RGB-D/分割仅在 OBSERVE/dwell 以 2--5 Hz 事件触发；`96x69` 和 `160x120` profile 不得混榜。顶刊结果必须额外报告 PhysX-only、ContactSensor、depth、RGB-D、RGB-D+instance 的吞吐矩阵与 profile 重标定过程。

场景丰富度证据也必须避免泄漏私有任务：每布局静态 receipt 只能写公开几何计数、任务/布局 hash 和类别化错误；不得写 target/support-site cardinality、私有 ID、坐标、witness、目标过程或原始 admission 文本。2026-08-02 已完成 train/validation/calibration 各四座、共 12 座开发城市的静态 receipt，所有布局 hash 唯一且通过；这只满足分层静态审计数量，仍须完成 L2 抽查与 L1 吞吐/碰撞/恢复复核，不能作为顶刊 visual gate。

2026-07-31 又补上一项必要但不足的工程门：内部单机 CF2X vertical slice 的 private evidence chain 已可离线 fail-closed 复核，逐条绑定 native action/状态、`OBSERVE`、confirmation、failure 和 return closure，并对删 receipt、错误 confirmation 归属、伪造无 RETURN 成功三类篡改回归失败。它不得写成“顶刊级原生 episode 已实现”：仍是单机、私有 fixture、`formal_score_eligible=false`，不含四机策略执行、公开基线、跨城市统计或外部有效性。

同日，外部集中式 G1-U 方法获得实际 JSONL process bridge，而不再只有 declaration。它保留 licence 进程边界、public-only packet projection、schema/request/action roster 校验、响应大小/时限与 adapter tax；本地 audit sentinel `target_count_public=false`/`target_process_public=false` 会在 process wire 的所有嵌套层级移除，target/evaluator/private 字段的大小写和连字符变体以及非 ASCII JSON 键会 fail closed。它不是 blind sandbox，不能取代G2-I atlas bridge、container digest runner、ROS graph、独立复现或任何外部 baseline 的 L1 结果。因此顶刊状态不因该接口变更而上调。

目标过程编译也不能靠无界重复计算维持规模：同一 layout、同一支持点集、同一成组起飞和执行合同的安全天空走廊证明允许使用进程内有界、深拷贝缓存，但缓存只优化生成时间，不改变 private witness、目标过程或正式评分，并须通过 paired-process reuse 和 mutation-isolation 回归。顶刊路线还要在更大 layout/多机配置测量缓存命中率、峰值内存和冷启动时间，避免将缓存收益误报成方法吞吐收益。

同日 G2-I 风险门完成一次严格 CPU 修复与五 ancestor 审计：inspection coverage 改为完整观察合同下的面积加权诊断；atlas admission 检查机体边界/净空、range/FoV/facing/LOS、显式 surface point 和 safe-sky climb；转场图有连通 MST backbone；Planner/JSONL process 支持 G2-I public-only 投影；匹配 target/distractor probe 未检测到显著信号。5/5 atlas 为 `PASS_CPU`，但完整 dwell 工作量仍超 300 s、split probe 样本不足，且没有 public non-oracle 多城确认、四机公开 L1 或 L0/L1 排名证据。因此顶刊状态仍为 `CONDITIONAL / NO-GO`。
