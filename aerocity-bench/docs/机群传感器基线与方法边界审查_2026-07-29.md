# AeroCityBench 机群，传感器，基线兼容性与方法范围权威审查

日期 2026-07-29

状态 `ACTIVE INPUT TO EXECUTION_PLAN / 2026-07-31 G2-I TASK-SEMANTICS REVISION`

适用范围 AeroCityBench，Paper I benchmark。自有方法只在本地 `experiments/aerocity-method` 工作区继续研究。

## 1. 结论

1. 四机是核心规模，适合跑完整基线矩阵。QD 有效性和机群规模泛化由 fleet-scaling 子矩阵单独检验。
2. 官方候选分层为 core-search `N=4`。fleet-scaling `N={2,4,8}`。resilience `N=8,k={0,1,2}`。`N=12` 仅在 Isaac 吞吐 pilot 通过后作为 large-swarm stress。自定义配置可支持 `N=1..32`，但不混入官方榜。
3. 深度相机是未知三维局部建图/避障的一种 modality。方法还可消费等价的 occupancy，voxel，range 或 point-cloud 观测，目标确认条件与传感器档位分开定义。
4. geometry-search 必须由 scorer 检查 `range + FoV + LOS + surface-facing + dwell + source_observation_id`，接近目标固定半径只提供候选线索。
5. RGB/RGB-D detector 属于单独的 perception-search 轨。它报告检测精确率，召回率，时延和任务结果，不与 geometry-search 排名混合。
6. benchmark 兼容更多论文的关键是提供分层 observation capability，三类 adapter，标准 transcript，target-free exploration任务，以及对隐藏目标搜索足够且不泄题的公共检查图。
7. 旧 RB-SF-SAC，successor features，ActionToken，receipt 与 realised-QD 没有从磁盘删除，但只作为 Paper II 的可审计工程资产。旧 CCUQD 理论候选失活，其去向以本仓库权威计划为准。

## 2. 四机是否限制 QD，把三个问题分开

### 2.1 benchmark 的统计与工程问题

四机能产生协同，重复覆盖，通信，碰撞和分配问题，并且相机/物理吞吐仍可承受，因此适合作为完整方法矩阵的 core。若把所有正式实验直接改成 8--12 机，GPU 相机数，同步等待，碰撞对和消息边会增加。最终可能只能减少 layout 或 seed，反而损害论文。

### 2.2 机群规模泛化问题

只跑四机不足以回答方法是否对 team size 稳健。MARVEL 以 4 agents 为标准设置并测试不同 team sizes。GS-MARL 的公开仓库用 3-agent 训练展示到更大规模的 zero-shot 演示。它们说明训练规模与测试规模分开值得测，其二维/MPE 结果能否迁移到本 benchmark 需要单独验证。

因此设置 `N={2,4,8}` 的代表性 fleet-scaling 子矩阵。它选择 3D sweep，强 frontier，decentralized allocation，MAPPO/RMAPPO，graph policy 与 oracle，覆盖代表性组合。

### 2.3 QD 的科学问题

`N` 大不自动使 QD 有用。QD 只有在以下事实经实验证明时才有意义。

- 同一公开 atlas 任务存在质量相近但区域责任，结构类别，高度带，冗余检查或通信行为不同的策略。
- 不同公开 atlas，已检查历史，匿名确认回执，通信图或减员条件会选择不同 repertoire 成员。若 target-process 变化完全私有且可见上下文为空，QD 与强 MAPPO 的差距会缩小。
- repertoire 的切换收益大于档案构建，重计分和适配成本。
- 行为描述符只使用公开行为特征，目标真值，确认数，recall，coverage分数，奖励，故障真值和编队紧凑度保持隔离。

因此 Paper I 的机群规模校准以规划方法为主。Paper II 若要证明 QD 价值，必须报告 repertoire coverage，selection regret，切换成本和 no-QD/随机策略集/普通 ensemble 对照，无人机数量只作规模维度，证据以对照实验为准。

在 AeroCityBench 中，QD+RL 只能位于冻结后的 G2-I 外部验证层。QD 维护公开检查图上的责任方案库，RL依据atlas，已检查历史，匿名确认回执，能量，通信与安全状态选择下一候选，统一CF2X controller执行 `GOTO/OBSERVE/RETURN`。QD 只维护责任方案库，电机控制与 Paper I 主榜设计保持独立。现有 G1-U 的公开搜索对象定义待补充，QD+RL 长训练以其通过为前提。`md_qd_swarm`历史中形成的编队紧凑度/邻居负载档案轴发生过archive collapse或以安全换多样性，其复用以新的真实执行可控性实验结论为准。

## 3. 为什么 resilience 主轨用八机

四机损失两机后只剩两机，容量损失容易压倒重协调差异。八机损失一或两机后仍有六到七个存活成员，才有足够空间观察 relay，区域责任，重复覆盖和 workload 的重新组织。

正式候选对照必须同时存在。

```text
F0(8)      : 八机全程无故障
Fk(8)      : 八机起飞，中途损失 k=1/2
F0(8-k)    : 从开始只有 7/6 机
Oracle(8)  : fault-aware centralized reassignment
```

`Fk(8)-F0(8)` 是总减员效应。`Fk(8)-F0(8-k)` 更接近检测/重协调代价。第三个对照用于区分飞机减员和算法恢复失败。具体 `N=8` 仍是 pilot 假设，若原生吞吐或方法区分度失败，可在预注册前调整，blind test 后保持冻结。

## 4. 传感器与目标确认的完整条件

### 4.1 文献实际采用的抽象

- Visual Drone Swarm 使用前向彩色相机，把目标搜索，接近，避障和感知耦合。
- MARVEL 研究受限 FoV 和固定 sensing range 内的无遮挡 frontier utility。其核心是二维 occupancy exploration，并非离散目标分类。
- FUEL 支持 depth image 或 point cloud/LiDAR 形成三维探索输入。
- RACER/FALCON 类方法消费点云，occupancy 或外部地图，其输入不以 RGB-D tensor 为准。
- MRIPP Target Mapping 使用 RGB-D，但仿真中使用 ground-truth window discovery。这是一种公开的几何任务抽象，区别于视觉识别。
- STAR-Searcher 使用 LiDAR+RGB camera，仿真最大识别距离约 3 m，相机 FoV 约 `[68°,51°]`，且确认受可见性和朝向约束。并非欧氏半径命中。
- FlightBench 提供 ground-truth depth 与 SGM depth 选项，并把 3 m/s 作为统一比较速度，说明 sensor fidelity 和 planning/control 应分开记录。

结论是，统一可用信息语义，原始传感器张量保持各自形式。

### 4.2 五级 observation capability

| Tier | 方法可见信息 | 典型方法 | 排名范围 |
| --- | --- | --- | --- |
| `T0_state_prior` | 本机状态，时间/能量，合法 coarse prior | sweep，known-map planner | 只与同 tier 比较 |
| `T1_occupancy_voxel` | T0 + 局部/共享 occupancy 或 voxel 更新 | frontier，auction，部分 MARL | geometry-search 主榜候选 |
| `T2_range_fov` | T0 + 受限 FoV range/ray/point observation | constrained-FoV planner，LiDAR-style 方法 | geometry-search 主榜候选 |
| `T3_rgbd` | T0 + 标定 RGB-D 和允许的局部地图 | visual/ego-depth policy | 单独 RGB-D 榜或等信息 geometry 榜 |
| `T4_full_perception` | T3 + 方法自有 detector/semantic output | end-to-end target search | perception-search 榜 |

信息层级高区别于自动更强。不同 tier 不混榜。一个方法可提交多个 profile，但每个 profile 的 checkpoint，训练预算和 transcript 分开。

### 4.3 geometry-search 确认合同

候选 detection event 至少包含。

- `agent_id`。
- `event_time`。
- `source_observation_id`。
- 方法给出的 target candidate/instance handle。
- 可选置信度。

scorer-private witness 同时验证。

1. 距离不超过冻结上限。
2. 目标位于该 source observation 的 FoV。
3. 从真实传感器位姿到目标 witness 的 ray 没有 collider 遮挡。
4. 目标支持面的法向/开口方向满足 front-facing 条件。
5. 同一 agent 连续满足最小 dwell 或合法 observation action。
6. event 未过期，未跨 agent，未重复。
7. 方法从未读取私有目标坐标或 fault truth。

pilot 可用 3 m 作为 STAR-Searcher 对照值，但必须在 2/3/5 m 和 FoV/dwell 敏感性实验后冻结。确认范围只依据预注册敏感性实验冻结。

### 4.4 perception-search

perception-search 使用可见 marker/parcel/opening cue 的 RGB 或 RGB-D detector。它必须单独报告 frame/event precision，recall，PR-AUC，calibration，latency，distance/angle/occlusion 分层和最终任务 confirmed-recall AUC。geometry oracle 结果与 detector 输出分列。detector 失败在 scorer 中保持为失败。

## 5. 更广泛基线兼容设计

### 5.1 三个任务视图，共用同一城市

1. `exploration-3d / G1-U` target-free，方法只见粗略先验与局部occupancy，评价可飞体积/地图覆盖，时间，能量和安全。FUEL，RACER，FALCON，frontier 类方法只依赖公共观测即可运行。
2. `geometry-search-3d / G2-I`，候选 Paper I 主任务。方法在G1-U外还可见目标无关公共检查图，使用scorer几何确认，比较系统检查规划与协同。当前仍在实现中，保持 `NO-GO`。
3. `perception-search-3d` optional，评价端到端目标感知与搜索，与 geometry 主榜分列。

这些是 task view，复用现有 layout split。它们复用同一 CitySpec，避免组合爆炸。

当前 G1-U 与 geometry-search 主榜分列，公开方法只有coarse prior和局部occupancy，目标，support和合法观察位姿完全私有。原完整表面扫掠在300 s预算下约需每机1,100--1,500 s。缩减 `sweep-3d` 的零确认属于 coverage diagnostic 的覆盖范围，目标搜索基线失败另行判定。

`G2-I` 的公共检查图必须只包含目标无关信息。

- 屋顶，立面，入口，瓦砾邻域等可检查区域的公开ID，类别，粗略范围，面积与高度带。
- 由冻结的传感器/安全语义导出的公开检查单元或姿态包络。
- 与目标无关的安全转场图或代价界，以及公开的已检查历史。

它只包含目标无关的公开结构，目标坐标，数目，ID，过程，support site，私有witness/ray，检查单元是否有目标，split，seed 和派生统计量保持隔离。atlas 在目标过程前冻结。配对 target-process episodes 必须复用同一 atlas，且通过字段审计，private-key拦截，对抗性分类和反事实换标测试。

G1-U与G2-I按榜单隔离。G1-U报告free-space/occupancy coverage。G2-I同时报告inspection-footprint coverage，即公开检查单元中被真实满足冻结range/FoV/LOS/dwell条件覆盖的比例。Paper I的可证伪问题应改为 free-space coverage是否足以预测confirmed recall，还是inspection-footprint coverage才提供稳定预测增量。

### 5.2 adapter ABI

- `PlannerAdapter`，当前输入版本化G1-U geometry/state/message snapshot。G2-I实现后再加入审计过的atlas projection，输出带时限的 waypoint-heading/hold/message 高层动作。
- `ParallelMultiAgentEnv` PettingZoo ParallelEnv 风格的 dict observation/action，支持 CTDE 的 public training state 与 decentralized execution projection。
- `GymnasiumFleetWrapper`，把联合机群作为一个 policy action 的集中式兼容层，仅进入 centralized profile。
- `ROSBridge`，为 FUEL/RACER/FALCON 类 ROS 方法提供点云/地图，里程计，目标动作与时间同步。其可见信息保持一致。
- `ReplayAdapter`，从统一 transcript 离线重放 observation/action/message/event，但离线可读区别于闭环 baseline 成立。

所有 adapter 统一写出 observation profile hash，action timing model，source observation IDs，message budget，planner deadline，controller receipt，collision/energy，容器/commit/checkpoint 和失败原因。

### 5.3 baseline registry，受控列表

候选目录分四层。

- 低界/诊断 random-safe，single-agent reference，private oracle，centralized assignment，fault-aware oracle。
- G1-U探索 2D sweep，只进2.5D/projection诊断，3D volumetric sweep，nearest frontier，FALCON/FUEL/RACER类探索器。
- G2-I搜索 surface-inspector，atlas-aware information gain，market/auction，Voronoi/inspection partition以及兼容公共检查图的target-search planner。
- 强三维系统 FUEL，RACER，FALCON/EPEE 风格，STAR-Searcher/target-search planner。
- 学习 IPPO，MAPPO，RMAPPO，MARVEL-style graph policy，Visual Drone Swarm，MRIPP-style target mapping，以及通过 ABI 的其他方法。

正式 Paper I 对每个方法跑每个 track 采取可选策略。普通版主表以3--5个有效G2-I闭环方法为上限，顶刊版至多8个。每个主榜至少包含一个非学习方法，一个学习方法和一个诊断上界。fleet-scaling/resilience跑代表性子矩阵。只有产生原生trace，权限证明和完整失败分母的方法才计为baseline。当前外部方法的 G2-I 闭环资格仍在评审中。

## 6. 旧方法的新颖性裁决

### 6.1 已被强烈覆盖的部分

| 旧主张/组件 | 高风险近邻 | 裁决 |
| --- | --- | --- |
| value critic + successor-feature critic + QD | QDAC | 新颖性归属已有工作 |
| descriptor-conditioned RL + QD | DCRL/DCG-MAP-Elites | 新颖性归属已有工作 |
| multi-agent team policy + QD archive + BD-conditioned critic | MIQD, AAMAS 2026 | 直接高风险 |
| 随机 fitness/descriptor 与档案纠正 | Uncertain-QD，Extract-QD | 统计校正属于已有工具 |
| physical damage 后从 repertoire 快速适应 | Robots that Adapt Like Animals，Hierarchical QD damage recovery | 故障+QD不足 |
| robot failure 下未知环境覆盖 | CARE | 韧性任务属于已有设定 |
| team member 加入/离开与可变组成 | COPA，open ad-hoc teamwork | 动态机群不足 |

### 6.2 三个旧理论候选的局限

- paired estimator 的方差下降是标准配对实验结论。可作为统计设计，不足以命名算法。
- descriptor confidence 不跨 cell 的 margin 条件是有用的 archive admission rule，但与 UQD/稳健分类思想接近，单独贡献偏薄。
- frozen finite candidates 的 simultaneous confidence bound 是标准多重推断/稳健选择工具。可用于保证声明，模块组合保持工具定位。

这些结果保留为附属定理或 scorer 统计保证，Paper II 三根主柱以核心机制为准。

### 6.3 更适配 AeroCityBench 的优先假设

暂定研究问题，而非既定方法。

> 在 active agent set 和通信图随时间变化，且故障身份只能从延迟 health evidence 推断时，能否用一个 permutation/set-equivariant 的团队责任组合算子，把已有三维搜索责任 repertoire 快速重组给存活成员，并对覆盖损失与切换代价给出可检验界。

暂定方法代号 `Survivor-Conditioned Responsibility Repertoire (SCRR)`，仅为讨论标签。

单一理论核心候选是 **agent-deletion stability of composable responsibility repertoires**。QD 只负责构建覆盖不同责任模式的 repertoire。RL，ActionToken，安全 critic 和 receipts 是训练/执行设施，不各自宣称创新。

最低形式化要求。

- active agent set 为潜变量，scorer `failed_agent_ids` 保持私有。
- 行为对象以三维 opportunity/region responsibility 为准。
- 明确定义删除，投影，repair，责任冲突，未覆盖区与切换成本。
- 在单调次模或其他明确假设下给出 survivor reallocation regret/approximation 目标。
- 明确 CARE，COPA，ad-hoc teamwork，fault-tolerant MRTA，MIQD 和层级 QD 不满足的哪一条联合条件。
- 若普通 graph MAPPO + agent dropout + greedy reassignment 已解释收益，则 SCRR 停止。

这只是最值得优先审查的方向，新颖性判定以后续审查结论为准。
