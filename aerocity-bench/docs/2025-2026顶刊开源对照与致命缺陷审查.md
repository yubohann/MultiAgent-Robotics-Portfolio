# 2025-2026 顶刊开源对照与致命缺陷审查

日期 2026-07-31
状态，设计审查，正式实验和法律意见另行执行。

## 结论

AeroCityBench 的潜在论文价值定位为受控测量结构。可成立的主张是，在统一物理，观察动作，信息权限和 scorer-private 确认条件下，受控三维目标过程会使 coverage 指标与多无人机搜索成绩之间出现稳定可测的偏离，并暴露确定性的失败机制。

目前正式实验保持 `NO-GO`，四类主要缺口如下。

1. CF2X 的 native 代码合同已具备。本地 CUDA/PhysX 已验证哈希锁定资产，逐旋翼执行器状态，实测质量，无接触悬停，横移，爬升，偏航，受控制动和地面接触，并在 calibration/train/validation 三座开发城市完成单机私有确认和返航闭环。城市障碍/窄通道碰撞和完整四机 episode 证据属于后续补齐项。
2. L0 与 L1 的排名偏差待测量，L0 只作开发期信号，正式分数以 L1 为准。
3. 外部公开方法的 L1 闭环待在同一权限，同一 controller，同一预算下完成。
4. target-process/topology 的 shortcut red-team，独立外部有效性和正式统计功效冻结进行中。

## 已调整的设计

### CF2X 与四旋翼证据

- 旧 `5_in_drone` 目录只作历史溯源，正式，预飞行和 L1 切片使用锁定资产。
- 唯一候选后端为本地 hash-locked CF2X，缺失，改动，schema 待闭合或受限路径立即失败。
- 方法的高层 action 经共享 controller 生成四个旋翼推力 [N]。`ThrusterCfg` 推进四个执行器状态，`Multirotor` 将其按 CF2X 几何 allocation matrix 映射为根刚体 PhysX wrench，执行路径以根刚体 wrench 为准。
- 记录 requested/applied rotor thrust，ContactSensor 和实际机体状态。
- root pose/velocity，关节转速推进和 raw body wrench 只作调试入口，逐旋翼执行是唯一正式路径。
- CF2X 仍是 `local_runtime_only_license_clearance_pending`，随代码，wheel，场景或容器发布需要许可证闭合。

### 相机与吞吐

- L1/G1 geometry 主榜以纯几何输入为准。相机 rig 的外参，FoV，时间戳仍用于 LOS/观察语义。
- L2/P1 的 RGB-D/分割只在合法 OBSERVE/dwell 中事件触发，候选 2 Hz，范围 2--5 Hz。
- `96x69` 与 `160x120` 是不同执行 profile，按 profile 分开统计和排名。
- 正式 calibration 必须测 PhysX-only，ContactSensor，depth，RGB-D，RGB-D+instance 五档 RTF，显存，掉帧与 deadline miss。

## 待解决的致命问题

| 风险 | 为什么致命 | 关闭条件 |
| --- | --- | --- |
| native 执行证据待补齐 | 四旋翼表述需要执行证据支撑 | 三城单机 CF2X preflight，接触和私有闭环回执已经具备。城市/窄通道，四机正式闭环和 replay evidence 属于后续补齐项 |
| L0/L1 排名一致性待验证 | 快速层筛选方法需要预注册的相关性支撑 | calibration 中预注册的相关性，淘汰误差，安全漏报和失败谱 |
| 外部方法权限存在差异 | adapter 可造成虚假优势或劣势 | capability profile，adapter tax，失败分母，独立重跑。当前已有 public-only G1 JSONL process bridge，真实上游闭环属于后续补齐项 |
| 目标/障碍生成规律泄漏 | 方法可能利用资产或几何模式 | target--distractor matching，反事实换标，元数据/图像 split probes |
| simulator 内 OOD 与真实泛化需要分开表述 | 表述需要预注册路线支撑 | 顶刊路线的预注册 X-SIM，X-HIL 或 X-REAL 子集 |
| 计分器更新影响成绩可比性 | 发布后纠错成本高 | scorer version，major leaderboard，撤回与重算政策 |
| CF2X 许可待闭合 | 公开发布需要许可证闭合 | 原始来源，授权/许可证，分发权的书面证据。当前保持 local-only |

## 立即执行顺序

1. 三城单机 CF2X private slice 已通过。失败只保留小型 receipt/log，大体积无效录制在采集后清理。
2. 接入四机完整 L1 executor，绑定 action，OBSERVE，private confirmation，return，failure 和 score。
3. 在城市障碍，窄通道和机间冲突中冻结接触，最小净空和越界语义。
4. 接入 sweep，frontier，information-gain，oracle 与至少一个外部方法，比较 L0/L1。
5. 在与 formal test 隔离的前提下完成生成器 shortcut red-team，吞吐和范围/速度 pilot。
6. 只有发现稳定，可重复且会影响方法选择的 coverage-to-search 结论后，才冻结正式实验矩阵。
7. 顶刊路线额外完成外部有效性，第二机器/操作者和盲测治理。

本轮代码关闭四个工程漏洞 `vertical_slice_contract.py` 使单机私有切片的 receipt，confirmation，failure 和 return closure 可被离线 fail-closed 复核。`ExternalProcessPlannerBridge` 则把外部集中式 G1 方法从只声明 process scope升级为 bounded JSONL 子进程协议，并拦截 scorer-private wire fields，错误 request ID，action roster 漂移，超长/超时响应和 container/ROS 伪装。2026-07-31 的回归又确认两个 false audit sentinel 即使意外嵌套也会在 wire 的所有层级移除，非 ASCII JSON key 直接拦截。配对 target-process 的安全天空走廊证明现在以 layout/支持点/起飞/执行合同为键做有界，深拷贝的进程内缓存，并将不变量碰撞检查去重。该优化只影响开发流程，release，witness 和分数保持不变，且有 mutation-isolation 回归。新 guidance 将 position target 锚定于测得状态，分离水平/垂直速度，并在三段天空路线冻结 yaw，消除了先前单机返航下降中观测到的范围退出。calibration/train/validation 三座开发城市随后都完成私有确认和返航闭环。fresh public/private `.json` 回执路径现在也在 Isaac 启动前 fail closed，保留失败证据。上述改动属于工程流程改进，以下顶刊阻断项保持开放 CF2X 城市/窄通道和四机原生闭环，L0/L1 排名偏差，真实上游方法闭环，10--20 布局审计，目标过程 red-team，预注册功效分析，外部有效性，blind scorer 和 CF2X 再分发许可。
