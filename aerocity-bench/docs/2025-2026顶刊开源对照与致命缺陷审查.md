# 2025-2026 顶刊开源对照与致命缺陷审查

日期：2026-07-31
状态：设计审查，不能替代正式实验或法律意见。

## 结论

AeroCityBench 的潜在论文价值不是“又一个 Isaac 城市”或“又加入一个无人机模型”。可成立的主张是：在统一物理、观察动作、信息权限和 evaluator-private 确认条件下，受控三维目标过程会使 coverage 指标不能稳定预测多无人机搜索成绩，并暴露可复现的失败机制。

目前仍是正式实验 `NO-GO`。最致命的四类缺口是：

1. CF2X 的 native 代码合同已具备；本地 CUDA/PhysX 已验证哈希锁定资产、逐旋翼执行器状态、实测质量、无接触悬停、横移、爬升、偏航、受控制动和地面接触，并在 calibration/train/validation 三座开发城市完成单机私有确认和返航闭环；但仍没有城市障碍/窄通道碰撞和完整四机 episode 证据；
2. 尚未测量 L0 与 L1 的排名偏差，L0 不能替代正式分数；
3. 外部公开方法尚未在相同权限、相同 controller、相同预算下完成 L1 闭环；
4. target-process/topology 的 shortcut red-team、独立外部有效性和正式统计功效尚未冻结。

## 已调整的设计

### CF2X 与四旋翼证据

- 禁止旧 `5_in_drone` 目录成为正式、预飞行或 L1 切片的可执行来源；
- 唯一候选后端为本地 hash-locked CF2X，缺失、改动、schema 不闭合或禁止路径立即失败；
- 方法的高层 action 经共享 controller 生成四个旋翼推力 [N]；`ThrusterCfg` 推进四个执行器状态，`Multirotor` 将其按 CF2X 几何 allocation matrix 映射为根刚体 PhysX wrench，而非向 prop-link 分别施力；
- 记录 requested/applied rotor thrust、ContactSensor 和实际机体状态；
- 不允许直接写 root pose/velocity、关节转速推进或 raw body wrench 替代逐旋翼执行；
- CF2X 仍是 `local_runtime_only_license_clearance_pending`，不得随代码、wheel、场景或容器发布。

### 相机与吞吐

- L1/G1 geometry 主榜不向方法提供 RGB；相机 rig 的外参、FoV、时间戳仍用于 LOS/观察语义；
- L2/P1 的 RGB-D/分割只在合法 OBSERVE/dwell 中事件触发，候选 2 Hz，范围 2--5 Hz；
- `96x69` 与 `160x120` 是不同执行 profile，不能混合统计或复用排名；
- 正式 calibration 必须测 PhysX-only、ContactSensor、depth、RGB-D、RGB-D+instance 五档 RTF、显存、掉帧与 deadline miss。

## 尚未解决的致命问题

| 风险 | 为什么致命 | 关闭条件 |
| --- | --- | --- |
| native 只有代码没有证据 | 评审会把四旋翼表述视为未证实 | 三城单机 CF2X preflight、接触和私有闭环回执已经具备；仍需城市/窄通道、四机正式闭环和 replay evidence |
| L0/L1 可能排名不同 | 用快速层筛选方法会制造错误科学结论 | calibration 中预注册的相关性、淘汰误差、安全漏报和失败谱 |
| 外部方法权限不等价 | adapter 可造成虚假优势或劣势 | capability profile、adapter tax、失败分母、独立复现；当前仅有 public-only G1 JSONL process bridge，尚无真实上游闭环 |
| 目标/障碍生成规律泄漏 | 方法可能沿资产或几何模式投机 | target--distractor matching、反事实换标、元数据/图像 split probes |
| simulator 内 OOD 被误称真实泛化 | 会导致过度主张 | 顶刊路线的预注册 X-SIM、X-HIL 或 X-REAL 子集 |
| 评测器更新使成绩不可比较 | 发布后难以纠错 | evaluator version、major leaderboard、撤回与重算政策 |
| CF2X 许可未闭合 | 公开发布可能必须下架 | 原始来源、授权/许可证、分发权的书面证据；否则永久 local-only |

## 立即执行顺序

1. 三城单机 CF2X private slice 已通过；失败只保留小型 receipt/log，不把大体积无效录制留在工作盘；
2. 接入四机完整 L1 executor，绑定 action、OBSERVE、private confirmation、return、failure 和 score；
3. 在城市障碍、窄通道和机间冲突中冻结接触、最小净空和越界语义；
4. 接入 sweep、frontier、information-gain、oracle 与至少一个外部方法，比较 L0/L1；
5. 在不读取 formal test 的前提下完成生成器 shortcut red-team、吞吐和范围/速度 pilot；
6. 只有发现稳定、可重复且会影响方法选择的 coverage-to-search 结论后，才冻结正式实验矩阵；
7. 顶刊路线额外完成外部有效性、第二机器/操作者和盲测治理。

本轮代码关闭四个工程漏洞：`vertical_slice_contract.py` 使单机私有切片的 receipt、confirmation、failure 和 return closure 可被离线 fail-closed 复核；`ExternalProcessPlannerBridge` 则把外部集中式 G1 方法从“只声明 process boundary”升级为 bounded JSONL 子进程协议，并拒绝 evaluator-private wire fields、错误 request ID、action roster 漂移、超长/超时响应和 container/ROS 伪装。2026-07-31 的回归又确认两个 false audit sentinel 即使意外嵌套也会在 wire 的所有层级移除，非 ASCII JSON key 直接拒绝。配对 target-process 的安全天空走廊证明现在以 layout/支持点/起飞/执行合同为键做有界、深拷贝的进程内缓存，并将不变量碰撞检查去重；该优化不写入 release、不改变 witness 或分数，且有 mutation-isolation 回归。新 guidance 将 position target 锚定于测得状态，分离水平/垂直速度，并在三段天空路线冻结 yaw，消除了先前单机返航下降中观测到的边界退出；calibration/train/validation 三座开发城市随后都完成私有确认和返航闭环。fresh public/private `.json` 回执路径现在也在 Isaac 启动前 fail closed，避免覆盖失败证据。上述改动都没有产生 benchmark 分数，也没有减少以下顶刊阻断项：CF2X 城市/窄通道和四机原生闭环、L0/L1 排名偏差、真实上游方法闭环、10--20 布局审计、目标过程 red-team、预注册功效分析、外部有效性、blind evaluator 和 CF2X 再分发许可。
