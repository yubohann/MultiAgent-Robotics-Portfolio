# AeroCityBench 权威计划深度审计报告

- 审计日期：2026-07-29
- 审计对象：docs/权威科研执行计划.md，提交 0347e6d
- 审计类型：代码事实、历史失败、本地论文全文、官方仓库、在线元数据和许可证交叉审计
- 审计结论：旧版计划失活；不得按旧版 P0-P4 和 1,572 布局承诺直接推进
- 新权威计划：docs/权威科研执行计划.md 的 AUDITED_ACTIVE 版本

## 1. 结论先行

旧计划的总体方向成立：开放程序化主场景、CitySpec 统一物理真值、三维目标、公开/私有隔离、Isaac 原生执行、receipt 和布局级统计都应保留。问题在于，它把“正确方向”误写成了“已经足够具体且可执行的合同”。

审计发现八个会使正式论文结论失效的首要问题：

1. 方法进程可从公开 CitySpec 的 split/family 和 coarse_prior 的 corruption_regime 直接识别测试机制；现有 privacy passed 无法发现这种 benchmark shortcut。
2. test_damage 同时改变物理损毁、烟雾、通信延迟和丢包率，无法归因“损毁 OOD”究竟由哪个因素造成。
3. 所谓多个语法族仍主要是轴对齐横纵道路的弱变体，topology_signature 也不是图同构或近重复检验；换 seed 不能证明拓扑泛化。
4. facade support 从建筑外接矩形生成，不从真实 L/U/庭院表面生成；目标可能悬空、埋入或位于不存在的墙上。
5. 三个 UAV 起点固定在地图中心附近，未进行机体包络碰撞、可达、通信初始连通、能量或返航证明。
6. support-to-target 比例只是候选点数比，不代表目标有可用观测姿态、足够视角、合理确认难度或可承受能耗。
7. native_isaac_gate 始终为 not_run；当前截图工具不执行合法路线、故意碰撞、通信、检测确认和 Action/Evaluator receipt 闭环。
8. 现有方法主张与 Uncertain-QD、Extract-QD、DCRL-MAP-Elites、QDAC 的既有贡献重叠；单个 Hoeffding LCB 不能解决 descriptor 漂移、幸运 elite、archive correction 和自适应选择。

因此，下一步不是 r4、v0.1 或训练，而是重建科研合同：先冻结任务与 evaluator ABI，再修几何和切分，再做难度与资源 pilot，最后依据功效分析决定正式规模。

## 3. 逐条审计矩阵

### A01：公开测试机制泄漏

- 旧计划承诺：方法不能读取 test 身份、raw layout ID 或 scene shortcut。
- 代码事实：schemas/cityspec_v1.schema.json 要求 split 和 family；generator.py 将它们写入公开 CitySpec；compiler.py 把 prior_ood/standard 写入公开 coarse_prior。
- 反例：无需飞行或看图，只读 JSON 即可选择 test 专用策略。
- 风险：致命。任何 OOD 增益都可能是条件分支而非泛化。
- 修订：split、生成祖先、holdout 标签和 corruption regime 只进入 evaluator-private manifest。方法进程只看到中性 scene handle、传感器流、声明允许的 coarse prior 与可观测 context。
- 验收：静态字段扫描、动态系统调用审计、split/scene identity probe 均不能高于预注册的机会水平容差。

### A02：privacy gate 定义过窄

- 代码事实：audit.py 的 FORBIDDEN_PUBLIC_KEYS 只禁止 targets、target_count、seed、witness 等目标字段。
- 缺失：没有禁止 split、family、corruption_regime、祖先模板、测试资产集合和可逆 scene identity。
- 风险：致命。validation_report 的 privacy_gate = passed 是错误的充分性暗示。
- 修订：改为 capability-based information-flow test；分别审计目标真值泄漏、测试身份泄漏和 oracle geometry 泄漏。
- 验收：公开工件白名单 schema 加容器内文件访问审计，不再只做关键词黑名单。

### A03：OOD 因子混杂

- 代码事实：test_damage 增加 rubble 数，同时 targets.py 增大 smoke、latency 和 drop probability。
- 风险：高。无法进行单因子因果归因，消融表不可解释。
- 修订：区分 LayoutSpec 的几何损毁与 EpisodeCondition 的感知、通信、动力学和资源条件；建立单因子配对 OOD 与额外 compound stress track。
- 验收：每个单因子 track 只有一个生成机制家族发生变化；其余 CitySpec、目标、起点和随机数使用成对承诺。

### A04：城市语法多样性被高估

- 代码事实：generator.py 的 family 主要改变横纵切割数量、模板选择和少量规则，母道路结构仍是轴对齐 cross/grid。
- 文献对照：ProcTHOR 表明程序化规模有价值，但规模不自动消除生成器归纳偏置；QD-MAPPER 用主动生成暴露算法弱点，而非只换随机 seed。
- 风险：高。模型可能记住母语法，topology OOD 只是表观模板 OOD。
- 修订：以道路图祖先、交叉口 motif、环/死胡同结构、街区分割和三维峡谷结构定义语法；至少包含非同构母图，而不是字符串 family。
- 验收：图核/同构 canonical form、连续几何嵌入近邻和可飞体素近邻三层去重。

### A05：topology_signature 不是拓扑证明

- 代码事实：topology_signature 是粗 payload 的内容哈希；哈希不同只证明序列不同，不能证明图结构或几何行为不同。
- 风险：高。轻微坐标变化即可伪造“新拓扑”。
- 修订：保存 canonical road/block graph、motif 向量、谱特征、三维自由空间摘要和最近邻证据；hash 只负责内容完整性。
- 验收：跨 split 无祖先组重叠，且所有近重复候选按冻结阈值拒收。

### A06：三维 facade 目标几何错误

- 代码事实：targets.py 按建筑 footprint 的外接矩形四边采样 facade；这对 L/U/庭院/退台结构不成立。
- 风险：致命。目标可能不在真实表面，N1/N2 和截图也可能被错误 overlay 掩盖。
- 修订：SceneCompiler 在生成建筑时同时输出有向边界面、屋顶多边形、入口面和 rubble 可承载面；support site 必须从真实面采样。
- 验收：每个目标带 surface_id、三角形/面内重心坐标、法向、偏移和双向 ray witness；Isaac raycast 与 CPU 几何在容差内一致。

### A07：起点不满足任务可行性

- 代码事实：三个起点固定在中心半径 0.08 × size 的圆上，z = 2.5 m。
- 缺失：机体包络、起飞净空、连通分量、初始通信、目标机会、能量和返航。
- 风险：高。episode 难度可能由非法起点主导。
- 修订：从经验证 takeoff volume 采样，执行全机体 sweep、可飞连通、最短能耗和 return-to-home witness。
- 验收：每个起点均有可复查路径与能耗上界；失败起点不进入 admitted episode。

### A08：support capacity 不能代表搜索机会

- 旧计划承诺：合法 support site 至少为目标数 6 倍。
- 代码事实：只比较点数；没有传感器视锥、遮挡、可达视点、确认帧数或能耗。
- 风险：高。可出现“点很多但几乎看不到”，或一帧看完大量目标。
- 修订：目标数由 opportunity budget 校准，而非面积或 support 点数。为每个候选目标计算可达观测姿态数、可见立体角、最小确认成本、共视目标数和 distractor 匹配。
- 验收：强 target-free baseline 的 recall、无机会目标率、每次 observation 的目标共视数和失败分类落入预注册难度带。

### A09：目标视觉/检测合同缺失

- 缺失：目标外观、尺寸、朝向、检测噪声、误报、确认帧、重复上报和时间同步尚未冻结。
- 风险：致命。结果可能测的是 detector 或 overlay，而非多 UAV 搜索。
- 修订：v1 设两条明确轨道：几何确认的 planning track 使用统一 evaluator detection contract；sensor track 使用固定公开 detector/noise model，另行报告。
- 验收：N0-N5 对 opportunity、attempt、observation、candidate、confirmation 和 failure 的语义由正反例测试固定。

### A10：多 UAV Dec-POMDP/ABI 不完整

- 缺失：每个 agent 可见什么、谁共享地图、训练时是否 CTDE、消息内容和字节预算、通信图、联合动作、UAV-UAV 碰撞、故障后任务重分配和 credit assignment。
- 文献对照：MAPPO 是强 CTDE 基线；RACER/FALCON 是强规划参考；MARVEL 的 perfect communication 和二维 occupancy 假设不能直接移植。
- 风险：致命。benchmark 名称声称 multi-UAV，但方法和基线可在不同信息条件下运行。
- 修订：G1 先冻结 observation/action/message/timing/reset/evaluator ABI；评估必须 decentralized execution。
- 验收：相同 observation transcript 对所有方法一致；禁止未声明共享内存或 oracle global map。

### A11：截图不能关闭 native gate

- 代码事实：tools/isaac_capture.py 加载 stage 并拍 RGB/depth/overlay；audit.py 始终写 native_isaac_gate = not_run。
- 历史反例：pine_tree_01 的非空图仍是巨大高饱和红树，机器检查误报成功。
- 风险：高。
- 修订：静态 scene health 与任务执行 gate 分离。必须运行合法路径、故意碰撞、guard 拒绝、通信事件、目标确认和 reset residue 检查。
- 验收：ActionReceipt、EvaluatorReceipt、contact、sensor、route、reset-state 和 FailureLedger 哈希闭环。

### A12：schema 只约束外壳

- 代码事实：CitySpec 的 roads/blocks/buildings 等数组无 items 约束，flight_bounds/metrics 是任意 object；EpisodeSpec 的 starts/smoke/communication 也无内部 schema。
- 风险：高。无效 JSON 可通过 schema，版本兼容不可控。
- 修订：为坐标、单位、范围、唯一 ID、surface、start、sensor、condition 和 receipt 建立严格 schema 与语义校验。
- 验收：mutation/property-based tests 能拒绝缺字段、NaN、越界、重复 ID、单位错配和非法引用。

### A13：资产准入仍含已知失败项

- 代码事实：smoke.json 和 v0.1.json 仍含 pine_tree_01；其 AABB 约 21.83 × 8.55 × 20.39 m，且出现材质异常与街景遮挡。
- 风险：高。已知失败可能重复进入下一版。
- 修订：默认 fail closed；只有 accepted AssetProfile 可被 release config 引用，配置不能绕过 profile 状态。
- 验收：构建前 schema/registry join 直接拒绝 pending/rejected 资产。

### A14：代码许可证不等于数据许可证

- 证据：Habitat-Lab 为 MIT，但官方 README 明确说 task datasets 和 trained models 受对应 scene dataset 条款约束；iGibson 部分数据需单独申请；Isaac Sim/Nucleus 资产不因 Isaac Lab BSD-3-Clause 自动可再分发。
- 额外发现：FlightBench 为 GPL-3.0；QDax、DCRL-MAP-Elites、pyribs 为 MIT；本地 Uncertain_Quality_Diversity 仓库没有根许可证文件；BEHAVIOR-1K GitHub API 未返回许可证。
- 风险：高。用户口头/私下沟通允许复用，不等于公共仓库可忽略许可证和署名。
- 修订：每个外部组件必须有 SPDX、commit、用途、链接方式、修改说明和书面授权文件。GPL 代码只能在兼容许可边界内使用或隔离为可选外部适配器。
- 验收：clean-room asset/code SBOM 和 legal manifest 完整；官方 Isaac 资产不进入公开资产链。

### A15：一行命令尚未达到干净环境复现

- 旧计划承诺：一行 build。
- 事实：命令依赖预置 PYTHONPATH、本地 asset root、Isaac Sim 5.1 和未闭合的 Kenney 转换；当前 CLI override 也未实现。
- 风险：中高。一行命令可能只是本机捷径。
- 修订：提供锁定环境、资产 fetch/verify/convert、build、validate 四个可组合子命令，并以单一 wrapper 执行；离线镜像和在线官方源都产生相同 asset lock。
- 验收：全新机器/容器从许可允许的源重建 pilot，逐文件 hash 或规范化语义 hash 一致。

### A16：1,572 布局没有科学依据

- 旧计划承诺：960/180/6×72 布局及固定 episode 数。
- 缺失：没有覆盖饱和曲线、布局内相关 ICC、方差、最小可检测效应、吞吐、磁盘和 GPU 预算。
- 风险：高。可能浪费算力，也可能对最差组严重欠功效。
- 修订：正式规模由 G3-G4 pilot 后的覆盖停止规则和 G7/G9 功效分析决定；1,572 降级为旧版占位符。
- 验收：冻结的 sample-size report 明确独立单位、目标功效、MDE、方差、ICC、丢失/拒收率和资源上限。

### A17：统计独立单位仍需细化

- 旧计划优点：已认识到 episode 不是独立布局。
- 缺失：生成祖先、布局、episode、训练 seed 和 method seed 的嵌套关系；多 OOD 组和多指标校正。
- 风险：高。把相关 rollout 当独立样本会缩窄置信区间。
- 修订：主要比较使用配对布局/祖先组，分层 bootstrap 或预注册 mixed-effects；报告 IQM、性能曲线、worst-group、效应量和区间，次要指标用 Holm 校正。
- 验收：统计脚本在冻结 synthetic fixtures 上覆盖已知效应与零效应，且不能把 episode 数误当布局数。

### A18：现有 QD 理论不足

- 旧计划主张：对每个 cell 用 Hoeffding LCB 排名。
- 文献反例：Uncertain-QD 明确指出单次评价会保留幸运 elite，fitness 和 descriptor 都是分布；Extract-QD 进一步把 extraction/correction 模块化。
- 风险：致命于方法主张。固定 cell 的质量 LCB 不能纠正 descriptor 跨 cell 漂移，也不能处理 archive 训练后的自适应候选选择。
- 修订：独立 correction set 上重评冻结候选，输出 corrected repertoire、descriptor stability 和 reproducibility；不稳定 cell 暂不分配或进入显式不确定单元。
- 验收：与 UQD/Extract-QD matched sampling budget 基线比较，报告 raw archive 与 corrected archive 差异。

### A19：方法创新与既有工作重叠

- 证据：DCRL-MAP-Elites 已有 descriptor-conditioned actor/critic、actor injection 和 reproducibility analysis；QDAC 已用 value critic + successor features critic。
- 风险：高。No-SF 或 topology context 的有效性不等于 SF/context 本身新颖。
- 修订：候选方法改为 Counterfactual Contextual Uncertain-QD；创新只候选性地放在成对反事实分解、层级可观测 context、receipt-derived descriptor correction 和 worst-context selection 的联合机制。
- 验收：完成系统新颖性检索；no-correction、no-counterfactual、no-context、shuffled-context、raw-ID probe、standard UQD 和 matched-budget MARL 均是必做反证。

### A20：理论边界过宽

- 风险：高。不能从有限样本 LCB 推导 RL 收敛或“理论上一定提高搜索”。
- 修订：理论只针对冻结有限候选集、预注册 context 组、独立布局 correction set 和有界指标，给出同时置信、corrected elite 选择或稳定 cell assignment 条件；训练过程只做经验研究。
- 验收：定理假设逐项映射到 evaluator 证据；相关布局、异方差或自适应复用任一不满足时不得使用该定理。

### A21：benchmark 与方法共同设计偏差

- 风险：高。如果目标数、context cell 或 OOD 阈值在看过方法结果后调整，test 就变成训练信号。
- 修订：benchmark track 与 method track 分开登记；benchmark 先冻结并 hash 承诺，方法轨可失败而不修改正式 test。
- 验收：append-only 决策日志、冻结 commit、test Merkle root 和外部 evaluator。

### A22：外部验证角色不清

- 风险：中。FALCON、SubT、RiverMark 或 CityLite 与主任务几何、许可、传感器和评价不一致。
- 修订：它们只作为 external validity track，不进入主 benchmark 规模，也不用于选择超参数。
- 验收：外部轨单独报告适配层、信息条件和不可比较项。

### A23：难度只按密度/尺度不充分

- 文献证据：FlightBench 使用 Traversability Obstruction、View Occlusion 和 Angle Over Length，并验证其与飞行表现相关。
- 风险：高。相同密度可对应完全不同的狭窄、遮挡和转弯难度。
- 修订：把 TO/VO/AOL 作为借鉴而非原样照搬；增加三维可飞体积、目标机会、通信断连和返航能耗。
- 验收：难度量度必须与多个强基线的失败概率/代价相关，且不能由单一视觉 shortcut 预测。

### A24：数据文档与版本治理不足

- 文献证据：Data Cards/Datasheets 强调目的、组成、采集/生成、预处理、用途、限制和维护责任。
- 缺失：dataset card、benchmark card、model card、弃用政策、兼容矩阵和长期归档 DOI。
- 风险：中。
- 修订：G10 要求独立复现、文档卡、SBOM、版本迁移、失败账本和归档。
- 验收：第三方只读文档即可知道可比较范围、禁止用途、隐藏测试政策和版本差异。

## 5. 保留、降级和删除的主张

### 保留

- 开放程序化城市作为主轨，RiverMark/CityLite 退出公开主场景；
- 任务物理由 deterministic CitySpec 统一拥有；
- CC0/CC-BY 视觉层必须经过 AssetProfile 和许可证闭包；
- 三维 roof/facade/entrance/rubble 目标；
- evaluator-private EpisodeSpec、Action/Evaluator receipt、N0-N5；
- 布局级或祖先组级统计、外部盲测、一次性正式 test；
- 100/160/224/288 m 只可作为 pilot 候选尺度。

### 降级为待证假设

- 目标数区间、6:1 support 比、1,572 布局；
- 三个训练 family 和 topology_holdout family 能形成真正 OOD；
- topology-contextual realised QD 优于 no-QD 或标准 UQD；
- successor features 在此任务有独立增益；
- 当前外观资产足以支持 appearance OOD；
- 一行命令已能从干净环境完整重建。

### 删除

- 公开 CitySpec 中的 split/family；
- coarse prior 中的 prior_ood 标签；
- test_damage 同时改变烟雾和通信；
- 从外接矩形生成 facade target；
- 中心固定起点；
- 仅凭截图/非空像素关闭 native gate；
- 以当前 Hoeffding LCB 作为完整 noisy-QD 理论；
- 在功效分析前承诺正式布局总数。

## 6. 审计后的执行优先级

### 立即阻断

- 不生成 smoke r4；
- 不构建 v0.1；
- 不训练 topology-contextual realised QD；
- 不用当前 test split 做任何方法选择；
- 不提交正式论文结果。

### 允许的下一阶段

1. 冻结 benchmark 与 method 的问题陈述和贡献边界；
2. 写 observation/action/message/evaluator ABI；
3. 修订公开/私有 schema 与信息流；
4. 重建 surface-derived support、takeoff/return witness 和单因子 ConditionSpec；
5. 之后才允许小规模 generation/calibration pilot。

## 7. 最终裁决

旧计划不是“稍作润色即可继续”，而是必须由新的阶段门取代。最强的科研路线是让 benchmark 即使方法失败也独立成立，让方法即使在 benchmark 上提升也必须通过 shortcut、UQD、强 MARL、统计功效和外部盲测反证。

正式地图数、目标数和方法结论在当前证据下保持未冻结，是严谨而不是保守。任何绕过 G0-G2 直接生成大规模数据的行为，都会把已知的机制错误固化进更昂贵的产物。
