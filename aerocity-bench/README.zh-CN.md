# AeroCityBench

> 面向城市拓扑、目标过程和机群韧性变化的物理约束多无人机三维目标搜索开放基准。

AeroCityBench 研究一个直接但常被忽略的问题：**多无人机覆盖更多空间，是否就更擅长发现目标？** 在三维城市中，答案未必成立。无人机可能飞过建筑却看不到屋顶，检查了错误立面，被建筑遮挡，或因运动过快而无法形成有效观测。AeroCityBench 将这些差异转化为可检验的任务和指标。

基准将程序化三维城市、公开任务合同、评测器私有目标真值和物理约束执行接口结合起来，使规划与学习方法能够在不暴露目标坐标、不允许仅凭接近触发确认的条件下比较。

> **研究原型，不是排行榜。** 当前版本为 `v0.2.0.dev0`。生成器、任务合同、审计工具、适配器和校准基础设施已经实现；正式盲测和可计分的原生多无人机回合尚未完成。使用或引用结果前，请先阅读下方的“当前状态”。

英文说明见 [README.md](README.md)。

## 核心问题

多数探索基准奖励覆盖面积、建图完成度或行驶距离，但这些信号不能证明目标曾从合法视点被观察到。

在 AeroCityBench 中，目标只有在评测器接受一次真实观测时才会确认。该观测必须同时满足距离、视场、视线、表面朝向、持续观察时间、源观测新鲜度、位姿稳定性和安全条件。因此，基准能够检验覆盖表现与目标搜索质量何时一致、何时分离，以及分离的原因。

## 任务与信息边界

```mermaid
flowchart LR
    A[程序化三维城市] --> B[公开任务合同]
    B --> C[四机协同方法]
    C --> D[物理执行与 OBSERVE 动作]
    D --> E[评测器私有确认]
    E --> F[回执与分项指标]
```

| 方法可见 | 评测器私有 |
| --- | --- |
| 自身状态、允许的传感器观测、时间和能量预算 | 目标坐标、数量、标签和生成过程 |
| 公开起点、通信消息和目标无关的粗先验 | 合法观测见证与确认判定 |
| 由几何生成的 G2-I 检查图谱 | 测试划分、城市族和随机种子 |

G2-I 公开检查图谱只说明应检查的结构类型，例如屋顶、立面、入口和瓦砾，不会指出哪些位置含有目标。递归泄漏检查会拒绝公开投影中的目标、见证、评测器、划分和种子字段。

## 任务轨道与评测

- **G2-I 几何搜索** 是主要研究轨道。它通过目标无关检查图谱和评测器约束的观测合同评价目标确认。
- **G1-U 探索** 是历史覆盖诊断任务，仍可显式选择，但不会产生 G2-I 成绩。
- **感知搜索** 保留给单独排名的检测与搜索轨道。RGB-D 可用于建图、避障和视觉策略，但几何排名不要求 RGB 输入。

正式设计在固定执行和信息边界下改变城市拓扑、空间尺度、目标过程、出生条件和机群条件，并分别报告：

- 已确认目标召回率及其随执行时间的变化；
- 碰撞、最小间隙、越界和安全返航；
- 路径长度、能耗、规划延迟和超时；
- 重复检查、工作量均衡、通信状态和机群变化后的任务重分配。

这些维度不会被压缩为不透明的单一总分。

## 仓库内容

- 受约束的程序化城市生成器、版本化发布配置和开放资产许可检查；
- 公开和私有任务投影、JSON Schema、内容哈希和发布验证；
- 不读取目标采样或评测器数据的 G2-I 检查图谱编译器；
- 绑定源观测的 `OBSERVE` 动作与私有确认评测器合同；
- 基线和外部进程适配边界，以及 CPU 与原生运行时预检工具；
- 测试、来源锁定、资产溯源检查和开发审计工具。

仓库不再分发 NVIDIA、Nucleus、Isaac Sim 或评测器私有资产。直接运行 Isaac 工作流需要本地 IsaacLab 与明确配置的资产根目录。

原生和 L0 校准记录仅是工程证据，不是正式基准分数。标记为 `formal_score_eligible=false` 的结果不得解释为方法排名结果。

## 快速开始

需要 Python 3.11 或更高版本。先安装开发依赖并运行聚焦的合同测试：

```powershell
python -m pip install -e ".[dev]"
python -m pytest tests/test_public_boundary.py tests/test_inspection_atlas.py tests/test_ordinary_v3.py -q
```

构建本地开发发布还需要经过验证的开放资产包和可写输出目录：

```powershell
$env:PYTHONPATH = (Resolve-Path .\src)
$assetRoot = (Resolve-Path $env:AEROCITY_ASSET_ROOT)
$outputRoot = Join-Path $env:AEROCITY_OUTPUT_ROOT "ordinary-v1-mini"

python -m aerocity_bench build --release .\configs\releases\ordinary-v1-mini.json `
  --asset-root $assetRoot `
  --output $outputRoot `
  --task-track G2-I `
  --allow-uncommitted-development
python -m aerocity_bench validate $outputRoot
```

使用 `aerocity-bench --help` 查看完整命令。此 Windows 主机上的部分集成路径会启动子 Python 或 Isaac 进程，应作为有边界且受主机保护的独立任务运行，不建议直接执行广泛递归测试。

## 范围

AeroCityBench 是用于受控三维多无人机搜索研究的实验工具。它不声称模拟真实灾后伤员分布，不认证飞控系统，也不能替代实机评测。它提供的是一个可证伪的环境，用于检验方法的覆盖行为能否在遮挡、视点约束、目标过程变化和物理执行要求下仍转化为真实的目标发现能力。
