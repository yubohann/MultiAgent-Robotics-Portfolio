# FAST-LIO2、Point-LIO 与机器人自主系统算法详解

> 本文是 Robocon MID-360 Autonomy Stack 的独立技术说明，不是简历摘要。内容按照“问题建模 -> 核心算法 -> 工程实现 -> 相关方法 -> 项目落地”的顺序组织，便于面试准备、源码阅读和系统设计复盘。

## 0. 文档结论

这个项目中的定位链可以抽象为：

```text
Livox MID-360 CustomMsg + IMU
    -> LiDAR--IMU 局部里程计（FAST-LIO2 / Point-LIO）
    -> 固定地图 scan-to-map（ICP/GICP 等）
    -> map -> odom 全局锚定
    -> pose contract / TF / Nav2 / 目标对准
    -> YOLO + RGB-D + 双车通信 + 投篮状态机
    -> UART/CAN -> STM32 实时执行器
```

必须区分以下三件事：

1. **FAST-LIO2 和 Point-LIO 都是局部 LiDAR--IMU 里程计**，本身不等于全局定位、回环检测或完整导航。
2. 当前 `robocon-mid360-autonomy-stack` 组合仓库的默认 LIO 路线是 FAST-LIO2；历史 ROBOCON 2025 工程中使用过 Point-LIO。
3. Point-LIO 和 FAST-LIO2 的精度、延迟和鲁棒性必须通过同一输入 bag、同一参数协议和同一硬件预算进行 A/B 测试，不能只凭算法名称下结论。

## 1. LiDAR--IMU 里程计的基本问题

### 1.1 为什么单独使用 LiDAR 或 IMU 都不够

LiDAR 的优点是几何约束稳定、长期漂移较小；缺点是帧率有限，且在纯平面、长走廊、稀疏场景和动态遮挡中容易退化。

IMU 的优点是频率高、短时间内对快速运动响应快；缺点是积分漂移，零偏误差会随时间累积。

二者结合后：

```text
IMU：高频预测运动
LiDAR：利用环境几何纠正漂移
```

### 1.2 传感器数据

LiDAR 点通常包含：

```text
(x, y, z, intensity, ring/line, point_time)
```

IMU 通常包含：

```text
angular_velocity = (wx, wy, wz)
linear_acceleration = (ax, ay, az)
timestamp
```

对于 Livox MID-360，不能只使用点云消息的 header 时间。必须保留：

- `timebase`：扫描时间基准；
- `offset_time`：每个点相对于基准的时间偏移。

如果把整帧点云强行设置成同一个时刻，急加速和急转弯时会产生明显的运动畸变。

### 1.3 状态变量

典型 LIO 状态可以写为：

```text
x = (R, p, v, b_g, b_a, g, R_LI, t_LI)
```

| 变量 | 含义 |
| --- | --- |
| `R` | IMU 在世界坐标系中的旋转姿态 |
| `p` | IMU 在世界坐标系中的位置 |
| `v` | IMU 在世界坐标系中的速度 |
| `b_g` | 陀螺仪零偏 |
| `b_a` | 加速度计零偏 |
| `g` | 重力向量 |
| `R_LI` | LiDAR 到 IMU 的旋转外参 |
| `t_LI` | LiDAR 到 IMU 的平移外参 |

姿态 `R` 属于 SO(3) 流形，不能简单用三个欧拉角直接相加。实际实现通常用旋转矩阵、四元数或李代数 `Exp/Log` 处理姿态更新。

### 1.4 IMU 传播模型

去除偏置后的 IMU 测量为：

```text
omega = omega_m - b_g - n_g
a      = a_m - b_a - n_a
```

概念性的离散传播是：

```text
R(k+1) = R(k) Exp(omega * dt)
v(k+1) = v(k) + (R(k) a + g) dt
p(k+1) = p(k) + v(k) dt + 1/2 (R(k) a + g) dt²
```

与此同时还要传播误差协方差 `P`。协方差不是装饰字段，它决定滤波器认为“IMU 预测有多可信”。

### 1.5 点云坐标变换

设 LiDAR 点 `p_i^L` 在时间 `t_i` 采样，则它在世界系中的位置为：

```text
p_i^W = R(t_i) (R_LI p_i^L + t_LI) + p(t_i)
```

这里的 `t_i` 很关键。使用帧头或帧尾状态代替 `t_i`，会把运动畸变误差混入位姿估计。

### 1.6 几何观测残差

在局部地图中搜索当前点的邻域，并拟合平面 `(n, q)`。点到平面残差为：

```text
r_i = nᵀ (p_i^W - q)
```

多个点的残差组成观测向量 `r`，再通过观测雅可比 `H` 送入 ESKF、IEKF 或 IKFoM。

在以下场景中，`H` 的某些方向会接近不可观：

- 只有一面大平墙；
- 长直走廊；
- 视场被人员或机器人遮挡；
- 点数过少；
- 所有点集中在同一平面；
- 地图和当前场地不一致。

这称为几何退化。系统应该输出残差、邻点数量、协方差、匹配重叠率或 degeneracy 状态，而不是继续假装位姿可信。

## 2. FAST-LIO2 详解

### 2.1 算法背景

FAST-LIO2 延续 FAST-LIO 的紧耦合 LiDAR--IMU 结构，主要解决三个问题：

1. 传统特征提取会丢失大量原始点信息；
2. 每帧重建地图结构会浪费计算；
3. 仅依赖 LiDAR 的方法在激烈运动中容易匹配失败。

FAST-LIO2 的主要思想是：

```text
IMU 高频预测
    + 原始点/轻量降采样点直接配准
    + ikd-Tree 增量地图
    + 迭代误差状态卡尔曼滤波
```

### 2.2 FAST-LIO2 与 LOAM 的本质区别

传统 LOAM：

```text
原始点云
    -> 曲率计算
    -> 角点/面点提取
    -> 点到线/点到面匹配
```

FAST-LIO2：

```text
原始点云
    -> 无效点/盲区过滤
    -> 轻量抽样/降采样
    -> 直接点到局部平面匹配
```

FAST-LIO2 不是完全“不使用平面”，而是不要求先把点云分类成固定的角点和面点。它仍然需要从局部邻域拟合平面，用于构造残差。

### 2.3 FAST-LIO2 的完整数据流

#### 阶段 A：输入与时间检查

输入层需要完成：

1. 检查 ROS topic 类型和 QoS；
2. 解析 Livox `CustomMsg`；
3. 保留 `timebase` 和 `offset_time`；
4. 统一时间单位；
5. 检查点数和 NaN/Inf；
6. 检查 IMU 时间单调性；
7. 检查 LiDAR/IMU 队列是否覆盖同一时间段。

时间同步分为三种情况：

- 硬件同步已经可靠：直接使用同步时间；
- 已经离线标定时间偏移：把固定偏移写入配置；
- 没有可靠同步：才考虑在线时间偏移估计。

不能用一个未经标定的固定 sleep 代替时间同步。

#### 阶段 B：IMU 初始化

初始化阶段通常利用短暂静止数据估计：

- 重力方向；
- 初始姿态倾角；
- 陀螺仪平均偏置；
- 加速度计均值；
- IMU 协方差初值。

如果启动时机器人正在运动，重力和真实加速度会混在一起，导致初始状态错误。

#### 阶段 C：IMU 高频传播

假设 LiDAR 为 10 Hz，IMU 为 200 Hz，那么两帧 LiDAR 之间有约 20 次 IMU 更新。FAST-LIO2 使用 IMU 状态作为当前点云匹配的先验。

IMU 传播的好处是：

- 给 LiDAR 匹配提供较好的初值；
- 在短时 LiDAR 点数不足时仍然保持状态连续；
- 支持急转弯和高速底盘运动。

#### 阶段 D：点云去畸变

点云去畸变的目标是把同一帧中不同时刻采集的点变换到同一个参考时刻。

对于点 `p_i`：

```text
1. 读取点时间 t_i
2. 从 IMU 轨迹插值 R(t_i), p(t_i)
3. 应用 LiDAR--IMU 外参
4. 变换到扫描参考时刻
```

当机器人急加速时，去畸变误差会直接影响平面拟合和最终位姿。

#### 阶段 E：直接点云预处理

典型处理包括：

- 盲区剔除；
- 超量程点剔除；
- 重复点剔除；
- 点云抽样；
- VoxelGrid 降采样；
- 可选的动态点过滤。

当前 MID-360 profile 中，`feature_extract_enable` 为关闭状态，体现的是 direct registration 路线。

#### 阶段 F：ikd-Tree 近邻搜索

对于每个预测世界坐标点：

1. 在局部地图中寻找 `k` 个最近邻；
2. 检查最远邻点距离；
3. 对邻点做平面拟合；
4. 检查平面拟合误差；
5. 合格后构造点到平面残差。

ikd-Tree 相比普通静态 KD-Tree 的优势在于：

- 支持实时增量插入；
- 支持局部删除；
- 不需要每帧完整重建；
- 适合滑动局部地图；
- 可将查询量控制在有限范围内。

#### 阶段 G：迭代误差状态卡尔曼更新

将观测线性化：

```text
r(x + delta_x) ≈ r(x) + H delta_x
```

然后进行卡尔曼更新：

```text
K = P Hᵀ (H P Hᵀ + R)⁻¹
delta_x = K innovation
```

FAST-LIO2 会在当前估计附近进行多次重新线性化，直到状态增量足够小或达到最大迭代次数。

这比一次普通 EKF 线性化更适合处理：

- 初始姿态误差较大；
- 高速转弯；
- 点云几何约束非线性较强；
- LiDAR 与 IMU 外参存在小误差。

#### 阶段 H：增量地图更新

更新后的点会被筛选并加入局部地图。地图维护通常包含：

- 体素下采样；
- 视场范围裁剪；
- 地图边界移动；
- 局部点删除；
- 地图点数量监控。

地图过大时，近邻查询变慢，内存和 CPU 占用增加；地图过小时，匹配约束不足。

### 2.4 FAST-LIO2 的代码对应关系

在当前组合仓库中，可以按以下路径阅读：

| 模块 | 作用 |
| --- | --- |
| `src/vendor_fast_lio/src/preprocess.cpp` | Livox 点解析、时间字段转换、盲区过滤、抽样 |
| `src/vendor_fast_lio/src/IMU_Processing.hpp` | IMU 初始化、传播、点云去畸变 |
| `src/vendor_fast_lio/src/laserMapping.cpp` | 主循环、近邻搜索、观测构造、滤波更新、地图发布 |
| `src/vendor_fast_lio/include/ikd-Tree/` | 增量 KD-Tree |
| `src/vendor_fast_lio/include/IKFoM_toolkit/` | 流形状态与迭代滤波工具 |
| `src/vendor_fast_lio/config/mid360.yaml` | MID-360 输入、噪声、外参、降采样和发布配置 |

### 2.5 FAST-LIO2 关键参数

| 参数 | 作用 | 风险 |
| --- | --- | --- |
| `point_filter_num` | 点云按序抽样 | 太大导致几何稀疏，太小造成 CPU 压力 |
| `filter_size_surf` | 当前扫描降采样 | 太大丢细节，太小匹配量过多 |
| `filter_size_map` | 地图插入降采样 | 太大地图粗糙，太小地图膨胀 |
| `max_iteration` | IEKF 最大迭代次数 | 太大增加延迟，太小可能不收敛 |
| `det_range` | 有效距离范围 | 过小丢约束，过大引入远距离噪声 |
| `fov_degree` | 地图视场裁剪 | 错误视场会导致地图维护异常 |
| `acc_cov` | 加速度噪声模型 | 过小会过度信任 IMU |
| `gyr_cov` | 陀螺仪噪声模型 | 过小会造成姿态预测偏置 |
| `extrinsic_est_en` | 在线外参估计 | 激励不足时可能吸收其他误差 |
| `time_sync_en` | 在线时间偏移估计 | 输入同步差时可能不稳定 |

### 2.6 FAST-LIO2 的典型失效模式

| 现象 | 可能原因 |
| --- | --- |
| 点云重影 | 点时间错误、LiDAR/IMU 时间偏移、外参错误 |
| 急转弯时姿态跳变 | IMU 饱和、噪声参数错误、初值差、点数不足 |
| 直线走廊中漂移 | 几何退化，横向约束不足 |
| 地图逐渐变厚 | 去畸变错误、外参错误、时间不同步 |
| CPU 占用越来越高 | 地图未裁剪、降采样过小、点数持续增长 |
| 运动物体被写入地图 | 缺少动态点剔除和时间一致性判断 |
| 输出正常但控制不安全 | pose age、协方差、地图锁定状态未传递到控制层 |

## 3. Point-LIO 详解

### 3.1 核心思想

Point-LIO 可以看作对高带宽 LiDAR--IMU 估计的进一步探索。

FAST-LIO2 常见的组织形式是：

```text
IMU 传播到当前扫描
    -> 当前扫描去畸变
    -> 当前扫描匹配
    -> 迭代更新
```

Point-LIO 更强调：

```text
IMU 传播到当前点时刻
    -> 当前点匹配
    -> 当前点更新
    -> 继续处理下一个点
```

这样做的目标是减少等待完整扫描带来的延迟，提高状态输出带宽，尤其适合：

- 高角速度运动；
- 急加速底盘；
- 扫描周期较长的雷达；
- 非重复扫描或固态雷达。

### 3.2 Point-LIO 的逐点流程

#### 阶段 A：点级时间解析

每个点需要携带自己的时间信息。算法按照点时间排序，并确保时间与 IMU 队列对应。

#### 阶段 B：传播到点时刻

对于点 `p_i`，从当前滤波状态传播到 `t_i`：

```text
x(t_i) = Propagate(x(t_prev), imu[t_prev:t_i])
```

这让点的坐标变换使用更接近真实采样时刻的姿态。

#### 阶段 C：点级地图查询

在 ikd-Tree 中查找邻域，并拟合局部平面。邻域不满足条件时跳过当前点，避免错误几何观测污染滤波器。

#### 阶段 D：点级滤波更新

使用当前点的点到平面残差更新状态：

```text
r_i = n_iᵀ (p_i_world - q_i)
```

更新后继续处理下一个点，而不是等待整帧结束。

#### 阶段 E：地图增量更新

通过体素、距离和视场规则，将有效点加入局部地图。

### 3.3 Point-LIO 的工程特点

Point-LIO 需要处理更多调度问题：

- IMU 和点云队列的同步；
- 点级状态读写；
- 多线程预处理；
- 地图查询与地图更新的竞争；
- 输出频率与控制缓存；
- 点级错误观测的鲁棒权重。

因此，Point-LIO 的优势不只是“更新更快”，它同时要求更严格的输入守门和线程设计。

### 3.4 历史 Point-LIO 工程中的代码模块

历史实现 `Desktop/作品集/ROBOCON2025/Lidar_Pointlio/` 中的模块大致对应：

| 文件 | 作用 |
| --- | --- |
| `src/preprocess.cpp` | 多种 LiDAR 格式、点时间、过滤、抽样和特征处理 |
| `src/IMU_Processing.hpp` | IMU 初始化、传播、去畸变 |
| `src/Estimator.cpp` | 近邻搜索、平面拟合、残差和滤波更新 |
| `src/laserMapping.cpp` | 主循环、同步、地图更新和发布 |
| `include/IKFoM/` | 迭代流形卡尔曼滤波工具 |
| `include/ikd-Tree/` | 增量 KD-Tree |
| `launch/mapping_*.launch.py` | 建图模式和定位模式 |

历史 launch 中还可以看到：

- `use_imu_as_input`；
- `prop_at_freq_of_imu`；
- `check_satu`；
- `space_down_sample`；
- `filter_size_surf`；
- `filter_size_map`。

这些开关会影响输入源、传播频率、IMU 饱和检查和计算负载，不能把不同配置的运行结果直接比较。

### 3.5 Point-LIO 的优势

- 扫描未完成时即可提供状态反馈；
- 对高动态运动的响应更及时；
- 点时间直接参与连续状态估计；
- 适合高带宽控制和快速运动机器人；
- 保留直接点云匹配和增量地图路线。

### 3.6 Point-LIO 的局限

- 点级更新更容易受到错误点时间影响；
- 动态点会更快进入观测链；
- 调度和线程同步更复杂；
- 点级更新可能产生更高 CPU 开销；
- 不同开源分支的参数和 topic 可能差异很大；
- 没有同一 bag 的实验结果时，不能声称它一定优于 FAST-LIO2。

## 4. FAST-LIO2 与 Point-LIO 对照

| 维度 | FAST-LIO2 | Point-LIO |
| --- | --- | --- |
| 主要目标 | 实时、稳定、直接 LiDAR--IMU 里程计 | 高带宽、点级、快速状态更新 |
| 更新组织 | 通常按扫描组织匹配和更新 | 强调点级或小批量点更新 |
| 点云模式 | 原始点直接配准，可轻量降采样 | 原始点直接配准，点时间连续参与 |
| IMU 作用 | 高频传播和去畸变 | 高频传播、点时刻预测和更新 |
| 地图结构 | ikd-Tree | ikd-Tree 或类似增量地图 |
| 滤波器 | IEKF/ESKF 迭代更新 | IKFoM/迭代滤波路线 |
| 反馈时延 | 低，常按扫描输出 | 理论上可进一步降低扫描等待 |
| CPU 风险 | 主要由点数、近邻和迭代次数决定 | 还受到点级调度和更新次数影响 |
| 适用场景 | 通用移动机器人、实时建图 | 激烈运动、高带宽和研究型对照 |
| 全局定位 | 不包含回环和全局锚定 | 不包含回环和全局锚定 |

公平对比需要固定：

- 同一 rosbag；
- 同一 MID-360 点字段；
- 同一时间基准；
- 同一外参初值；
- 同一地图策略；
- 同一 CPU 约束；
- 同一输出 topic 和停止条件；
- 同一 ground truth 和误差计算方法。

至少报告：

```text
输出频率、端到端延迟、CPU、内存、有效匹配点数、
平移误差、航向误差、失锁次数、输入告警、失败原因
```

## 5. 其他 LiDAR SLAM 算法

### 5.1 LOAM

LOAM（Lidar Odometry and Mapping）是经典特征驱动 LiDAR SLAM。

主要流程：

```text
点云曲率计算
    -> 提取边缘点和面点
    -> lidar odometry
    -> lidar mapping
```

优点：

- 理论直观；
- 点到线、点到面的几何残差清晰；
- 适合作为学习和基线算法。

局限：

- 依赖线束结构和扫描顺序；
- 特征阈值较多；
- 对 Livox 非重复扫描需要改造；
- 没有 IMU 时高速运动性能受限。

### 5.2 LeGO-LOAM

LeGO-LOAM 针对地面车辆，先做地面分割和聚类，再进行特征匹配。

适合：

- 平坦道路；
- 有明显地面的户外车辆；
- 算力有限的场景。

不适合直接照搬到：

- 台阶和坡面；
- 机器人机构遮挡；
- 篮球场动态人员；
- 需要完整 3D 几何的场景。

### 5.3 LIO-SAM

LIO-SAM 使用因子图把以下信息统一起来：

- IMU 预积分；
- LiDAR scan matching；
- GPS；
- 回环约束；
- 关键帧位姿。

优点：

- 能抑制长期漂移；
- 支持回环闭合；
- 适合长时间建图。

代价：

- GTSAM 等依赖；
- 关键帧和回环管理复杂；
- 后端延迟和内存更高；
- 不一定适合只要求低延迟局部定位的比赛链路。

### 5.4 LVI-SAM、FAST-LIVO2

这些方法融合视觉、LiDAR 和 IMU：

```text
LiDAR：几何与尺度
相机：纹理与语义
IMU：高频运动预测
```

适合 LiDAR 几何退化但相机纹理丰富的环境。

工程难点包括：

- 相机内参；
- LiDAR-相机外参；
- 相机滚动快门；
- 图像和点云时间同步；
- 光照和曝光变化；
- 深度相机无效值。

### 5.5 KISS-ICP

KISS-ICP 是强调简单和参数少的 LiDAR odometry 基线，通常使用点云匹配、运动模型和鲁棒处理。它适合快速验证 LiDAR-only 的可行性，但在高速运动、点时间处理和 IMU 强约束方面不等同于 FAST-LIO2 或 Point-LIO。

## 6. 点云匹配与固定地图定位

LIO 提供连续的局部运动，固定地图模块负责把局部轨迹锚定到比赛场地地图：

```text
T_map_base = T_map_odom * T_odom_base
```

### 6.1 点到点 ICP

目标函数：

```text
min Σ ||R p_i + t - q_i||²
```

优点是实现简单，缺点是：

- 对初始位姿敏感；
- 平面场景约束不足；
- 容易受到动态点影响；
- 易陷入局部最优。

### 6.2 点到面 ICP

目标函数：

```text
min Σ (n_iᵀ(R p_i + t - q_i))²
```

通常比点到点 ICP 收敛更快，适合墙面、地面和规则结构较多的场地。

### 6.3 GICP

GICP 为点邻域建立协方差，把局部几何不确定性加入匹配目标。

优点：

- 几何表达更完整；
- 对不同点密度更鲁棒；
- 通常比普通点到点 ICP 更稳定。

缺点：

- 计算量较高；
- 邻域协方差质量影响结果；
- 仍然需要合理初值。

### 6.4 NDT

NDT 将地图划分成体素，并在每个体素中建立高斯分布，通过最大化点落入体素分布的概率进行匹配。

优点：

- 不需要显式点对应；
- 对初始匹配关系要求相对低；
- 适合粗粒度大范围匹配。

缺点：

- 体素分辨率敏感；
- 存在局部极值；
- 精确定位时往往需要其他方法补充。

### 6.5 scan-to-map 的状态机

固定地图定位不能只看一次 ICP fitness。建议使用：

```text
UNINITIALIZED
    -> INITIALIZING
    -> TRACKING
    -> RELOCALIZING
    -> LOST
```

进入 `LOST` 的条件可以包括：

- 匹配残差连续升高；
- scan-map overlap 下降；
- pose age 超时；
- 协方差超过阈值；
- 地图版本不匹配；
- 当前场地与地图不一致。

人工 `/initialpose` 只能提供初始锚点，不能直接宣布地图已经锁定。

## 7. 状态估计后端

### 7.1 ESKF

ESKF 使用名义状态和小误差状态：

```text
名义状态：R, p, v, bg, ba
误差状态：delta_theta, delta_p, delta_v, delta_bg, delta_ba
```

优点：计算量低、适合在线机器人。

### 7.2 IEKF

IEKF 在同一观测内反复线性化：

```text
预测 -> 匹配 -> 更新 -> 重新线性化 -> 再更新
```

FAST-LIO2 的关键更新机制属于这类思路。

### 7.3 IKFoM

IKFoM 是面向流形状态的迭代卡尔曼滤波工具箱。Point-LIO 历史实现中可以看到这种组织方式。

### 7.4 因子图和位姿图

因子图将多个时刻状态和约束共同优化：

```text
x0 -- IMU -- x1 -- IMU -- x2
 |                         |
 +-------- loop -----------+
```

适合：

- 回环；
- GPS；
- 多传感器全局融合；
- 长时间地图一致性。

代价是后端复杂度、延迟、内存和调试成本更高。

## 8. 地图表示与数据结构

### 8.1 VoxelGrid

把空间划分为固定大小体素，每个体素保留一个或多个代表点。

作用：

- 降低点数；
- 控制地图内存；
- 使点密度更均匀。

### 8.2 ikd-Tree

适合 LIO 的增量 KD-Tree，主要操作包括：

- `Nearest_Search`；
- `Add_Points`；
- 局部删除；
- 初始地图构建；
- 树规模管理。

### 8.3 Occupancy Grid / OctoMap

表示空间是否被占据，适合：

- 碰撞检测；
- Nav2 costmap；
- 2D/3D 路径规划。

但占据地图不一定适合高精度连续位姿估计。

### 8.4 Surfel / 局部平面地图

每个地图元素不仅保存位置，还保存法向、半径和协方差，适合点到面匹配和表面重建。

## 9. 导航规划算法

### 9.1 全局规划

#### A*

使用：

```text
f(n) = g(n) + h(n)
```

其中 `g` 是已消耗代价，`h` 是启发式估计。

适合栅格地图上的静态全局路径规划。

#### Dijkstra

不使用启发式，能够求出最短路径，但搜索范围通常更大。

#### D* Lite

地图发生变化后进行增量重规划，适合未知或动态环境。

#### Hybrid A*

同时考虑：

- `x`；
- `y`；
- `yaw`；
- 最小转弯半径；
- 底盘运动学约束。

适合非完整约束底盘。

### 9.2 局部控制

- DWB：速度采样和轨迹评分；
- TEB：时间弹性带优化；
- MPC：显式考虑动力学和约束；
- MPPI：基于采样的模型预测控制。

导航控制器不能只订阅一个位姿数字，还应该检查：

- `pose_valid`；
- `pose_age`；
- `map_locked`；
- TF 是否连续；
- costmap 时间戳；
- 急停和底盘状态。

## 10. 感知、目标定位与投篮算法

### 10.1 YOLOv5 / YOLO 系列

YOLO 输出：

```text
class_id, confidence, bounding_box
```

它解决的是目标检测，不直接解决：

- 精确三维位置；
- 机器人相对目标航向；
- 地图坐标中的目标位置；
- 目标是否稳定可用。

### 10.2 RGB-D 反投影

对于像素 `(u, v)` 和深度 `Z`：

```text
X = (u - cx) Z / fx
Y = (v - cy) Z / fy
Z = depth(u, v)
```

再通过相机外参和 TF 转换到机器人或地图坐标系。

必须处理：

- 深度为零；
- 深度超范围；
- 目标边缘混合深度；
- 遮挡；
- 相机时间戳过期；
- 相机与 LiDAR 外参误差。

### 10.3 时序门控

目标只有满足以下条件才进入动作层：

```text
confidence 合格
depth 有效
连续多帧稳定
观测 age 未超时
机器人 pose 有效
地图已锁定
机构状态正常
队友状态安全
```

### 10.4 弹道模型

投篮的物理模型可以包含：

- 重力；
- 空气阻力；
- 马格努斯力；
- 初始速度；
- 发射角度；
- 球体旋转；
- 篮筐相对位置。

离线阶段可以使用：

- 网格搜索；
- 模拟退火；
- 数值积分；
- 曲线拟合；
- 距离到发射速度回归。

在线阶段更适合使用已经验证的查表或映射：

```text
机器人与篮筐距离 -> 发射速度、角度和旋转参数
```

## 11. 项目中的系统级安全设计

一个可靠的比赛动作不应等价于“调用了 FireShot”。它应当是多个条件的逻辑合取：

```text
enabled = stage
       && pose_valid
       && pose_fresh
       && map_locked
       && target_valid
       && ball_present
       && mechanism_ok
       && teammate_safe
       && communication_alive
       && can_alive
```

任意条件失败，都应进入：

- WAIT；
- PAUSED；
- RECOVERY；
- FAULT；
- ESTOP。

固定 `sleep(2)` 不能替代：

- 球存在反馈；
- 机构到位反馈；
- 目标观测确认；
- 队友 ACK；
- 定位新鲜度检查。

## 14. 面试表达模板

### 30 秒版本

“FAST-LIO2 和 Point-LIO 都是紧耦合 LiDAR--IMU 里程计。IMU 负责高频传播，LiDAR 点通过逐点时间去畸变后，与 ikd-Tree 局部地图做点到平面匹配，再用 IEKF 或 IKFoM 迭代更新姿态、位置和偏置。FAST-LIO2 更偏向扫描级的直接点配准，Point-LIO 强调点级连续更新和高带宽。项目中再用固定地图 ICP 估计 `map -> odom`，最后通过 pose age、地图锁定、视觉有效性和 STM32 反馈决定是否允许投篮。”

### 深挖时的关键点

1. **时间**：MID-360 必须保留 `timebase` 和 `offset_time`，否则运动去畸变没有依据。
2. **几何**：点到平面残差依赖邻域平面质量，走廊和大平面会出现退化。
3. **滤波**：IEKF/IKFoM 不是简单平均位姿，而是结合协方差和观测雅可比进行状态更新。
4. **地图**：ikd-Tree 负责高效增量近邻查询，但不能自动消除长期漂移。
5. **系统**：局部 LIO、固定地图、TF、导航和控制必须分层，不能让多个节点同时发布同一条 TF。
6. **证据**：同一 bag、同一参数和同一硬件预算下的 A/B 结果，才足以支撑算法比较。
