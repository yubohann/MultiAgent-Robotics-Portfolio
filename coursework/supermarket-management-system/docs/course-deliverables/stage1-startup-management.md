## 团队 SWOT

| 维度 | 内容 |
| --- | --- |
| 优势 | 小组角色分工明确，核心功能采用 Flask 分层结构，报告图表和代码可以互相映射。 |
| 劣势 | 课程时间有限，成员对自动化测试和覆盖率工具熟练度不一致。 |
| 机会 | 可通过 Gitee、pytest、coverage 和统一文档目录提高可交付性。 |
| 威胁 | 若后期只补报告不补代码，文档与系统实现会不一致；若不做截图留存，系统实施阶段证据不足。 |

## 项目 SWOT

| 维度 | 内容 |
| --- | --- |
| 优势 | 超市管理业务边界清晰，商品、库存、销售、财务之间有天然数据闭环。 |
| 劣势 | 单机 SQLite 更适合课程演示，不适合多门店并发生产环境。 |
| 机会 | 二期可扩展会员、员工、供应商、系统管理，满足课程设计范围。 |
| 威胁 | 库存、收银、财务若缺测试，容易出现数量和金额不一致。 |

## 可行性评估

| 评估项 | 结论 |
| --- | --- |
| 技术可行性 | Flask 与 SQLite 可以快速完成课程演示；SQLAlchemy 能满足 ORM 建模要求。 |
| 经济可行性 | 使用开源技术和本地运行环境，无额外采购成本。 |
| 操作可行性 | 浏览器访问，管理员和收银员账号区分清晰，页面交互符合门店业务习惯。 |
| 进度可行性 | 按 7 个阶段拆分任务，可先交付一期核心，再补二期模块。 |
| 风险控制 | 通过测试用例、自动化测试、截图和代码审查记录降低交付风险。 |
