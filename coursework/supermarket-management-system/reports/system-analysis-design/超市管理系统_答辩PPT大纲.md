# 超市管理系统答辩 PPT 大纲

依据：`~\Downloads\软件开发与管理课程设计 推荐答辩流程.xlsx`

答辩总时长按 15 分钟设计，其中 12 分钟汇报与系统演示，3 分钟老师提问验收。PPT 建议控制在 10 页以内，不堆截图，每页只保留能支撑答辩判断的核心证据。

## 整体汇报策略

答辩主线：从“需求为什么这样设计”讲到“系统如何实现”，再用“测试和仓库证据”证明项目真实完成。

重点突出四个一致性：

| 验收重点 | PPT 中的体现 |
| --- | --- |
| 需求与设计一致 | 用泳道图、用例图、代表业务流程说明系统要做什么。 |
| 设计与实现一致 | 用 ER/ORM、页面设计、路由/服务/模型结构说明设计已经落到代码。 |
| 实现与测试一致 | 用测试用例、pytest、coverage 和功能测试证据说明功能可验证。 |
| 个人贡献与仓库记录一致 | 用分工、Gitee 提交、代码审查记录说明协作可信。 |

| 页码 | 标题 | 对应答辩环节 | 建议时间 | 汇报人 |

| 1 | 项目概况与答辩路线 | 项目概况与分工 | 1 分钟 | 组长 |

## 第 4 页：代表性业务闭环

页面目标：用一个业务闭环把需求、设计、实现串起来。

推荐闭环：供应商维护 → 商品/库存维护 → 会员信息维护 → 收银结算 → 销售订单 → 库存流水 → 财务流水 → 经营分析。

页面内容：

| 步骤 | 业务动作 | 系统实现 |
| --- | --- | --- |
| 1 | 维护供应商 | 供应商档案、联系人、结算周期、启停 |
| 2 | 维护商品与库存 | 商品资料、库存数量、低库存预警、库存流水 |
| 3 | 维护会员 | 会员等级、积分、状态 |
| 4 | 收银销售 | 商品检索、购物车、库存校验、订单生成 |
| 5 | 查询统计 | 销售订单、财务流水、经营分析图表 |

## 答辩时容易被问的问题

| 问题 | 建议回答方向 |
| --- | --- |
| 为什么选择 Flask + SQLite？ | 课程演示重点是流程、模型、实现和测试闭环；Flask 适合快速构建，SQLite 便于本地运行和提交演示数据。 |
| 数据模型如何支撑销售闭环？ | 商品和库存支撑收银校验，销售单和销售明细记录交易，库存流水记录扣减，财务流水记录收入。 |
| 会员/员工/供应商是不是只写了文档？ | 不是，模型、服务、路由、页面和测试都已补齐。 |
| coverage 100% 是否真实？ | 使用 `uv run coverage run -m pytest` 和 `uv run coverage report` 得到，证据保存在截图目录。 |
| 如果继续做，优先改什么？ | 优先增强操作日志、采购订单流转、权限细粒度、UI 自动化测试和生产部署能力。 |
